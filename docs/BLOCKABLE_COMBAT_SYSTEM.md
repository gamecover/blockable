# Blockable 전투 시스템 명세 V0.5.3

> 파일명: `BLOCKABLE_COMBAT_SYSTEM.md`
> 문서 버전: `V0.5.3`
> 문서 상태: 현재 확정된 전투 규칙 및 구현 기준
> 상위 기획: `BLOCKABLE_GAME_DESIGN.md`
> 대상 프로젝트: Blockable
> 관련 데이터: Blockable Block Designer JSON, Blockable Monster Designer JSON

---

## 1. 문서 목적과 범위

이 문서는 Blockable의 실제 전투 판정에 필요한 공통 규칙을 정의한다.

이 문서에서 관리하는 내용은 다음과 같다.

- 전투 진행 순서와 승리·패배 판정
- 블록 배치와 조합식 판정
- 조합 참여 블록과 미참여 블록의 처리
- 기본 피해, 독립 피해, 타격 횟수와 피해 반올림
- 색상 시너지
- 방어도, 회복, 버프, 디버프, 상태 피해와 군중 제어
- 다수 몬스터 슬롯과 공격 범위
- Block Designer 및 Monster Designer 효과 데이터의 런타임 해석

다음 내용은 이 문서의 범위가 아니며 `BLOCKABLE_GAME_DESIGN.md`에서 관리한다.

- 튜토리얼
- 청사진과 퀵 조합 UI
- 개발자 모드와 개발자 전투 공식 표시
- 화면 배치, 말풍선, 팝업 등 전투 규칙이 아닌 UX
- 게임 전체 진행, 지도, 이벤트, 경제 및 콘텐츠 해금

개별 블록, 조합식, 몬스터, 능력과 행동 패턴의 실제 값은 각 Designer가 생성한
JSON을 단일 데이터 기준으로 사용한다. 메인 프로그램은 JSON에 없는 개별 수치를
임의로 만들거나 서로 다른 효과 ID를 추론하여 연결하지 않는다.

## 2. 규칙 우선순위와 데이터 책임

규칙이 충돌할 경우 다음 순서를 적용한다.

1. 사용자가 가장 최근에 확정한 명시적 규칙
2. 이 문서 `BLOCKABLE_COMBAT_SYSTEM.md`
3. `BLOCKABLE_GAME_DESIGN.md`
4. Designer JSON의 개별 데이터
5. 기존 구현 코드

Designer JSON은 개별 콘텐츠의 값을 제공하지만 공통 전투 공식을 변경하지 않는다.
JSON에서 새로운 Type 또는 `parameters.id`가 발견되면 임의로 기존 변수에 연결하지
않고 먼저 별도의 런타임 지원 여부를 확정한다.

현재 고정 데이터 경로는 다음과 같다.

```text
docs/references/designs/blockable_block_design.json
docs/references/designs/blockable_monster_design.json
```

파싱 또는 검증에 실패하면 런타임 오류에 파일 경로, 처리 단계와 원인을 표시한다.
몬스터 이미지가 없는 것은 JSON 거부 사유가 아니며 대체 표시를 사용한다.

## 3. 블록 분류

### 3.1 색상과 등급 분류

현재 별도의 독립된 등급 필드는 사용하지 않는다. 블록의 색상 값이 분류와 등급의
역할을 함께 담당한다.

| 분류 | 색상 ID | 등급 해석 |
|---|---|---|
| 일반 블록 | `steel`, `fire`, `water`, `nature` | 모두 같은 일반 등급 |
| 고유 블록 | `special` | special 등급 |
| 전설 블록 | `legendary` | legendary 등급 |
| 저주 블록 | `curse` | curse 등급 |

`special`, `legendary`, `curse`는 일반 속성 시너지의 속성 개수에 포함하지 않는다.
`steel`은 일반 등급이지만 현재 화염·물·자연 속성 시너지 단계에는 포함하지 않는다.

### 3.2 블록 효과의 출처

블록 자체의 피해, 방어, 회복과 기타 효과는 Block Designer JSON의 해당 블록
`effects[]`에서 가져온다. 조합식 효과는 조합 데이터의 `effects[]`에서 가져온다.

메인 프로그램이 별도로 계산하는 것은 다음 공통 규칙뿐이다.

- 조합식 기하 판정
- 조합 참여·미참여 블록 분리
- B, A, H 피해 패킷 구성
- 일반 속성 시너지
- 범위와 대상 슬롯 판정
- 상태와 자원 효과의 공통 실행

## 4. 전투 진행 순서

한 전투 턴은 다음 순서로 처리한다.

```text
1. 플레이어 입력과 블록 배치
2. 조합식, 참여 블록, 미참여 블록 판정
3. 블록 자체 효과, 조합 효과, 색상 시너지 계산
4. 대상과 범위 확정
5. 플레이어 행동 실행
   5.1 기본 공격 B를 H회 실행
   5.2 독립 공격 A 패킷을 순서대로 실행
   5.3 버프·디버프·상태·군중 제어 갱신
   5.4 방어·회복·자원 효과 적용
6. 일반전 승리 또는 보스전 즉시 승리 판정
7. 살아 있고 행동 가능한 몬스터가 슬롯 순서대로 행동
8. 승리·패배 판정
9. 턴 종료 상태 피해 처리
10. 턴 종료 스택과 지속 시간 갱신
11. 최종 승리·패배 판정
```

플레이어가 먼저 적을 처치하면 해당 적은 행동하지 않는다. 보스전에서는 5번 보스가
사망하는 순간 승리하며 남은 행동과 미실행 효과를 취소한다.

## 5. 조합식 판정

### 5.1 판정 기준

조합식은 블록 이름이나 색상이 아니라 다음 정보를 기준으로 판정한다.

- 조합식에 정의된 블록 인스턴스
- 각 블록의 한 칸 단위 셀 형태
- 셀의 상대 위치
- 허용된 회전
- 허용된 반사
- 블록 타입, 형태 또는 조합 슬롯의 매칭 조건

일반 블록은 색상이 달라도 형태와 조합 조건이 같으면 같은 조합식을 완성할 수 있다.
색상이 다르다는 이유만으로 조합식 판정을 실패시키지 않는다.

### 5.2 참여 블록

조합식의 기하와 슬롯 조건을 실제로 만족시킨 블록을 조합 참여 블록으로 본다.

- 참여 블록의 `BASE_DAMAGE.value`는 조합 기본 피해 B에 합산한다.
- 참여 블록의 `BASE_HIT_COUNT.value`도 조합 1타 B에 합산한다.
- 참여 블록의 `INDEPENDENT_DAMAGE`는 별도 A 패킷으로 유지한다.
- 참여 블록의 방어, 회복 및 상태 효과는 원래 Type대로 처리한다.
- 조합식 자체의 효과를 참여 블록 효과 뒤에 적용한다.

### 5.3 조합식에 사용되지 않는 블록

거푸집에 배치되었지만 어떤 발동 조합식에도 참여하지 않은 블록은 미참여 블록이다.

미참여 블록 하나마다 다음 규칙을 적용한다.

```text
미참여 블록의 변환 A
= Σ(BASE_DAMAGE.value + BASE_HIT_COUNT.value)
```

- 미참여 블록의 B 계열 피해를 해당 블록 전용 A 패킷 하나로 변환한다.
- 변환된 A는 조합의 H를 상속하지 않고 1회 실행한다.
- 미참여 블록의 `BASE_HIT_COUNT.intensify`는 무시한다.
- 미참여 블록의 기존 `INDEPENDENT_DAMAGE`는 효과마다 별도 A 패킷으로 유지한다.
- 같은 종류의 미참여 블록이 여러 개여도 각 블록의 패킷을 독립적으로 유지한다.
- 방어, 회복, 버프, 디버프와 상태 효과는 변환하지 않고 원래 Type대로 적용한다.

모든 피해 패킷은 실제 적용 직전에 0 미만을 0으로 보정한다.

### 5.4 피해 패킷 실행 순서

```text
1. 조합 기본 공격 B 패킷을 H회
2. 조합 및 참여 블록의 기존 A 패킷
3. 미참여 블록에서 변환된 A 패킷
4. 미참여 블록의 기존 A 패킷
```

동일한 범위와 수치를 가진 A라도 출처가 다른 독립 패킷을 임의로 하나로 합치지 않는다.

## 6. 피해 공식

### 6.1 변수

| 기호 | 의미 | 기본값 |
|---|---|---:|
| `B` | 기본 공격 1타의 피해 기준값 | 0 |
| `P` | 기본 공격에 직접 더하는 피해 보너스 | 0 |
| `M` | 공격력 증가 배율 | 1 |
| `D` | 약화 등 공격력 감소 배율 | 1 |
| `W` | 상처 등 받는 피해 증가 배율 | 1 |
| `H` | 기본 공격의 총 타격 횟수 | 1 |
| `A` | 기본 공격 뒤 별도로 실행하는 독립 피해 | 0 |

현재 `M`을 변경하는 확정 효과는 없지만 공식과 기본값은 보존한다. 효과가 종료되면
`M`과 `D`는 1, `P`는 0으로 돌아간다.

### 6.2 기본 공격 B

```text
기본 공격 1타 피해량
= floor(max(0, (B + P) × M × D × W))

기본 공격 총 피해량
= 1타 피해량 × H
```

각 타격은 별도 피해 패킷이다. 방어도 소모와 대상 생존 여부도 타격마다 갱신한다.

### 6.3 독립 공격 A

```text
독립 공격 피해량
= floor(max(0, A × M × D × W))
```

- A는 기본 공격의 모든 처리가 끝난 뒤 실행한다.
- A는 별도 명시가 없는 한 H를 상속하지 않는다.
- A 효과가 여러 개면 각 효과 또는 변환 블록별 독립 패킷으로 실행한다.

### 6.4 `BASE_HIT_COUNT`

`BASE_HIT_COUNT`의 해석은 다음으로 고정한다.

| 필드 | 의미 |
|---|---|
| `value` | 1타당 기본 피해 B에 더할 값 |
| `parameters.intensify` | 이번 기본 공격의 총 타격 횟수 H |
| `parameters.duration` | 0 |
| `parameters.id` | `CURRENT_ACTION` |

예시는 다음과 같다.

```text
value = 2
parameters.intensify = 3

결과: B에 2를 더하고 총 H=3회 공격
개념적 피해: 2 × 3
```

구현 내부에서는 기본 1회에 더할 추가 횟수를 `intensify - 1`로 보관할 수 있다.
그러나 외부 규칙과 최종 표시에서 H는 언제나 `intensify` 그 자체다.

한 행동에 `BASE_HIT_COUNT`가 여러 개 있으면 가장 큰 `intensify`를 기본 H로 사용한다.
색상 시너지 등 명시적으로 H를 증가시키는 효과는 그 이후 H에 더한다.

### 6.5 반올림과 하한

- 일반 피해는 각 개별 패킷 적용 직전에 내림한다.
- 음수 피해는 0으로 보정한다.
- 여러 패킷을 먼저 합친 뒤 한 번만 반올림하지 않는다.
- 체력은 0 미만으로 내려가지 않는다.
- 회복은 최대 체력을 넘지 않는다.

## 7. 색상 시너지

### 7.1 판정 대상

색상 시너지는 거푸집에 배치된 모든 블록 중 `fire`, `water`, `nature` 블록의
개수를 기준으로 메인 프로그램이 계산한다. 조합식 하나별로 따로 계산하지 않는다.

`steel`, `special`, `legendary`, `curse`는 속성 개수와 단계에서 제외한다.

### 7.2 속성 개수별 상태

| 활성 속성 종류 수 | 판정 | 효과 |
|---:|---|---|
| 1 | 단일 속성 | 해당 속성의 단색 단계 시너지 적용 |
| 2 | 뒤섞인 | 단색 단계 효과를 모두 끄고 정의된 두 속성 혼합 효과만 적용 |
| 3 | 미구현 | 모든 단색·뒤섞인 시너지와 시너지 표기를 적용하지 않음 |

“두 속성 이상이면 뒤섞인”이라는 규칙은 사용하지 않는다. 뒤섞인은 정확히 두 속성일
때만 성립한다.

### 7.3 단계 계산

단일 속성 상태의 단계는 거푸집 위 해당 색상 블록의 개수다. 현재 단계까지의 모든
하위 단계 효과를 누적 적용한다.

예를 들어 화염 블록이 3개라면 화염 1·2·3단계 효과를 모두 적용한다.

### 7.4 화염 단색 시너지

| 단계 | 누적되는 효과 |
|---:|---|
| 1 | 독립 피해 A +10 |
| 2 | 기본 공격 B와 독립 공격 A의 범위를 전체로 변경 |
| 3 | 독립 피해 A +20 |
| 4 | H +1 |
| 5 | H +1 |

시너지로 발생한 공격 피해는 모두 A다. B에 합산하지 않으며 조합 H를 상속하지 않는다.

### 7.5 물 단색 시너지

| 단계 | 누적되는 효과 |
|---:|---|
| 1 | 방어도 +10 |
| 2 | 방어도 +20 |
| 3 | 적 전체 빙결, 이번 턴 방어도를 다음 턴에 유지 |
| 4 | 이번 행동에서 획득하는 방어도 2배 |
| 5 | 이번 턴 방어도를 독립 피해 A에 합산 |

빙결은 아직 구현하지 않는다. 방어도 유지와 배율은 현재 전투 시스템의 정식 확장
요소이며 이후 다른 효과에서도 사용할 수 있다.

### 7.6 자연 단색 시너지

| 단계 | 누적되는 효과 |
|---:|---|
| 1 | 회복 +2 |
| 2 | 회복 +3, 적 전체 중독 +20 |
| 3 | 회복 +5, 적 전체 중독 +100% |
| 4 | 회복 +8, 적 전체 중독 +20 |
| 5 | 회복 +12, 적 전체 중독 +100%, 즉시 중독 1스택 추가 |

중독은 아직 구현하지 않으며 현재는 회복 효과만 적용한다.

### 7.7 두 속성 뒤섞인 시너지

| 속성 조합 | 효과 |
|---|---|
| 화염 + 물 | 독립 피해 A +5, 방어도 +5 |
| 화염 + 자연 | 독립 피해 A +5, 회복 +1 |
| 물 + 자연 | 현재 정의된 효과 없음 |

순서는 결과에 영향을 주지 않는다. 화염+물과 물+화염은 같은 조합이다.

세 속성이 동시에 존재하면 위 두 속성 조합을 부분적으로 찾아 적용하지 않는다.
화염+물+자연은 모든 속성 시너지 미적용 상태다.

## 8. 방어도와 회복

### 8.1 방어도

방어도는 일반 피해를 고정 수치만큼 대신 받는 소모형 수치다.

```text
흡수 피해 = min(현재 방어도, 계산된 피해)
남은 방어도 = 현재 방어도 - 흡수 피해
체력 피해 = 계산된 피해 - 흡수 피해
```

- 기본 공격과 독립 공격은 모두 방어도를 소모한다.
- 다단 공격은 각 타격마다 현재 남은 방어도를 다시 사용한다.
- 기본적으로 턴 종료 시 방어도는 사라진다.
- 방어도 유지 효과가 있으면 지정된 다음 턴까지 보존한다.
- 방어도 증가량과 방어도 배율은 서로 다른 계산 요소로 존재할 수 있다.
- 출혈은 방어도를 무시한다.
- 화상은 일반 피해처럼 방어도로 막을 수 있다.

### 8.2 회복

```text
회복 후 체력 = min(최대 체력, 현재 체력 + 회복량)
```

0 이하의 회복량은 적용하지 않는다.

## 9. 공통 효과 Type

| Type | `value` | `parameters.id` | `duration` | `intensify` |
|---|---|---|---|---|
| `BASE_DAMAGE` | 기본 피해 B | 사용 안 함 | 0 | 0 |
| `BASE_HIT_COUNT` | 1타 B | `CURRENT_ACTION` | 0 | 총 H |
| `INDEPENDENT_DAMAGE` | 독립 피해 A | 사용 안 함 | 0 | 0 |
| `BLOCK` | 획득 방어도 | 사용 안 함 | 0 | 0 |
| `RECOVERY` | 회복량 | 사용 안 함 | 0 | 0 |
| `STATUS_DAMAGE` | 발동당 피해 기준값 | 상태 피해 ID | 상태별 규칙 | 상태 강도·스택 |
| `DEBUFF` | 능력치 감소값 | 디버프 ID | 지속 턴 | 강도·스택 |
| `CROWD_CONTROL` | 현재 별도 계산값 없음 | 제어 ID | 제어별 규칙 | 제어 강도 |
| `BUFF` | 능력치 증가값 | 버프 ID | 지속 턴 | 강도·스택 |
| `EXTRA_TURN` | 추가 턴 수 | 턴 대상 ID | 무시 | 1 |
| `DECK_CAPACITY` | 덱 용량 증감 | 대상 덱 | 무시 | 1 |
| `DRAW` | 드로우 개수 | 대상 덱 | 무시 | 1 |
| `PLACEMENT_COUNT` | 배치 횟수 증감 | `BLOCK_PLACEMENT` | 무시 | 1 |

`BUFF / DAMAGE_BONUS`는 현재 무효 처리한다. JSON에 존재하더라도 임의로 P, 분노 또는
다른 기존 변수에 연결하지 않으며 실행에서 제외하고 진단 경고를 남긴다.

몬스터는 `EXTRA_TURN`을 사용할 수 있다. 몬스터는 블록·덱을 사용하지 않으므로
`DECK_CAPACITY`, `DRAW`, `PLACEMENT_COUNT`는 몬스터 행동에서 무시한다.

## 10. 상태와 상태이상

### 10.1 공통 지속 값

```text
duration = 0   즉시 적용 또는 상태별 고유 규칙
duration = 1+  해당 턴 수만큼 유지
duration = -1  현재 전투 종료까지 유지
duration = -2  영구 적용
```

`intensify`는 실제 계산값인 `value`와 별도로 효과의 단계 또는 스택 강도를 나타낸다.

### 10.2 출혈 `STATUS_DAMAGE / BLEEDING`

출혈은 대상에 따라 피해 기준이 다르다.

```text
플레이어가 받는 출혈 피해
= 해당 턴 사용 블록 개수 × 출혈 스택

몬스터가 받는 출혈 피해
= JSON value × 출혈 스택
```

- 플레이어 계산 기준은 블록이 차지하는 셀 수가 아니라 사용한 블록 개수다.
- 출혈은 방어도를 무시하고 체력에 직접 적용한다.
- 출혈 피해 처리 후 스택을 1 감소시킨다.
- 스택이 0이 되면 제거한다.

### 10.3 화상 `STATUS_DAMAGE / BURN`

```text
화상 피해 = 감소 전 화상 스택 수
처리 후 스택 = floor(처리 전 스택 / 2)
```

- 화상은 별도의 지속 턴을 사용하지 않으며 설정된 duration을 무시한다.
- 화상은 일반 피해처럼 방어도로 막을 수 있다.
- 스택이 1이면 피해 1을 처리한 뒤 0이 되어 제거된다.

### 10.4 약화 `DEBUFF / ATTACK_REDUCTION`

```text
value = 10  → 0.10
value = 0.1 → 0.10

D = max(0, 1 - 약화 감소율 합계)
```

약화는 기본 공격 B와 독립 공격 A의 D에 적용한다.

### 10.5 상처 `DEBUFF / DAMAGE_TAKEN_INCREASE`

```text
value = 10  → 0.10
value = 0.1 → 0.10

W = 1 + 상처 증가율 합계
```

상처는 공격자가 아니라 각 피해 대상의 상태를 기준으로 계산한다. 출혈과 화상에는
W를 적용하지 않는다.

### 10.6 새 약화·상처의 감소

최신 규칙은 다음과 같다.

- 새로 적용된 약화·상처 스택은 적용된 턴에 항상 보호한다.
- 해당 턴의 피해 계산에 실제로 참여했는지는 감소 조건으로 사용하지 않는다.
- 다음 턴부터 턴 종료마다 1스택 감소한다.
- 전투가 종료되면 남은 약화·상처를 제거한다.

### 10.7 기절 `CROWD_CONTROL / STUN`

- `value`는 무시한다.
- 지속은 1턴이다.
- `intensify`는 1로 고정하며 다른 값은 무시한다.
- 이미 기절한 대상에게 새 기절을 중첩하거나 갱신하지 않는다.
- 기존 기절이 끝난 뒤 다시 적용할 수 있다.

### 10.8 미구현 상태

다음 상태는 데이터 예약은 가능하지만 현재 전투 효과를 실행하지 않는다.

- `STATUS_DAMAGE / POISON`
- `CROWD_CONTROL / FREEZE`
- `CROWD_CONTROL / ACTION_LOCK`

미구현 상태를 임의로 다른 상태에 연결하지 않는다.

## 11. 공격 대상과 범위

### 11.1 슬롯

| 슬롯 | 용도 |
|---:|---|
| 1~4 | 일반·강력 몬스터 슬롯 |
| 5 | 보스 전용 슬롯 |

사망한 몬스터의 슬롯은 해당 전투가 끝날 때까지 빈자리로 유지한다. 남은 몬스터를
앞쪽 슬롯으로 당겨 전투 규칙상의 위치를 바꾸지 않는다.

### 11.2 대상 문법

| `target` | 범위 |
|---|---|
| `SELECTED` 또는 `self` | 기준 대상 1개 또는 자신 |
| `Lx` | 기준 대상과 왼쪽 x개 |
| `Rx` | 기준 대상과 오른쪽 x개 |
| `Bx` | 기준 대상과 양쪽 x개 |
| `all` | 살아 있는 전체 대상 |

예시는 다음과 같다.

```text
L1 = 기준 대상 + 왼쪽 1개
R2 = 기준 대상 + 오른쪽 2개
B1 = 기준 대상 + 왼쪽 1개 + 오른쪽 1개
```

보스 5번 슬롯은 1~4번 슬롯 모두와 인접한 것으로 취급한다. 빈 슬롯과 사망한 슬롯은
피해 대상에서 제외한다.

### 11.3 범위 판정 예시

```text
중심 2번 + 좌 1      → 1, 2, 5
중심 2번 + 우 1      → 2, 3, 5
중심 2번 + 좌우 1    → 1, 2, 3, 5
중심 1번 + 좌 1      → 1, 5
중심 1번 + 우 1      → 1, 2, 5
중심 5번 + 좌 1      → 1, 2, 3, 4, 5
중심 5번 + 우 1      → 1, 2, 3, 4, 5
```

## 12. 몬스터 출현과 전투 유형

### 12.1 일반 전투

- 1~4번 슬롯 중 1~2마리에 몬스터를 배치한다.
- 모든 적과 이미 시작된 연쇄 효과 처리가 끝난 뒤 살아 있는 적이 없으면 승리한다.
- 향후 몬스터 데이터에 “2마리 출현일 때만 등장” 같은 출현 인원 조건을 추가할 수 있다.

### 12.2 강력 전투

- 1~4번 슬롯 중 2~3마리에 강력 전투 몬스터를 배치한다.
- 승리 조건은 일반 전투와 같다.

### 12.3 보스전

- 5번 슬롯에 보스 정확히 1마리만 배치한다.
- 1~4번 슬롯에 부하 몬스터를 함께 생성하지 않는다.
- 5번 보스가 사망하는 즉시 승리한다.
- 남은 몬스터 행동, 플레이어 피해 패킷, 상태 처리와 연쇄 효과를 즉시 취소한다.

### 12.4 패배

플레이어 HP가 0이 되면 즉시 패배한다. 패배 후 런과 세이브 처리, 개발자 모드의
예외 동작은 `BLOCKABLE_GAME_DESIGN.md`에서 관리한다.

## 13. Monster Designer 효과 실행

몬스터 능력도 블록과 같은 공통 Type 및 상태 처리기를 사용한다. 같은 Type과
`parameters.id`는 플레이어와 몬스터에게 같은 의미로 적용한다.

몬스터는 가능하면 기본 공격에 `BASE_DAMAGE` 또는 `BASE_HIT_COUNT`를 사용한다.
`INDEPENDENT_DAMAGE`도 공통 공식상 지원하지만 몬스터 데이터에서는 특별한 이유가
없으면 사용하지 않는다.

몬스터 행동 순서는 살아 있는 1~4번 슬롯 순이며 보스는 5번 슬롯에서 행동한다.

`BUFF / DAMAGE_BONUS`는 현재 무효다. JSON 로딩 자체는 허용하지만 해당 효과를
실행 목록에서 제외하고 경고한다.

## 14. 승리·사망과 처리 중단

### 14.1 일반전

- 현재 실행 중인 피해 패킷과 이미 시작된 연쇄 효과를 마친다.
- 모든 적이 사망하고 플레이어가 살아 있으면 승리한다.
- 죽은 몬스터의 예정 행동은 취소한다.

### 14.2 보스전

- 5번 보스 사망을 확인한 즉시 승리한다.
- 아직 실행하지 않은 모든 행동과 효과를 취소한다.

### 14.3 플레이어 사망

- 플레이어 HP가 0이 되는 즉시 이후 행동을 중단한다.
- 같은 처리 단계에서 승리와 패배가 함께 가능해 보이면 전투 유형별 사망·승리
  판정 순서를 적용하고 로그에 원인을 남긴다.

## 15. 필수 검증 항목

### 15.1 조합과 피해

1. 색상이 다른 일반 블록으로도 같은 형태의 조합식이 발동한다.
2. 참여 블록 B만 조합 B에 합산된다.
3. 미참여 블록 B는 블록별 A 1회로 변환된다.
4. 미참여 블록은 조합 H를 상속하지 않는다.
5. `BASE_HIT_COUNT value=2, intensify=3`은 B 2를 H 3회 적용한다.
6. 여러 A 패킷이 임의로 합쳐지지 않는다.
7. B는 H회 각각 방어도와 생존 여부를 판정한다.

### 15.2 색상 시너지

1. 단일 속성은 해당 단계까지 하위 효과를 누적한다.
2. 정확히 두 속성은 뒤섞인 효과만 적용한다.
3. 세 속성은 모든 시너지와 시너지 표기를 적용하지 않는다.
4. 시너지 피해는 B가 아니라 A에 추가된다.
5. 시너지 A는 H를 상속하지 않는다.
6. 조합식이 여러 개여도 거푸집 전체 색상으로 한 번만 판정한다.
7. `steel`, `special`, `legendary`, `curse`는 속성 개수에서 제외한다.

### 15.3 상태

1. 플레이어 출혈은 사용 블록 개수×스택으로 계산한다.
2. 몬스터 출혈은 JSON value×스택으로 계산한다.
3. 출혈은 방어도를 무시한다.
4. 화상은 감소 전 스택만큼 피해를 주고 방어도로 막힌다.
5. 화상 처리 후 스택을 절반으로 내림한다.
6. 새 약화·상처는 적용 턴에 감소하지 않는다.
7. 약화·상처는 다음 턴부터 1스택씩 감소한다.
8. 기절은 중첩·갱신되지 않는다.

### 15.4 몬스터 수와 승리

1. 일반 전투는 1~2마리다.
2. 강력 전투는 2~3마리다.
3. 보스전은 5번 슬롯 보스 1마리만 생성한다.
4. 일반전은 모든 적과 연쇄 효과 처리 후 승리한다.
5. 보스전은 보스 사망 즉시 승리한다.

## 17. V0.5.3 확정 요약

1. 색상이 등급 분류 역할을 하며 별도 등급 필드는 사용하지 않는다.
2. 단일 속성, 정확히 두 속성, 세 속성의 시너지 판정을 분리한다.
3. 시너지 피해는 독립 피해 A로 처리한다.
4. 방어도 유지와 배율을 정식 전투 요소로 인정한다.
5. `BASE_HIT_COUNT.value`는 1타 B, `intensify`는 최종 H다.
6. 일반 1~2마리, 강력 2~3마리, 보스 1마리로 고정한다.
7. 플레이어와 몬스터의 출혈 계산 기준을 분리한다.
8. 새 약화·상처는 적용 턴에 항상 보호하고 다음 턴부터 감소한다.
9. 조합 미참여 블록의 B는 블록별 A 1회로 변환한다.
10. 튜토리얼, 청사진과 개발자 표시 규칙은 게임 기획 문서에서 관리한다.
