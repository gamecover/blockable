# BLOCKABLE 전투 시스템

문서 버전: 0.5.4
적용 게임 버전: v0.7.1 이후 개발 버전

이 문서는 전투 계산, 공통 효과 타입, 상태 효과, 색상 시너지의 최우선 기준이다.
UI·튜토리얼·청사진·개발자 기능은 `BLOCKABLE_GAME_DESIGN.md`에서 관리한다.

## 1. 전투 처리 순서

플레이어가 턴 종료를 확정하면 다음 순서로 처리한다.

1. 기본 공격 B를 H회 실행한다.
2. 독립 공격 A 패킷을 정의된 순서대로 실행한다.
3. 버프·디버프·지속 피해·군중 제어를 갱신한다.
4. 방어·회복·드로우·추가 턴·추가 배치 같은 자원 효과를 적용한다.
5. 추가 턴이 없다면 생존한 몬스터가 슬롯 순서대로 행동한다.
6. 턴 종료 상태 피해와 스택 감소를 처리한다.
7. 다음 턴을 시작한다.

일반 전투는 모든 적과 연쇄 효과 처리가 끝난 뒤 승리한다. 보스 전투는 5번 슬롯의 보스가 사망하면 즉시 승리하며 남은 부하 행동을 취소한다.

## 2. 피해 공식

| 기호 | 의미 | 기본값 |
| --- | --- | ---: |
| B | 기본 공격 1타의 피해 기준값 | 0 |
| P | 기본 공격에 직접 더하는 피해 보너스 | 0 |
| M | 공격력 증가 배율 | 1 |
| D | 약화 등 공격력 감소 배율 | 1 |
| W | 상처 등 받는 피해 증가 배율 | 1 |
| H | 기본 공격의 총 타격 횟수 | 1 |
| A | 기본 공격 뒤 별도로 실행하는 독립 피해 | 0 |

- 기본 공격 1타: `(B + P) × M × D × W`
- 기본 공격 총합: `((B + P) × M × D × W) × H`
- 독립 공격 패킷: `A × M × D × W`
- 계산 결과는 음수가 되지 않게 0으로 제한하고, 최종 피해의 소수점 이하는 버린다.
- A는 기본 공격 처리가 모두 끝난 뒤 패킷 순서대로 실행한다.

## 3. 블록과 조합식

### 3.1 합산 원칙

- 조합식에 참여한 블록의 `BASE_DAMAGE`, `BLOCK`, `RECOVERY`는 해당 조합 계산에 합산한다.
- 조합식 효과는 블록 색이 달라도 모양과 슬롯 조건이 맞으면 발동한다.
- 하나의 배치에서 여러 조합식이 성립하면 각 조합 효과를 정의된 순서대로 처리한다.

### 3.2 조합식에 사용되지 않은 블록

- 조합식에 참여하지 않은 블록의 `BASE_DAMAGE`는 B가 아니라 개별 A 패킷으로 변환한다.
- 변환된 A는 기본 공격 H의 영향을 받지 않고 한 번만 처리한다.
- 사용되지 않은 블록의 다른 유효 효과는 본래 타입을 유지한다.

## 4. 색상과 시너지

### 4.1 색상 분류

- 일반 색상: `steel`, `fire`, `water`, `nature`
- 추가 색상: `special`, `legendary`, `curse`
- 별도의 수치형 등급은 없으며 색상 분류로 시각적 등급을 표현한다.

### 4.2 적용 구분

- `fire`, `water`, `nature` 중 한 속성만 존재: 단색 단계 시너지
- 정확히 두 속성이 존재: 뒤섞인 시너지
- 세 속성이 모두 존재: 시너지 없음
- 단색 단계는 해당 색 블록 수를 단계로 삼고 하위 단계 효과를 누적한다.

### 4.3 단색 단계

화염:

1. A +10
2. 기본 공격과 독립 공격의 범위를 전체로 변경
3. A +20
4. H +1
5. H +1

물:

1. 방어 +10
2. 방어 +20
3. 방어도를 다음 턴까지 유지
4. 이번 턴 획득 방어도 2배
5. 이번 턴 방어도를 A에 합산

자연:

1. 회복 +2
2. 회복 +3
3. 회복 +5
4. 회복 +8
5. 회복 +12

중독 관련 자연 시너지는 중독 시스템과 별도로 확정할 때 연결한다.

### 4.4 뒤섞인 시너지

- 화염 + 물: A +5, 방어 +5
- 화염 + 자연: A +5, 회복 +1
- 색 순서는 결과에 영향을 주지 않는다.
- 뒤섞인 상태에서는 단색 단계 효과를 적용하지 않는다.

## 5. 공통 효과 JSON

블록 및 몬스터 디자인 JSON은 최상위 `metadata`에 적용하는 전투 효과 규격 버전을 반드시 선언한다.

```json
{
  "metadata": {
    "combat_effect_spec_version": "0.5.4"
  }
}
```

- 현재 런타임이 지원하는 값은 정확히 `"0.5.4"`이다.
- 필드가 없거나 값이 다르면 JSON 로딩을 중단하고 파일 경로와 원인을 포함한 검증 오류를 표시한다.
- 런타임은 이전 버전의 타입이나 `parameters.id`를 자동 변환하거나 추론하지 않는다.
- 디자이너 출력 JSON이 이 문서의 0.5.4 정규 형식을 직접 제공해야 한다.

개별 효과는 다음 구조를 사용한다.

```json
{
  "effect_id": "고정 효과 ID",
  "effect_name": "표시 또는 진단용 이름",
  "description": "설명",
  "target": "self",
  "value": 0,
  "type": "BASE_DAMAGE",
  "parameters": {
    "id": "NONE",
    "duration": 0,
    "intensify": 0
  }
}
```

- 실제 실행 의미는 `type`, `value`, `parameters.id`, `target`으로 결정한다.
- `effect_id`는 고정 식별자이며 중복되면 안 된다.
- `effect_name`과 `description`은 표시와 진단에 사용하며 계산을 결정하지 않는다.
- 0.5.4에서는 `parameters.duration`과 `parameters.intensify`를 읽되 계산에는 사용하지 않는다.

## 6. target

- `self`: 자신
- `SELECTED`: 선택한 대상
- `Lx`: 기준 대상과 왼쪽 x칸
- `Rx`: 기준 대상과 오른쪽 x칸
- `Bx`: 기준 대상과 양쪽 x칸
- `all`: 모든 대상

범위는 모든 공격·버프·디버프·지속 피해·군중 제어 효과에 적용할 수 있다.

## 7. type과 parameters.id

| type | parameters.id | value 의미 |
| --- | --- | --- |
| `BASE_DAMAGE` | `NONE` | B |
| `INDEPENDENT_DAMAGE` | `NONE` | A 패킷 |
| `BLOCK` | `NONE` | 획득 방어도 |
| `RECOVERY` | `NONE` | 회복량 |
| `DAMAGE_OVER_TIME` | `BURN`, `POISON`, `BLEED` | 부여 스택 |
| `BUFF` | `RAGE`, `ARMOR` | 부여 스택 |
| `DEBUFF` | `WEAKNESS`, `CHILL`, `WOUND` | 부여 스택 |
| `CROWD_CONTROL` | `STUN` | 부여 스택. 실제 스택은 1로 제한 |
| `EXTRA` | `DRAW` | 다음 턴 추가 드로우 수 |
| `EXTRA` | `HIT_COUNT` | H 추가 횟수 |
| `EXTRA` | `ATTACK_RANGE` | 공격 범위 변경 채널 |
| `EXTRA` | `TURN` | 추가 턴 수 |
| `EXTRA` | `PLACEMENT` | 추가 배치 수 |

`BASE_HIT_COUNT`, `STATUS_DAMAGE`, `EXTRA_TURN`, `DRAW`, `PLACEMENT_COUNT`, `PER_TURN`은 0.5.4의 정식 타입이 아니다. 이러한 구형 타입이 포함된 JSON은 런타임에서 변환하지 않고 검증 오류로 거부한다.

## 8. 지속 피해

### 8.1 화상 (`DAMAGE_OVER_TIME/BURN`)

- 턴 종료 시 현재 스택만큼 피해를 준다.
- 일반 피해처럼 방어도로 막을 수 있다.
- 피해 처리 뒤 스택을 절반으로 줄이고 소수점 이하는 버린다.
- 새로 부여된 턴에도 턴 종료 피해와 감소가 발생한다.

### 8.2 출혈 (`DAMAGE_OVER_TIME/BLEED`)

- 플레이어: 턴 종료 시 `스택 × 이번 턴 거푸집에 놓은 블록 개수` 피해
- 몬스터: 턴 종료 시 `스택 × 3` 피해
- 블록이 차지하는 칸 수가 아니라 배치한 블록 오브젝트 수를 사용한다.
- 방어도를 무시한다.
- 피해 처리 뒤 스택을 1 감소시킨다.

### 8.3 중독 (`DAMAGE_OVER_TIME/POISON`)

- 새로 부여된 다음 턴부터 작동한다.
- 플레이어: 블록을 하나 배치할 때마다 `max(1, floor(스택 × 0.5))` 피해
- 몬스터: 턴 종료 시 `스택 × 3` 피해
- 방어도를 무시한다.
- 턴 종료 시 스택을 절반으로 줄이고 소수점 이하는 버린다.

## 9. 버프

버프는 획득한 턴의 상태 갱신 단계에서 대기 상태가 된다. 다음 턴 시작부터 스택에 따라 작동하고, 그 턴 종료 시 전부 제거한다.

### 9.1 분노 (`BUFF/RAGE`)

- 스택당 P +1
- B에만 더해지며 A의 기준값에는 직접 더하지 않는다.

### 9.2 철갑 (`BUFF/ARMOR`)

- 해당 턴에 방어도를 획득할 때 스택당 방어 +1
- 오한과 상쇄하며 최종 추가 방어도는 0 미만이 될 수 없다.

## 10. 디버프

스택형 디버프는 적용된 턴에는 감소하지 않는다. 다음 턴부터 턴 종료마다 1스택 감소한다.

### 10.1 약화 (`DEBUFF/WEAKNESS`)

- 스택당 공격자의 D를 10% 감소시킨다.
- `D = max(0, 1 - 스택 × 0.1)`

### 10.2 상처 (`DEBUFF/WOUND`)

- 스택당 피격자의 W를 10% 증가시킨다.
- `W = 1 + 스택 × 0.1`

### 10.3 오한 (`DEBUFF/CHILL`)

- 새로 획득하는 방어도를 스택당 1 감소시킨다.
- 철갑과 상쇄하며 획득 방어도는 0 미만이 될 수 없다.

## 11. 군중 제어

### 기절 (`CROWD_CONTROL/STUN`)

- 대상의 다음 행동 한 번을 취소한다.
- 이미 기절 중인 대상에게 다시 부여해도 중첩하거나 갱신하지 않는다.
- 행동 취소 후 제거한다.

## 12. EXTRA

### 12.1 추가 드로우 (`EXTRA/DRAW`)

- 다음 턴 시작 시 value만큼 추가로 드로우한다.
- 덱과 핸드만 변하며 드로우 자체로 다른 효과를 발동하지 않는다.

### 12.2 추가 타격 (`EXTRA/HIT_COUNT`)

- value만큼 H를 증가시킨다.
- `value=2`이면 기본 H 1에 더해 총 3회 공격한다.

### 12.3 범위 변경 (`EXTRA/ATTACK_RANGE`)

- target의 범위를 공격 채널에 적용한다.
- value 채널: `0=A`, `1=B`, `2=B와 A`.

### 12.4 추가 턴 (`EXTRA/TURN`)

- 현재 턴의 B와 A, 상태·자원 처리가 끝난 뒤 value만큼 플레이어 추가 턴을 예약한다.
- 추가 턴은 완전히 새로운 플레이어 턴이다. 일반 드로우와 배치 횟수 초기화를 수행한다.
- 이전 턴 방어도는 별도 유지 효과가 없다면 초기화한다.
- 몬스터는 행동하지 않으며 몬스터의 턴 종료 상태 피해도 처리하지 않는다.
- 플레이어의 상태 처리와 공격·방어·회복은 정상 실행한다.
- 추가 턴에서 다시 추가 턴을 획득할 수 있다.

### 12.5 추가 배치 (`EXTRA/PLACEMENT`)

- value만큼 현재 입력 단계의 배치 가능 횟수를 늘린다.
- 추가 배치 선택을 끝낼 때까지 전투 계산과 상태 감소를 진행하지 않는다.

## 13. 방어와 회복

- 방어도는 일반 피해와 화상을 먼저 흡수한다.
- 출혈과 중독은 방어도를 무시한다.
- 턴이 끝나면 유지 효과가 없는 방어도는 0이 된다.
- 회복은 최대 체력을 넘을 수 없다.

## 14. 구현 경계

- JSON은 블록·조합·몬스터 효과 데이터를 제공한다.
- 메인 프로그램은 공식, 실행 순서, 상태 수명, 플레이어 전용 자원 제약을 관리한다.
- `DRAW`와 `PLACEMENT`는 현재 플레이어만 사용한다. 몬스터 데이터에 있으면 실행하지 않고 진단 정보로 남긴다.
- 알 수 없는 type 또는 `parameters.id`는 임의 연결하지 않고 원인을 포함한 런타임 오류로 처리한다.
