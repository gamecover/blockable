# BLOCKABLE 전투 시스템

문서 버전: 0.5.5  
공통 전투 Effect Spec 버전: **0.5.4**

## 문서 목적

이 문서는 **Blockable의 전투가 어떤 순서와 공식으로 계산되는지**를 정의하는 전투 시스템의 상세 기준 문서다.

이 문서가 관리하는 범위:

- 턴 처리 순서
- 공격·방어·회복 계산
- 블록과 조합식의 전투 효과 처리
- 색상 시너지
- 공통 Effect JSON
- 상태 효과와 수명
- 몬스터 행동 예약과 실행
- 사망·연쇄 효과
- 승리·패배 판정
- 전투 재시작 시 복원 원칙

UI의 구체 배치, 튜토리얼 단계, 청사진 발견 조건은 `BLOCKABLE_GAME_DESIGN.md`에서 관리한다.

지도에서 어떤 전투 노드가 생성되고 어떤 Encounter를 연결하는지는 `BLOCKABLE_MAP_SYSTEM.md`와 Encounter 데이터가 관리한다.

문서 간 충돌 시 최신 명시적 기획 결정을 우선한다.

# 1. 전투 기본 구조

## 1.1 전투 단계

플레이어가 턴 종료를 확정하면 다음 순서로 처리한다.

1. 플레이어의 기본 공격 B를 H회 실행한다.
2. 독립 공격 A 패킷을 정의된 순서대로 실행한다.
3. 버프·디버프·지속 피해·군중 제어를 갱신한다.
4. 방어·회복·드로우·추가 턴·추가 배치 같은 자원 효과를 적용한다.
5. 새 사망자와 사망·연쇄 효과 대기열을 처리한다.
6. 보스 즉시 승리 예외를 확인한다.
7. 추가 턴이 없으면 생존한 몬스터가 예약된 행동을 슬롯 순서대로 실행한다.
8. 각 몬스터 행동 뒤 새 사망자와 연쇄 효과를 처리한다.
9. 턴 종료 상태 피해와 상태 수명을 처리한다.
10. 최종 승리·패배를 판정한다.
11. 전투가 계속되면 사용·미사용 블록을 버림 더미로 보내고 거푸집을 비운다.
12. 유지 효과가 없는 방어도를 초기화한다.
13. 추가 턴 또는 다음 일반 턴을 시작한다.

## 1.2 플레이어 입력 단계

턴 시작 시:

1. 살아 있는 각 몬스터의 이번 턴 행동을 확정한다.
2. 몬스터 행동 예고를 화면에 공개한다.
3. 블록을 드로우한다.
4. 플레이어가 블록을 배치·회전·회수한다.
5. 조합과 색상 시너지 Preview를 계산한다.
6. 필요한 경우 중심 공격 대상을 선택한다.
7. 플레이어가 턴 종료를 확정한다.

Preview는 정보를 보여주기 위한 계산이며 실제 HP, 상태, 덱을 변경해서는 안 된다.

# 2. 적 슬롯과 대상 판정

## 2.1 일반 슬롯

일반 전투 계열은 1~4번 고정 슬롯을 사용한다.

```text
[1] [2] [3] [4]
```

- 한 몬스터는 하나의 슬롯을 점유한다.
- 사망한 몬스터의 슬롯은 빈 상태로 남는다.
- 다른 몬스터가 빈 슬롯으로 자동 이동하지 않는다.
- 범위는 현재 살아 있는 몬스터의 배열 순서가 아니라 고정 슬롯 위치를 기준으로 한다.

## 2.2 보스 슬롯

보스는 5번 전용 슬롯을 사용한다.

```text
[1] — [2] — [3] — [4]
  ╲      │      │      ╱
             [5]
```

- 5번 슬롯은 1~4번 슬롯 모두와 직접 연결된다.
- 기본 보스전에서는 5번 슬롯의 보스 1마리만 사용한다.
- 보스전 범위 판정은 1~4번의 선형 거리와 5번 슬롯의 연결 관계를 함께 사용한다.

## 2.3 target

공통 Effect의 `target`은 다음 기준을 사용한다.

| target | 의미 |
|---|---|
| `self` | 시전자 자신 |
| `SELECTED` | 직접 선택한 중심 대상 |
| `Lx` | 중심 대상 + 왼쪽 x 슬롯 |
| `Rx` | 중심 대상 + 오른쪽 x 슬롯 |
| `Bx` | 중심 대상 + 좌우 각각 x 슬롯 |
| `all` | 해당 진영의 모든 유효 대상 |

필요한 Effect는 대상 진영 정보를 별도로 가진다.

예:

- 플레이어
- 시전자 자신
- 특정 아군 몬스터
- 모든 아군 몬스터
- 지정된 적 슬롯 범위
- 모든 전투 참가자
- 시전자를 제외한 모든 전투 참가자

## 2.4 단일과 범위 공격

단일 공격:

- 살아 있는 유효 대상 한 마리를 직접 선택한다.
- 선택한 대상에게만 적용한다.

좌·우·좌우 범위:

- 직접 선택한 중심 대상을 포함한다.
- 슬롯 범위를 벗어난 위치는 무시한다.
- 빈 슬롯에는 효과가 발생하지 않는다.
- 빈 슬롯 때문에 범위를 확장하지 않는다.

전체 공격:

- 별도의 중심 대상을 필요로 하지 않는다.
- 실행 시점의 모든 살아 있는 유효 대상을 다시 판정한다.

## 2.5 중심 대상 무효화

- 중심 대상이 필요한 효과인데 유효 대상이 없으면 해당 공격 기회를 취소한다.
- 공격 실행 전 중심 대상이 사망·무효화되면 다른 적으로 자동 재지정하지 않는다.
- 기본 공격 B의 연타 도중 중심 대상이 사망하면 남은 B 타격을 다른 적에게 넘기지 않는다.
- A는 B와 별도의 독립 공격이므로 자신의 target을 다시 판정한다.
- A가 지정한 대상이 무효라면 A 역시 자동 재지정하지 않는다.

# 3. 피해 계산 변수

| 기호 | 의미 | 기본값 |
|---|---|---:|
| B | 기본 공격 1타의 피해 기준값 | 0 |
| P | 기본 공격에 직접 더하는 피해 보너스 | 0 |
| M | 공격력 증가 배율 | 1 |
| D | 공격력 감소 배율 | 1 |
| W | 피격자의 받는 피해 증가 배율 | 1 |
| H | 기본 공격 총 타격 횟수 | 1 |
| A | 독립 피해 패킷의 기준값 | 0 |

## 3.1 기본 공격

```text
기본 공격 1타 = (B + P) × M × D × W
```

- H회 개별 실행한다.
- 각 타격마다 방어도, 피해, 사망, 피격 반응과 연쇄 효과를 처리한다.
- 최종 적용 피해는 0 미만이 되지 않는다.
- 최종 피해의 소수점 이하는 버린다.

## 3.2 독립 공격

```text
독립 공격 = A × M × D × W
```

- 모든 기본 공격 처리가 끝난 뒤 실행한다.
- 각 A 패킷은 출처별로 독립적으로 유지한다.
- 여러 A를 임의로 하나로 합치지 않는다.
- 기본 공격 H를 상속하지 않는다.

## 3.3 Raw 값과 적용 값

전투 계산과 Presentation이 필요할 경우 계산 전 Raw 값과 실제 적용 값을 구분할 수 있다.

예:

```text
rawDamage = 계산 결과
appliedDamage = max(0, floor(rawDamage))
```

실제 HP에는 `appliedDamage`만 적용한다.

여러 B 성분이 하나의 기본 공격으로 합산되는 경우 각 성분을 먼저 0으로 Clamp하지 않고 **Raw 합산 후 최종 공격 단위에서 Clamp**한다.

# 4. 방어와 회복

## 4.1 방어도

방어도는 방어도 무시 피해가 아닌 일반 피해를 먼저 흡수한다.

```text
armorDamage = min(currentArmor, damage)
hpDamage = max(0, damage - currentArmor)
nextArmor = max(0, currentArmor - damage)
nextHp = max(0, currentHp - hpDamage)
```

- 현재 턴에 획득한 방어도는 같은 턴의 몬스터 공격을 막을 수 있다.
- 기본적으로 턴 종료 시 0이 된다.
- 유지 효과가 있으면 정해진 턴까지 보존할 수 있다.

## 4.2 방어도 무시 피해

- 출혈과 중독 등 명시된 효과는 방어도를 무시한다.
- 방어도 값을 변경하지 않고 HP에 직접 적용한다.

## 4.3 회복

- `RECOVERY`의 `value`만큼 HP를 회복한다.
- 현재 HP는 최대 HP를 초과하지 않는다.

# 5. 블록과 조합식

## 5.1 조합 참여 블록

조합식에 참여한 블록의 전투 Effect는 조합 계산에 사용한다.

- `BASE_DAMAGE`
- `BLOCK`
- `RECOVERY`
- 기타 유효한 공통 Effect

조합의 실제 기하 판정과 참여 블록 결정은 블록·조합 데이터에 따른다.

## 5.2 조합에 참여하지 않은 블록

- 조합에 참여하지 않은 블록의 `BASE_DAMAGE`는 B에 합산하지 않는다.
- 각 블록의 B를 **개별 A 패킷 1회**로 변환한다.
- 이 A는 조합의 H를 상속하지 않는다.
- 블록이 가진 다른 유효 Effect는 원래 Type을 유지한다.

## 5.3 여러 조합

하나의 배치에서 여러 조합이 유효한 경우 정의된 순서로 처리한다.

여러 조합이 동일 블록을 공유할 수 있는지, 완전한 다중 조합 우선순위 등 고도화 규칙은 정식 확장 항목이다.

# 6. 색상 시너지

## 6.1 색상 분류

일반 색상:

- `steel`
- `fire`
- `water`
- `nature`

추가 분류:

- `special`
- `legendary`
- `curse`

`fire`, `water`, `nature`만 기본 속성 시너지 계산에 참여한다.

## 6.2 적용 규칙

- 한 속성만 존재: 단색 단계 시너지
- 정확히 두 속성 존재: 뒤섞인 시너지
- 세 속성 모두 존재: 시너지 없음

단색 단계에서는 현재 거푸집의 해당 색 블록 개수를 단계로 사용하고 하위 단계 효과를 누적한다.

## 6.3 화염

1. A +10
2. B와 A 공격 범위를 전체로 변경
3. A +20
4. H +1
5. H +1

## 6.4 물

1. 방어 +10
2. 방어 +20
3. 방어도를 다음 턴까지 유지
4. 이번 턴 획득 방어도 2배
5. 이번 턴 방어도를 A에 합산

## 6.5 자연

1. 회복 +2
2. 회복 +3
3. 회복 +5
4. 회복 +8
5. 회복 +12

## 6.6 뒤섞인 시너지

- 화염 + 물: A +5, 방어 +5
- 화염 + 자연: A +5, 회복 +1
- 뒤섞인 상태에서는 단색 단계 효과를 적용하지 않는다.

추가 색상 조합은 별도 확정 전까지 임의로 생성하지 않는다.

# 7. 공통 Effect JSON

## 7.1 Effect Spec 버전

Block Designer와 Monster Designer가 출력하는 JSON의 최상위 `metadata`는 다음 버전을 선언한다.

```json
{
  "metadata": {
    "combat_effect_spec_version": "0.5.4"
  }
}
```

현재 정식 Effect Spec은 **0.5.4**다.

- 문서 버전이 0.5.5가 되어도 Effect JSON 스키마 자체는 0.5.4를 유지한다.
- 버전이 없거나 지원하지 않는 값이면 로딩을 중단하고 원인을 보고한다.
- 구형 Type이나 ID를 런타임에서 임의 추론·자동 변환하지 않는다.

## 7.2 개별 Effect 구조

```json
{
  "effect_id": "unique_effect_id",
  "effect_name": "표시 이름",
  "description": "설명",
  "target": "self",
  "value": 0,
  "type": "BASE_DAMAGE",
  "parameters": {
    "id": "NONE",
    "duration": 0,
    "intensify": 0
  }
}
```

실제 실행 의미는 다음 필드가 결정한다.

- `type`
- `parameters.id`
- `value`
- `target`

`effect_name`과 `description`은 표시와 검토용 정보이며 계산 의미를 추론하는 기준으로 사용하지 않는다.

## 7.3 Type과 ID

| type | parameters.id | value 의미 |
|---|---|---|
| `BASE_DAMAGE` | `NONE` | B |
| `INDEPENDENT_DAMAGE` | `NONE` | A 패킷 |
| `BLOCK` | `NONE` | 방어도 획득량 |
| `RECOVERY` | `NONE` | HP 회복량 |
| `DAMAGE_OVER_TIME` | `BURN` | 화상 스택 |
| `DAMAGE_OVER_TIME` | `POISON` | 중독 스택 |
| `DAMAGE_OVER_TIME` | `BLEED` | 출혈 스택 |
| `BUFF` | `RAGE` | 분노 스택 |
| `BUFF` | `ARMOR` | 철갑 스택 |
| `DEBUFF` | `WEAKNESS` | 약화 스택 |
| `DEBUFF` | `CHILL` | 오한 스택 |
| `DEBUFF` | `WOUND` | 상처 스택 |
| `CROWD_CONTROL` | `STUN` | 기절 |
| `EXTRA` | `DRAW` | 다음 턴 추가 드로우 |
| `EXTRA` | `HIT_COUNT` | H 추가 |
| `EXTRA` | `ATTACK_RANGE` | 공격 범위 변경 |
| `EXTRA` | `TURN` | 추가 턴 |
| `EXTRA` | `PLACEMENT` | 추가 배치 |

다음 구형 Type은 0.5.4 정식 Type이 아니다.

- `BASE_HIT_COUNT`
- `STATUS_DAMAGE`
- `EXTRA_TURN`
- `DRAW`
- `PLACEMENT_COUNT`
- `PER_TURN`

# 8. 지속 피해

## 8.1 화상 — `DAMAGE_OVER_TIME/BURN`

- 턴 종료 시 현재 화상 스택만큼 피해를 준다.
- 일반 피해처럼 방어도로 막을 수 있다.
- 피해 처리 후 스택을 절반으로 줄이고 소수점 이하는 버린다.
- 새로 부여된 턴에도 피해와 감소가 발생한다.

## 8.2 출혈 — `DAMAGE_OVER_TIME/BLEED`

플레이어:

```text
출혈 피해 = 현재 출혈 스택 × 이번 턴 최종 사용 블록 개수
```

몬스터:

```text
출혈 피해 = 현재 출혈 스택 × 3
```

- 방어도를 무시한다.
- 피해 처리 후 스택을 1 감소시킨다.
- 플레이어 계산에서 블록 칸 수가 아니라 사용한 블록 오브젝트 수를 사용한다.

## 8.3 중독 — `DAMAGE_OVER_TIME/POISON`

중독은 부여된 다음 턴부터 작동한다.

플레이어:

```text
블록 1개 배치 시 피해 = max(1, floor(중독 스택 × 0.5))
```

몬스터:

```text
턴 종료 피해 = 중독 스택 × 3
```

- 방어도를 무시한다.
- 턴 종료 시 스택을 절반으로 줄이고 소수점 이하는 버린다.

# 9. 버프

버프는 획득한 턴에는 대기 상태가 되며 다음 턴부터 활성화된다. 활성화된 턴 종료 시 제거한다.

## 9.1 분노 — `BUFF/RAGE`

```text
P = P + 분노 스택
```

- 스택당 P +1
- B에만 직접 추가된다.
- A 기준값에는 직접 더하지 않는다.

## 9.2 철갑 — `BUFF/ARMOR`

- 새 방어도를 획득할 때 스택당 +1
- 오한과 서로 상쇄한다.
- 최종 추가 방어도는 0 미만이 될 수 없다.

---

# 10. 디버프

새로 적용된 약화·상처·오한은 해당 턴에 감소하지 않는다. 다음 턴부터 턴 종료마다 1스택 감소한다.

## 10.1 약화 — `DEBUFF/WEAKNESS`

```text
D = max(0, 1 - 약화 스택 × 0.1)
```

공격자의 일반 공격 피해 배율을 감소시킨다.

## 10.2 상처 — `DEBUFF/WOUND`

```text
W = 1 + 상처 스택 × 0.1
```

피격자가 받는 일반 공격 피해를 증가시킨다.

## 10.3 오한 — `DEBUFF/CHILL`

- 새로 획득하는 방어도를 스택당 1 감소시킨다.
- 철갑과 서로 상쇄한다.
- 최종 획득 방어도는 0 미만이 될 수 없다.

---

# 11. 군중 제어

## 11.1 기절 — `CROWD_CONTROL/STUN`

- 대상 몬스터의 다음 예약 행동 1회를 건너뛴다.
- 최대 1스택이다.
- 이미 기절 중이면 중첩하거나 갱신하지 않는다.
- 실제 행동 순서가 왔을 때 행동을 취소하고 기절을 제거한다.
- 기절로 행동을 건너뛰어도 몬스터의 행동 패턴 위치는 다음 단계로 진행한다.
- 행동 차례 전에 사망하면 기절을 소비하지 않는다.

---

# 12. EXTRA

## 12.1 추가 드로우 — `EXTRA/DRAW`

- 다음 턴 시작 시 `value`만큼 추가 드로우한다.
- 드로우 자체로 별도 전투 Effect를 발동하지 않는다.

## 12.2 추가 타격 — `EXTRA/HIT_COUNT`

```text
H = H + value
```

예: `value=2`이면 기본 H 1에 더해 총 3회 공격한다.

## 12.3 공격 범위 변경 — `EXTRA/ATTACK_RANGE`

`target`의 범위를 지정 공격 채널에 적용한다.

`value` 채널:

- `0`: A
- `1`: B
- `2`: B와 A

## 12.4 추가 턴 — `EXTRA/TURN`

- 현재 턴의 플레이어 Effect 처리 후 `value`만큼 추가 플레이어 턴을 예약한다.
- 추가 턴은 완전히 새로운 Player Turn이다.
- 일반 드로우를 수행한다.
- 기본 배치 횟수를 다시 제공한다.
- 거푸집은 빈 상태로 시작한다.
- 별도 유지 효과가 없는 방어도는 초기화한다.
- 몬스터는 행동하지 않는다.
- 몬스터의 턴 종료 상태 피해·감소도 처리하지 않는다.
- 플레이어 상태 처리와 공격·방어·회복은 정상 실행한다.
- 추가 턴에서 다시 추가 턴을 얻을 수 있다.

## 12.5 추가 배치 — `EXTRA/PLACEMENT`

- 현재 입력 단계의 배치 가능 횟수를 `value`만큼 늘린다.
- 추가 배치 선택이 끝날 때까지 전투 계산 단계로 넘어가지 않는다.

---

# 13. 몬스터 행동 예약 — Intent

Monster Intent는 단순 UI 설명이 아니라 전투 규칙의 일부다.

## 13.1 행동 결정 시점

각 살아 있는 몬스터는 **플레이어 입력 단계가 시작되기 전에 이번 턴에 사용할 Ability를 확정**한다.

개념 흐름:

```text
Turn 시작
→ Monster Pattern / AI 판정
→ planned ability 확정
→ UI Intent 공개
→ Player 입력
→ Monster 행동 단계
→ 같은 planned ability 실행
```

## 13.2 Planned Ability

구현 데이터 이름은 프로젝트 구조에 따라 달라질 수 있으나 의미상 다음 정보를 유지해야 한다.

- `ability_id`
- 예상 Damage 또는 주요 수치
- target / range
- 적용 Effect
- 해당 행동의 Pattern 위치 또는 조건

## 13.3 UI와 실제 행동 일치

금지되는 구조:

```text
UI 표시 시 Random
→ Ability A 표시

실제 행동 시 다시 Random
→ Ability B 실행
```

정식 구조:

```text
행동 계획 단계에서 Ability A 확정
→ UI에서 Ability A 표시
→ 실제 행동에서도 Ability A 실행
```

Presentation은 행동 선택용 난수를 별도로 생성하지 않는다.

## 13.4 여러 몬스터

- 각 몬스터는 독립적인 Planned Ability를 가진다.
- Monster A를 선택하면 A의 Intent를 보여준다.
- Monster B를 선택하면 B의 Intent를 보여준다.
- 한 몬스터의 Intent를 다른 몬스터가 공유하지 않는다.

## 13.5 사망과 행동 취소

- 행동 순서 전에 몬스터가 사망하면 Planned Ability를 실행하지 않는다.
- 기절 상태라면 Planned Ability 자체를 다른 Ability로 바꾸는 것이 아니라 현재 예약 행동을 건너뛴다.
- 다음 턴에는 Monster Pattern 규칙에 따라 새로운 Planned Ability를 결정한다.

## 13.6 Intent에 표시해야 할 전투 정보

최소 정보:

- 기술명
- 예상 피해
- 범위 또는 대상
- 상태 이상·버프·디버프 등의 부가 Effect

사용자용 Effect 이름과 범위 표현은 공통 Formatter를 사용하고 내부 ID를 그대로 노출하지 않는다.

---

# 14. 몬스터 등급과 Encounter 경계

전투 시스템이 사용하는 정식 Grade:

| grade | 의미 |
|---|---|
| `normal` | 일반 |
| `elite` | 엘리트 |
| `boss` | 보스 |

전투 시스템은 이미 결정된 Encounter를 실행한다.

즉 다음은 Combat System의 책임이 아니다.

- 특정 노드에서 어떤 Monster ID를 뽑을지
- 동일 Boss 중복 방지 방식
- 특정 Monster 조합의 Spawn 확률
- 프로토타입용 임시 Spawn 규칙

이러한 결정은 Encounter/Map/Data 계층이 담당한다.

Combat System은 전달받은 몬스터들의 슬롯, 능력치, Ability, Effect를 동일한 전투 규칙으로 처리한다.

---

# 15. 사망·연쇄 효과

## 15.1 발동 유형

다음은 서로 다른 조건이다.

- 자폭 행동
- 사망 시 효과
- 피격 반응 효과

## 15.2 연쇄 처리

사망 효과는 즉시 재귀 호출하지 않고 순차 대기열로 처리한다.

```text
현재 공격/효과 완료
→ 새 사망자 확인
→ 사망 효과 Queue 등록
→ Queue 첫 효과 실행
→ 새 사망자 확인
→ Queue가 빌 때까지 반복
```

## 15.3 순서

한 효과로 여러 몬스터가 동시에 사망하면:

1. 1번 슬롯
2. 2번 슬롯
3. 3번 슬롯
4. 4번 슬롯
5. 보스가 함께 포함된다면 5번 슬롯

순으로 Queue에 등록한다.

동일한 사망 이벤트가 중복 실행되지 않도록 한다.

---

# 16. 턴 종료 상태 처리

기본 순서:

1. 플레이어 출혈 피해 및 감소
2. 플레이어 생존 시 화상 피해 및 감소
3. 플레이어 중독 관련 처리
4. 보호가 끝난 약화·상처·오한 감소
5. 활성 분노·철갑 제거 및 대기 Buff 활성화
6. 추가 턴이 아니라면 살아 있는 몬스터를 슬롯 순서로 선택
7. 몬스터 출혈
8. 몬스터 화상
9. 몬스터 중독 및 디버프 감소
10. 몬스터 Buff 수명 처리
11. 각 상태 피해 후 사망·연쇄 Queue 처리
12. 일반전 최종 승리·패배 판정

상태 피해로 5번 Boss가 사망하면 보스전 즉시 승리 규칙을 적용한다.

---

# 17. 전투 종료

## 17.1 일반 전투

승리 조건:

- 모든 적이 사망
- 현재 Effect 처리가 끝남
- 사망·연쇄 Queue가 비어 있음
- 플레이어가 생존

마지막 적의 사망 효과로 플레이어가 사망하면 승리가 아니라 패배다.

## 17.2 보스전

5번 Boss 사망이 확정되면 즉시 승리한다.

- 남은 미실행 몬스터 행동 취소
- 남은 상태 처리 취소
- 이후 승리 흐름으로 진행

## 17.3 패배

필수 후속 처리 후 플레이어 HP가 0 이하이면 패배한다.

---

# 18. 전투 중 종료와 Continue

Blockable은 전투 중간의 모든 Runtime 상태를 그대로 저장하는 방식을 기본으로 하지 않는다.

전투 중 종료하면 Continue에서 해당 전투의 **시작 상태**로 돌아간다.

다만 다음은 동일해야 한다.

- Encounter ID
- 몬스터 ID와 슬롯 구성
- 플레이어 전투 시작 HP / Gold / Deck
- 전투 시작 Random Seed 또는 동등한 결정 정보
- 초기 Shuffle / Draw를 결정하는 상태

따라서 반복 Continue로 Monster 또는 초기 블록 순서를 재추첨할 수 없어야 한다.

저장 구조의 상세 기준은 `BLOCKABLE_MAP_SYSTEM.md`를 따른다.

---

# 19. Designer와 Runtime 역할

## 19.1 Block Designer

- 블록 데이터
- 조합 데이터
- 블록·조합 Effect
- 범위와 설명

을 JSON으로 출력한다.

## 19.2 Monster Designer

- 몬스터 능력치
- Ability
- 행동 Pattern
- 자폭·사망·피격 반응
- Effect

를 JSON으로 출력한다.

## 19.3 Runtime

Runtime은 공통 Effect를 다음 정보로 해석한다.

```text
type + parameters.id + value + target
```

- 이름이나 description을 보고 실행 의미를 추론하지 않는다.
- 알 수 없는 Type / ID를 임의 연결하지 않는다.
- 지원하지 않는 Effect를 발견하면 오류 또는 진단 결과로 보고한다.
