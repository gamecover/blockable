# Blockable 게임 기획안 v0.5.5

## 문서 목적

이 문서는 **Blockable에서 플레이어가 무엇을 경험하고 어떤 규칙으로 게임을 진행하는지**를 정의하는 최상위 게임 기획 문서다.

세부 전투 계산은 `BLOCKABLE_COMBAT_SYSTEM.md`, 지도 생성·이동·저장은 `BLOCKABLE_MAP_SYSTEM.md`, 코드 구조와 구현 원칙은 `BLOCKABLE_CODEX_DEVELOPMENT_GUIDE.md`를 기준으로 한다.

문서 간 내용이 충돌하면 다음 우선순위를 적용한다.

1. 최신 명시적 기획 결정
2. 해당 분야의 상세 시스템 문서
3. 이 문서의 상위 개념 설명
4. 기존 문서의 오래된 내용
5. 프로토타입 임시 구현 코드

프로토타입 마감을 위해 존재하는 하드코딩, 일시적인 스폰 규칙, UI 버그 수정 이력, 특정 CSS 좌표·폰트 크기·이미지 파일명은 이 문서의 정식 기획으로 취급하지 않는다.

# 1. 게임 개요

## 1.1 장르

- 로그라이크 덱빌딩
- 블록 배치 퍼즐
- 턴제 전투

## 1.2 플랫폼

- 웹 브라우저 기반 싱글 플레이 게임
- 설치 없이 링크를 통해 실행하는 정적 웹 배포를 기본으로 한다.

## 1.3 핵심 컨셉

플레이어는 세계 최고의 대장장이가 되어 직접 던전에 들어간다. 전투에서는 카드 대신 여러 칸으로 이루어진 **블록**을 주머니에서 뽑아 거푸집에 배치한다. 블록 자체 효과, 배치 조합, 색상 시너지와 상태 효과를 이용해 몬스터의 다음 행동에 대응하고 덱을 정비하며 던전을 공략한다.

Blockable의 핵심 재미는 다음 세 요소의 결합에 있다.

1. **블록 배치 퍼즐**: 제한된 거푸집에 어떤 블록을 어떤 방향으로 놓을지 판단한다.
2. **덱빌딩**: 전투·이벤트·상점·휴식을 통해 현재 런의 블록 덱을 변화시킨다.
3. **행동 예고 기반 턴제 전투**: 몬스터의 이번 턴 기술과 피해·범위·효과를 확인한 뒤 가장 유리한 배치를 선택한다.

## 1.4 한 문장 요약

> 전체 지도에서 던전을 선택하고 노드형 층 지도를 탐험하며, 매 턴 주머니에서 뽑은 블록을 거푸집에 배치해 조합과 색상 시너지를 만들고 몬스터의 행동 예고에 대응하여 최종 던전의 보스를 처치하는 로그라이크 블록 배치 게임이다.

# 2. 세계관 및 프롤로그

세계 제일의 대장장이인 당신.

그러나 당신의 실력을 비웃기라도 하는 듯, 당신이 만든 무기로 출정을 떠난 용사들은 하나같이 던전을 정복하지 못하고 패퇴를 반복하고 있었다.

답답함에 보다 못한 당신은 자신의 '블럭 주머니'를 들고 직접 던전을 정복하기로 한다.

당신은 과연 던전을 정복할 수 있을까?

# 3. 전체 게임 진행

## 3.1 해커톤 버전의 전체 흐름

```text
새 게임
→ 프롤로그
→ 고유 블록 선택
→ 전체 지도
   ├─ 일반 던전 A 또는 B 선택
   │  → 층 지도 탐험
   │  → 전투 / 이벤트 / 상점 / 휴식 / 보상
   │  → 던전 최종 보스
   │  → 일반 던전 클리어
   │  → 전체 지도 복귀
   │
   └─ 중앙 최종 던전 입장
      → 중앙 최종 던전 탐험
      → 전투 / 이벤트 / 상점 / 휴식 / 보상
      → 최종 보스
      → 최종 승리 / 엔딩
```

- 플레이어는 전체 지도에 진입한 이후 **일반 던전과 중앙 최종 던전 중 원하는 곳을 선택할 수 있다.**
- 중앙 최종 던전은 일반 던전 클리어 여부와 관계없이 처음부터 입장할 수 있다.
- 일반 던전은 블록, Gold, 덱 정비 등 추가적인 성장과 파밍을 위한 선택적 공략 경로다.
- 일반 던전을 클리어하면 중앙 최종 던전으로 자동 진행하지 않고 **전체 지도로 복귀한다.**
- 플레이어가 사망하면 현재 런은 종료된다.

## 3.2 전체 지도

- 해커톤 버전에는 **일반 던전 2개와 중앙 최종 던전 1개**가 존재한다.
- 플레이어는 전체 지도에서 일반 던전 또는 중앙 최종 던전을 선택해 입장할 수 있다.
- 두 일반 던전은 원하는 순서로 공략할 수 있으며, 반드시 모두 완료할 필요는 없다.
- **중앙 최종 던전은 별도의 개방 조건 없이 처음부터 입장 가능하다.**
- 일반 던전은 전투, 이벤트, 상점, 휴식과 보상을 통해 블록과 자원을 획득하고 덱을 성장시키기 위한 선택적 공략 지역이다.
- 일반 던전에서 획득한 블록과 덱 변화, 플레이어의 진행 상태는 현재 런 동안 유지된다.
- 일반 던전을 완료하면 전체 지도로 복귀하며, 이후 다른 일반 던전 또는 중앙 최종 던전을 선택할 수 있다.
- 중앙 최종 던전의 최종 보스를 처치하면 게임을 클리어한다.

## 3.3 고유 블록 선택

고유 블록 선택은 **새 게임에서 한 번만** 진행한다.

- 기본 시작 덱은 고정 블록 12개로 시작한다.
- 프롤로그 이후, 최초 전체 지도 진입 전에 고유 블록 1개를 선택한다.
- 선택한 고유 블록을 추가하여 시작 덱은 총 13개가 된다.
- 각 던전 또는 각 층의 시작 노드에서 고유 블록을 다시 선택하지 않는다.

## 3.4 중앙 최종 던전

- 중앙 최종 던전은 최종 도전 구간이다.
- 현재 게임 기획 기준으로 중앙 최종 던전은 **총 3층**으로 구성한다.
- 마지막 층의 최종 보스를 처치하면 일반 던전 클리어가 아니라 게임 전체 승리로 처리한다.
- 층 수를 코드 조건문으로 직접 고정하는 방식은 구현 세부이며 본 기획의 대상이 아니다.

# 4. 던전과 지도 탐험

상세 생성 규칙, 난이도별 노드 수, 브랜치 수, 검증과 저장 방식은 `BLOCKABLE_MAP_SYSTEM.md`를 따른다.

## 4.1 지도 계층

```text
전체 지도
└─ 던전
   └─ 층
      └─ 노드와 통로
```

하나의 층은 시작 노드에서 계단 또는 보스 노드까지 이어지는 **주 경로**와, 선택적으로 탐험할 수 있는 **브랜치**로 구성된다.

## 4.2 탐험 원칙

- 시작 노드에서 목적지까지 도달 가능한 주 경로가 존재한다.
- 브랜치는 전투, 이벤트, 상점, 휴식, 보상과 같은 선택 기회를 제공한다.
- 위험 브랜치는 더 높은 위험과 더 높은 보상을 제공한다.
- 완료한 노드는 다시 방문할 수 있다.
- 완료한 전투·이벤트·휴식·보상은 재방문 시 다시 발생하지 않는다.
- 완료한 노드만 지나는 경로는 자동 이동할 수 있다.
- 미완료 노드를 통과하여 그 뒤로 이동할 수 없다.
- 다음 층으로 이동하면 이전 층으로 돌아갈 수 없다.

## 4.3 노드 종류

현재 게임의 주요 노드는 다음과 같다.

| 노드 | 역할 |
|---|---|
| 층 시작 | 안전한 층 진입 지점 |
| 일반 전투 | 일반 전투 인카운터 |
| 강적 | 일반 전투보다 위험한 전투 인카운터 |
| 이벤트 | 선택과 결과가 있는 비전투 인카운터 |
| 상점 | Gold를 사용해 덱을 정비 |
| 휴식 | 블록 또는 체력을 정비 |
| 보상 | 골드·블록 등 보상 획득 |
| 계단 | 다음 층으로 이동 |
| 보스 | 해당 던전 또는 최종 진행을 위한 보스 전투 |

## 4.4 지도 정보 공개

- 현재 위치와 이동 가능한 노드는 명확하게 구분한다.
- 완료한 노드는 완료 상태로 표시한다.
- 위험한 경로와 강적 노드는 일반 경로보다 명확한 경고 표현을 제공한다.
- 멀리 떨어진 미발견 노드의 정확한 콘텐츠는 공개하지 않는다.
- 지도에서는 위험을 예상할 수 있게 하되 정확한 몬스터 구성과 보상 결과까지 모두 미리 공개하지 않는다.

# 5. 블록과 덱

## 5.1 덱의 표현

게임에서 덱은 **블록 주머니**로 표현한다.

- 시작 덱은 고정 블록 12개 + 고유 블록 1개, 총 13개다.
- 현재 런 동안 보상, 상점, 휴식과 이벤트에 의해 덱 구성이 변할 수 있다.
- 덱에 추가하거나 제거한 결과는 이후 전투에서도 유지된다.

## 5.2 블록 데이터

각 블록은 데이터로 정의한다.

주요 속성:

- 고유 ID
- 표시 이름
- 사용자 정의 type
- 모양
- 색상
- 회전·반전 허용 여부
- 자체 효과
- 설명
- 태그

블록은 실행 코드를 직접 보유하지 않으며, 전투 효과는 공통 Effect 구조를 통해 해석한다.

## 5.3 드로우와 순환

전투 기본 규칙:

- 전투 시작 시 블록 주머니의 순서를 섞는다.
- 일반 턴 시작 시 블록 5개를 드로우한다.
- 기본적으로 한 턴에 최대 3개의 블록을 거푸집에 배치한다.
- 추가 배치 효과가 있으면 배치 가능 수가 증가할 수 있다.
- 사용하거나 사용하지 않은 블록은 턴 종료 후 버림 더미로 이동한다.
- 다음 드로우에 필요한 블록이 부족하면 남은 주머니를 먼저 사용한 뒤 버림 더미를 섞어 다시 주머니로 만든다.

## 5.4 블록 조작

- 마우스로 블록을 드래그한다.
- 드래그 중 `R` 키로 90도 회전한다.
- 거푸집 바깥 또는 다른 블록과 겹치는 위치에는 배치할 수 없다.
- 배치 가능한 위치는 Ghost 또는 유효 배치 표시로 미리 보여준다.
- 턴 종료 전까지 배치한 블록을 회수하고 다시 배치할 수 있다.

# 6. 청사진과 조합

## 6.1 청사진

청사진은 특정 블록 배치가 어떤 **조합식**을 만들고 어떤 효과를 발생시키는지 보여주는 정보 시스템이다.

청사진에는 다음 정보를 표시할 수 있다.

- 조합 이름
- 필요한 블록과 배치 형태
- 조합 효과
- 조건부 효과

## 6.2 기본 공개 청사진

다음 조건을 모두 만족하는 청사진은 처음부터 공개한다.

- 구성 블록이 모두 일반 블록이다.
- 조합 크기가 3×3 이하이다.

## 6.3 미발견 청사진

다음 중 하나에 해당하면 미발견 청사진으로 취급한다.

- 특수 성격의 블록이 포함된 조합
- 4×4 이상의 대형 조합

미발견 상태에서도 다음은 확인할 수 있다.

- 조합 이름
- 배치 형태

하지만 다음 정보는 `???`로 숨긴다.

- 조합 Effect
- 상세 효과 설명

## 6.4 발견 조건

청사진은 단순히 배치를 확인했다고 발견되지 않는다.

**실제 전투에서 해당 조합의 효과가 한 번 실제로 실행되었을 때** 발견된다.

다음은 발견 조건이 아니다.

- Ghost Preview
- 배치 가능 Preview
- 단순 조합 인식
- 효과 실행 전의 조합 완성
- 청사진 UI 열람

동일한 조합의 회전 형태는 같은 청사진으로 취급한다.

## 6.5 조합과 색상 시너지

- 조합식은 블록의 실제 위치·모양·조건을 기준으로 판정한다.
- 조합 효과와 색상 시너지는 서로 다른 규칙이다.
- 조합식 판정 후 거푸집 전체의 `fire`, `water`, `nature` 속성 구성을 이용해 색상 시너지를 계산한다.
- 정확한 계산 공식과 처리 순서는 `BLOCKABLE_COMBAT_SYSTEM.md`를 따른다.

# 7. 전투

전투 계산의 상세 기준은 `BLOCKABLE_COMBAT_SYSTEM.md`를 따른다.

## 7.1 전투의 기본 흐름

```text
턴 시작
→ 몬스터 이번 턴 행동 확정 및 공개
→ 블록 드로우
→ 블록 회전 / 배치 / 회수
→ 조합·색상 시너지 확인
→ 필요 시 공격 대상 선택
→ 턴 종료
→ 플레이어 효과 실행
→ 생존 몬스터 행동
→ 상태 효과 처리
→ 다음 턴
```

## 7.2 플레이어의 판단 정보

전투는 몬스터의 행동을 숨긴 채 추측하는 방식보다, **행동 예고를 보고 퍼즐 배치를 결정하는 방식**을 핵심으로 한다.

플레이어는 몬스터별로 최소 다음 정보를 확인할 수 있다.

- 이번 턴 기술명
- 예상 피해
- 대상 또는 공격 범위
- 상태 이상·버프·디버프 등 부가 효과

화면에 예고한 Ability와 실제 몬스터 행동에서 실행되는 Ability는 동일해야 한다.

## 7.3 적 슬롯

- 일반 전투 계열의 적은 1~4번 고정 슬롯을 사용한다.
- 사망한 몬스터의 빈 슬롯을 다른 몬스터가 자동으로 당겨 채우지 않는다.
- 단일·좌·우·좌우·전체 범위는 고정 슬롯과 연결 관계를 기준으로 판정한다.
- 보스는 별도의 5번 보스 슬롯을 사용한다.
- 보스전에서는 부하 몬스터를 기본 구성으로 생성하지 않는다.

## 7.4 몬스터 등급

정식 게임 기획의 몬스터 등급은 다음 세 종류다.

| grade | 의미 |
|---|---|
| `normal` | 일반 몬스터 |
| `elite` | 엘리트 몬스터 |
| `boss` | 보스 몬스터 |

등장 가능한 던전과 층, 실제 Encounter 편성은 몬스터 데이터와 Encounter 규칙에서 결정한다.

## 7.5 상태 효과

현재 전투 시스템은 다음 범주의 효과를 지원한다.

- 지속 피해: 화상, 출혈, 중독
- 버프: 분노, 철갑
- 디버프: 약화, 상처, 오한
- 군중 제어: 기절
- 추가 효과: 드로우, 추가 타격, 범위 변경, 추가 턴, 추가 배치

정확한 효과 수명, 피해 공식과 적용 순서는 `BLOCKABLE_COMBAT_SYSTEM.md`를 따른다.

## 7.6 승리와 패배

- 일반 전투는 모든 적과 남은 연쇄 효과 처리가 끝난 뒤 플레이어가 살아 있으면 승리한다.
- 보스전은 보스 사망이 확정되면 승리 처리한다.
- 플레이어 HP가 0 이하가 되면 패배한다.

# 8. 전투 보상

## 8.1 일반 전투 보상

일반 전투 승리 후:

- Gold를 획득한다.
- 무작위 블록 후보 3개 중 최대 1개를 선택해 덱에 추가할 수 있다.
- 필요하지 않으면 블록 선택을 건너뛸 수 있다.

## 8.2 보스 전투 보상

- 일반 던전의 최종 보스 처치: 해당 던전을 완료하고 전체 지도로 복귀한다.
- 중앙 최종 던전의 최종 보스 처치: 게임 전체 승리로 진행한다.

# 9. 휴식

휴식은 단순 HP 회복 방이 아니라 **런 중 덱과 상태를 정비하는 선택 노드**다.

현재 휴식에서 선택 가능한 행동:

- 속성 주입
- 체력 회복
- 모양 변환
- 지금은 사용하지 않는다

## 9.1 체력 회복

- 현재 기준 회복량은 +20이다.
- 현재 HP는 최대 HP를 넘지 않는다.
- 회복을 최종 선택하기 전에 변경될 HP를 미리 확인할 수 있다.

## 9.2 완료

- 한 번의 휴식 노드에서 선택한 서비스를 처리하면 해당 노드는 완료된다.
- 완료된 휴식 노드의 효과는 다시 사용할 수 없다.

속성 주입과 모양 변환의 구체적인 콘텐츠는 데이터로 관리하며, UI의 버튼 위치나 확인 화면 구조는 본 기획에 포함하지 않는다.

# 10. 상점

상점은 Gold를 사용해 현재 런의 블록 덱을 정비하는 노드다.

## 10.1 기본 서비스

- 블록 구매
- 블록 정리
- 상점 나가기

## 10.2 블록 구매

- 구매 서비스에 들어가면 일반 등급 블록 후보 4개를 제시한다.
- 후보는 서비스 진입 시 한 번 결정하며 화면 재렌더링이나 Hover로 다시 추첨하지 않는다.
- 한 블록을 구매하면 현재 런의 덱에 영구 추가한다.

## 10.3 블록 정리

- 플레이어가 보유한 블록 하나를 선택한다.
- 선택한 블록을 현재 런의 덱에서 영구 제거한다.
- 전투 중 버림 더미와는 다른 개념이다.

## 10.4 이용 횟수

- 한 상점 노드에서 구매와 정리를 합산하여 최대 3회의 서비스 선택을 사용할 수 있다.
- 실제 거래 성공 여부가 아니라 **서비스에 들어간 시점**에 이용 횟수를 소비한다.
- 서비스에 들어갔다가 취소해도 사용 횟수는 되돌아오지 않는다.
- 모든 이용 횟수를 사용할 필요는 없으며 언제든 상점을 나갈 수 있다.

## 10.5 현재 프로토타입 가격

| 서비스 | 1회차 | 2회차 | 3회차 |
|---|---:|---:|---:|
| 블록 구매 | 50 | 75 | 100 |
| 블록 정리 | 50 | 100 | 150 |

- 구매와 정리의 가격 진행은 서로 독립적으로 계산한다.
- 위 수치는 현재 프로토타입 밸런스 값이며 플레이 테스트에 따라 조정할 수 있다.

## 10.6 재방문

같은 상점 노드를 다시 방문해도 기존 상태를 유지한다.

- 사용한 서비스 횟수 유지
- 구매·정리 결과 유지
- 이미 생성한 구매 후보 유지
- 재방문만으로 상품을 다시 추첨하지 않음

# 11. 이벤트

이벤트는 전투 외의 선택과 보상을 제공한다.

현재 게임의 주요 이벤트 범주는 다음과 같다.

- 무작위 보상 또는 상자
- 블록 관련 이벤트
- HP 관련 이벤트
- 상점
- 휴식

## 11.1 생명의 샘

현재 기준:

- 최대 HP +25
- 현재 HP +25

최대 HP가 증가한 만큼 현재 HP도 함께 증가한다.

## 11.2 이벤트 처리 원칙

- 이벤트 결과는 한 번만 적용한다.
- 완료한 이벤트를 다시 방문해 같은 결과를 다시 획득할 수 없다.
- 플레이어가 결과를 확정한 후 지도 진행으로 복귀한다.
- 이벤트의 상세 선택지와 수치는 이벤트 데이터에서 관리한다.

# 12. 튜토리얼

튜토리얼은 설명 슬라이드를 순서대로 넘기는 방식이 아니라, **실제 게임 UI를 직접 조작하면서 배우는 단계형 튜토리얼**이다.

## 12.1 진행 원칙

- 한 번에 하나의 학습 단계만 안내한다.
- 현재 조작해야 하는 실제 UI 영역을 강조한다.
- 플레이어가 실제 게임 행동을 완료하면 다음 단계로 진행한다.
- 별도의 가짜 전투 UI를 만들지 않고 실제 전투 시스템을 사용한다.

## 12.2 학습 순서

1. 모루의 대기 블록 드래그
2. `R` 키로 블록 회전
3. 거푸집의 유효한 위치에 배치
4. 청사진을 이용한 조합 배치
5. 공격 대상 몬스터 선택
6. 남은 블록과 버림 더미 확인
7. 턴 종료
8. 플레이어 피해와 거푸집 변화 확인
9. 자유 전투

튜토리얼의 목적은 블록 조작법뿐 아니라 **몬스터 행동 예고를 보고 배치를 판단하는 Blockable의 전투 사고방식**을 익히게 하는 것이다.

# 13. 저장 및 이어하기

## 13.1 저장 대상

현재 런을 이어가기 위해 최소 다음 정보를 저장한다.

- 완료한 던전과 개방된 던전
- 현재 던전과 층
- 현재 노드
- 생성된 지도 구조
- 방문·공개·완료 노드 상태
- 현재 HP / 최대 HP
- Gold
- 현재 덱
- 현재 Encounter 참조
- 전투 시작 시점 복원에 필요한 상태

상세 지도 저장 구조는 `BLOCKABLE_MAP_SYSTEM.md`를 따른다.

## 13.2 전투 중 종료

전투 중 게임을 종료한 경우 **정확한 중간 턴 상태를 저장하지 않는다.**

Continue 시 해당 전투의 **시작 상태**에서 다시 시작한다.

다만 재시작을 이용한 Encounter 리롤은 허용하지 않는다. 따라서 다음은 동일하게 복원되어야 한다.

- 같은 던전
- 같은 층
- 같은 노드
- 같은 Encounter
- 같은 몬스터 구성
- 같은 전투 시작 덱
- 같은 전투 시작 Random 결과 및 블록 순서

`Save → Main → Continue`를 반복해도 동일한 전투 시작 상태가 재현되어야 한다.

## 13.3 Main 이동과 사망 구분

- **Quit to Main**: 현재 런을 저장하고 메인으로 이동한다. 런은 유지된다.
- **Player Death**: GameOver로 진행하고 현재 런은 종료된다.

두 결과를 동일한 상태로 처리하지 않는다.

# 17. 프로토타입 임시 구현과 정식 기획의 구분

해커톤 마감 과정에서는 테스트와 완성을 위해 일부 스폰·밸런스·층 구성 규칙을 임시로 구현할 수 있다.

다만 다음 원칙을 따른다.

- 임시 구현 자체를 정식 기획으로 자동 승격하지 않는다.
- 현재 일반 전투에서 사용하는 `horde` 등급과 2~3마리 편성은 프로토타입용 임시 Spawn 규칙이다. `horde`는 정식 몬스터 Grade 표에 포함하지 않으며, 정식 Encounter 설계가 확정될 때 재검토한다.
- 정식 기획으로 확정된 규칙만 이 문서에 기록한다.
- 버그 수정 이력, 특정 코드 조건문, CSS 위치 조정과 일회성 하드코딩은 문서에서 제외한다.
- 향후 정리 시 이 문서와 상세 시스템 문서를 기준으로 임시 구현을 재검토한다.
