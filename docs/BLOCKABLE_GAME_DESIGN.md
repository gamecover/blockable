# Blockable 게임 기획안 v0.5.4

프로젝트 목적
- NHN 2026 해커톤 참여를 목적으로 제작하는 웹 기반 게임 프로토타입이다.
- 공식 페이지: https://nan2026.nhn.com/

작성 기준
- 현재까지 논의된 세계관, 지도, 전투, 블록, 보상, 이벤트 및 UI 구성을 통합한 기획 초안이다.
- v0.5 본문, 2026-07-25 회의 내용, 블록·조합 규칙 편집기 기획안 v0.3 및 이후 대화에서 확정한 기준을 우선 적용한다.
- v0.5.1에서는 다수 몬스터 전투, 일반 적 4개 고정 슬롯, 보스 전용 5번 슬롯, 연결 기반 범위 공격, 진영 판정, 사망·연쇄 효과, 전체 지도와 복수 던전, 방·통로형 층 지도, 완료 방 자유 왕복 및 막다른 위험 가지를 추가한다.
- v0.5.2에서는 기본 공격과 A 독립 공격을 분리하고, `P`를 현재 버프로부터 계산된 데미지 추가 값으로 정의하며, 상처 계수를 `W`로 통일한다. 또한 대상 사망·무효화 시 남은 연타와 해당 공격 기회를 다른 적에게 재지정하지 않는 규칙을 확정한다.
- v0.5.3에서는 당시 조합 참여·미참여 블록의 피해 처리, `BASE_HIT_COUNT`의 B·H 해석, 색상 분류와 단색·뒤섞인·세 속성 시너지, 방어도 유지·배율, 플레이어·몬스터 출혈 구분, 새 약화·상처의 보호 규칙 및 전투별 몬스터 수를 확정했다. 전투 효과 포맷과 처리 순서는 아래 v0.5.4 규칙이 이를 대체한다.
- v0.5.4에서는 공통 전투 효과를 `BASE_DAMAGE`, `INDEPENDENT_DAMAGE`, `BLOCK`, `RECOVERY`, `DAMAGE_OVER_TIME`, `BUFF`, `DEBUFF`, `CROWD_CONTROL`, `EXTRA`로 정리한다. 상태 스택과 추가 수치는 `value`로 읽고, `parameters.id`로 세부 효과를 구분한다. 다음 턴형 버프, 중독·오한·철갑, 완전히 새로운 플레이어 턴인 추가 턴 규칙을 확정하며 상세 기준은 `BLOCKABLE_COMBAT_SYSTEM.md` V0.5.4를 따른다.
- 편의상 사용한 '레고'라는 표현은 실제 게임 제작 시 '블록'으로 통일한다.
- 최근 대화에서 직접 확정한 UI 구성은 본문에 반영한다.
- 확정하지 않은 수치와 규칙은 본문에서 명시적으로 '임시값', '후보' 또는 '추후 결정'으로 구분한다.
- 지도는 프로토타입 검증을 위해 템플릿 기반 제약형 무작위 생성 방식을 우선 적용한다. 난이도별 던전·층·방 수와 세부 확률은 아직 확정되지 않았다.
- 비용, 확률, 피해량 등 본문에 남아 있는 숫자는 별도 표기가 없는 한 프로토타입 검증용 임시값이다.

3. 주요 게임 구조

3.1. 전투 시스템

3.1.1. 전투의 기본 구조
- 전투는 블록 배치 퍼즐과 턴제 전투를 결합한다.
- 플레이어는 주머니에서 블록을 뽑아 퍼즐 판에 배치하고, 블록 자체 효과·조합 효과·조건부 효과·색상 시너지를 발생시킨다.
- 일반 전투에는 1~2마리, 강력 전투에는 2~3마리의 몬스터가 1~4번 고정 슬롯에 등장한다.
- 보스전에는 5번 보스 전용 슬롯의 보스 1마리만 등장하며 1~4번 슬롯에 부하를 함께 생성하지 않는다.
- 블록과 조합의 구체적인 효과는 Blockable Block Designer가 만든 JSON을 기준으로 한다.
- 몬스터의 능력치, 행동 패턴, 자폭 및 사망 효과는 Blockable Monster Designer가 만든 JSON을 기준으로 한다.
- Block Designer와 Monster Designer의 전투 효과는 `effect_id`, `effect_name`, `description`, `target`, `value`, `type`, `parameters`의 공통 구조로 출력한다.
- 상세한 블록 드로우, 퍼즐 판, 피해 공식, 상태 이상 및 UI 규칙은 5장을 함께 적용한다.

3.1.2. 적 고정 슬롯
- 적 진영에는 1~4번의 고정 슬롯을 둔다.
- 전투에 등장하는 몬스터는 각 슬롯을 하나씩 점유한다.
- 슬롯은 비어 있음, 살아 있는 몬스터 점유, 사망 처리 중 상태를 가질 수 있다.
- 몬스터가 사망해도 다른 몬스터가 빈자리로 당겨지지 않는다.
- 범위 효과는 현재 살아 있는 몬스터의 나열 순서가 아니라 고정 슬롯 번호와 슬롯 거리를 기준으로 판정한다.
- 빈 슬롯을 건너뛰어 범위 밖의 몬스터를 추가 대상으로 찾지 않는다.
- 전투 영역을 벗어나는 좌우 범위는 무시한다.
- 해커톤 버전에서는 몬스터 이동, 위치 교환, 밀치기, 당기기, 앞열·뒷열 판정을 구현하지 않는다.
- 향후 몬스터 이동을 추가할 경우 몬스터가 점유한 슬롯 번호를 바꾸는 방식으로 확장한다.
- 이 절의 1~4번 선형 거리 판정은 일반 전투의 기본 규칙이며, 보스전에서는 3.1.3의 추가 연결 규칙을 함께 적용한다.

표시 예시

플레이어                        적 진영
                              [1] [2] [3] [4]

전투 시작: [A] [B] [C] [D]
B 사망:    [A] [ ] [C] [D]

3.1.3. 보스 전용 5번 슬롯
- 보스전에서는 5번 보스 전용 슬롯만 점유하며 1~4번 슬롯은 비워 둔다.
- 5번 슬롯에는 보스만 배치하며, 일반 몬스터는 1~4번 슬롯을 점유한다.
- 1~4번 슬롯의 기존 좌우 연결은 유지한다.
- 5번 슬롯은 1번, 2번, 3번, 4번 슬롯 모두와 직접 연결된다.
- 보스전에는 부하 몬스터를 생성하지 않는다.
- 보스전의 범위 판정은 단순한 슬롯 번호 증감이 아니라 슬롯 연결 관계를 기준으로 한다.

보스전 연결 관계

1번: 2번, 5번과 연결
2번: 1번, 3번, 5번과 연결
3번: 2번, 4번, 5번과 연결
4번: 3번, 5번과 연결
5번: 1번, 2번, 3번, 4번과 연결

표시 예시

[1] — [2] — [3] — [4]
 ╲      │      │      ╱
          [5: 보스]

- 좌 1, 우 1 또는 좌우 1의 범위에는 중심 대상과 해당 방향의 일반 슬롯뿐 아니라 중심 슬롯에 직접 연결된 5번 보스 슬롯도 포함된다.
- 5번 보스 슬롯을 중심으로 좌 1 또는 우 1 공격을 사용하면, 5번과 직접 연결된 1~4번 슬롯 전체가 범위에 포함된다.
- 범위 안의 빈 슬롯에는 효과가 발생하지 않으며, 빈 슬롯을 이유로 다른 슬롯을 추가하지 않는다.
- 직접 선택한 대상과 연결 범위에 포함된 대상에는 동일한 피해량과 효과를 적용한다.
- 5번 보스 슬롯이 연결 범위로 피격되더라도 피해를 감소시키지 않는다.
- 보스전의 기본 밸런스는 우선 보스의 최대 체력과 기본 능력치 상승으로 조절한다.
- 부하 생존 중 보스 피해 감소 같은 부하 연계 기믹은 현재 보스전 구성에 사용하지 않는다.

범위 판정 예시

중심 2번 + 좌 1: 1번, 2번, 5번
중심 2번 + 우 1: 2번, 3번, 5번
중심 2번 + 좌우 1: 1번, 2번, 3번, 5번
중심 1번 + 좌 1: 1번, 5번
중심 1번 + 우 1: 1번, 2번, 5번
중심 5번 + 좌 1: 1번, 2번, 3번, 4번, 5번
중심 5번 + 우 1: 1번, 2번, 3번, 4번, 5번

3.1.4. 플레이어 공격 타겟팅

단일 공격
- 살아 있는 몬스터 한 마리를 직접 선택한다.
- 빈 슬롯과 사망 처리 중인 슬롯은 선택할 수 없다.
- 선택한 몬스터에게만 효과를 적용한다.

중심 지정 범위 공격
- 살아 있는 몬스터 하나를 중심 대상으로 선택한 뒤 그 슬롯을 기준으로 좌우 범위를 계산한다.
- 좌, 우, 좌우 범위는 기본적으로 직접 선택한 중심 대상도 포함한다.
- 일반 전투에서 왼쪽 N칸, 오른쪽 N칸은 각각 1~4번 선형 슬롯의 고정 거리를 의미한다.
- 보스전에서는 3.1.3의 연결 관계를 범위에 추가한다.

범위 종류
- 단일: 선택한 중심 대상만 적용
- 좌: 중심 대상과 왼쪽 N슬롯 적용
- 우: 중심 대상과 오른쪽 N슬롯 적용
- 좌우: 중심 대상과 좌우 각각 N슬롯 적용
- 전체: 별도의 중심 대상 선택 없이 모든 살아 있는 적에게 적용

예시: 3번 슬롯을 중심으로 왼쪽 2칸 공격

[1] [2] [3] [4]
 X   X   ◎

- ◎는 직접 선택한 중심 대상이다.
- X는 범위에 포함된 슬롯이다.
- 범위 안에 빈 슬롯이 있으면 그 슬롯에는 아무 효과도 발생하지 않는다.
- 빈 슬롯 뒤에 있더라도 정해진 슬롯 범위 안에 있는 몬스터는 대상이 된다.
- 범위를 벗어난 몬스터는 빈 슬롯 수와 관계없이 대상이 되지 않는다.

3.1.5. 대상 선택 화면
- 중심 대상 선택이 필요한 효과를 발동하면 전투 화면을 대상 선택 상태로 전환한다.
- 중심 대상은 조준선, 굵은 테두리 또는 중심 표식으로 강조한다.
- 범위에 포함될 대상은 바닥 범위, 옅은 테두리 또는 효과 아이콘으로 함께 강조한다.
- 범위 밖 대상은 어둡게 표시할 수 있다.
- 빈 슬롯과 선택 불가능한 대상은 선택 불가 상태를 표시한다.
- 각 대상 위에는 예상 피해 또는 적용될 상태 효과를 표시할 수 있다.
- 클릭하면 대상을 확정하고, 취소 입력은 대상 선택을 해제한다.
- 색상만으로 중심·범위·비대상을 구분하지 않고 테두리, 아이콘과 바닥 표시를 함께 사용한다.

3.1.6. 유효한 중심 대상을 찾을 수 없는 경우
- 중심 대상이 필요한 효과인데 살아 있는 적이 없으면 해당 효과를 취소한다.
- 대상 선택 후 실제 효과 실행 전에 중심 대상이 사망했다면 효과를 취소한다.
- 다른 적을 자동으로 다시 선택하지 않는다.
- 자동 재지정으로 플레이어가 의도하지 않은 대상에게 효과가 적용되는 것을 방지한다.
- 기본 공격의 연타 도중 중심 대상이 사망하거나 무효화되면 남은 연타와 그 공격 기회를 즉시 종료한다.
- 이 규칙은 추가 턴에 실행하는 공격 기회에도 동일하게 적용하며, 사망한 대상을 다른 적으로 자동 변경하지 않는다.
- 최초 중심 대상이 무효가 되어 공격 기회가 종료되면, 그 공격 기회에 포함된 후속 효과가 범위 효과이더라도 실행하지 않는다.
- `A`는 기본 공격의 후속 타격이 아니라 모든 기본 공격 처리가 끝난 뒤 실행하는 독립 공격이므로, 기본 공격 대상의 사망 여부와 별개로 `A` 자체의 대상과 범위를 다시 판정한다.
- 단, `A` 자체가 지정한 대상이 사망하거나 무효화된 경우에는 `A` 역시 다른 적에게 재지정하지 않고 종료한다.
- 중심 대상 없이 발동하는 전체 효과는 실행 시점에 살아 있는 유효 대상을 다시 판정한다.

3.1.7. 몬스터 효과와 대상 진영
- 몬스터 효과는 플레이어만 대상으로 제한하지 않는다.
- 효과에 따라 시전자 자신, 특정 아군 몬스터, 모든 아군 몬스터, 플레이어, 지정 슬롯 범위 또는 모든 전투 참가자에게 적용할 수 있다.
- 기획상 구분해야 할 대상은 다음과 같다.
  - 플레이어
  - 시전자 자신
  - 특정 아군 몬스터
  - 모든 아군 몬스터
  - 지정된 적 슬롯 범위
  - 플레이어와 모든 몬스터
  - 시전자를 제외한 모든 전투 참가자
- 다른 몬스터에게도 피해를 주는 행동은 행동 예고에 대상 진영을 명시한다.
- 아이콘만으로 대상을 표현하지 않고 마우스 오버 또는 상세 패널에서 대상 설명을 제공한다.

행동 예고 예시

폭발 8
대상: 플레이어 + 다른 모든 몬스터

3.1.8. 자폭과 사망 효과
- 자폭 행동, 사망 시 폭발, 피격 반응 폭발은 서로 다른 발동 조건으로 구분한다.

자폭 행동
- 몬스터가 자신의 행동 순서에 폭발 효과를 실행하고 스스로 사망한다.

사망 폭발
- 다른 공격 또는 효과로 사망했을 때 사망 사건을 조건으로 폭발한다.

피격 반응 폭발
- 공격을 받았을 때 정해진 조건을 만족하면 폭발한다.

슬라임 사망 폭발 예시
- 발동 조건: 슬라임 사망
- 대상: 죽은 슬라임 자신을 제외한 모든 전투 참가자
- 결과: 플레이어와 살아 있는 다른 몬스터에게 폭발 피해

3.1.9. 연쇄 효과 처리
- 사망 폭발로 다른 몬스터가 죽는 연쇄 효과를 허용한다.
- 연쇄 효과는 함수의 즉시 중첩 호출이 아니라 순차 대기열로 처리한다.

처리 흐름
1) 현재 공격 또는 효과를 끝까지 처리한다.
2) 새로 사망한 몬스터를 확인한다.
3) 발동할 사망 효과를 대기열에 등록한다.
4) 대기열의 첫 효과를 처리한다.
5) 새로 사망한 몬스터와 후속 효과를 확인한다.
6) 대기열이 빌 때까지 반복한다.

- 같은 몬스터의 같은 사망 효과는 한 번만 발동한다.
- 한 효과로 여러 몬스터가 동시에 사망하면 1번 슬롯부터 4번 슬롯 순서로 등록하고, 보스전에서 5번 슬롯의 보스도 동시에 사망했다면 마지막에 등록한다.
- 고정된 등록 순서를 사용해 같은 입력과 전투 상태에서 항상 같은 결과가 나오도록 한다.

연쇄 예시

슬라임 A 사망
→ A의 사망 폭발
→ 슬라임 B 사망
→ B의 사망 폭발
→ 추가 피해 처리

3.1.10. 다수 몬스터 행동 순서와 예고
- 해커톤 프로토타입에서는 속도 능력치를 추가하지 않고 1번 슬롯부터 4번 슬롯 순서로 살아 있는 몬스터가 행동하고, 보스전에서는 5번 보스가 마지막에 행동하는 방식을 우선 적용한다.
- 모든 살아 있는 몬스터의 다음 행동을 플레이어 블록 배치 전에 결정하고 화면에 공개한다.
- 행동 예고에는 행동 종류, 예상 피해 또는 효과, 대상 진영과 특수 조건을 표시한다.
- 몬스터 행동 실행 시점에 해당 몬스터가 사망했다면 그 행동을 건너뛴다.
- 앞선 몬스터 행동으로 뒤 슬롯 몬스터가 사망했다면 사망·연쇄 대기열을 먼저 처리한 뒤 다음 살아 있는 슬롯으로 진행한다.
- 행동 순서, 행동 예고 공개 범위 및 향후 속도 능력치 도입 여부는 플레이 테스트 후 변경할 수 있다.

3.1.11. 전투 종료 판정
- 일반 전투와 강력 전투에서는 마지막 몬스터가 사망해도 대기 중인 사망·연쇄 효과가 남아 있으면 즉시 승리 처리하지 않는다.
- 현재 효과와 사망·연쇄 효과 대기열을 전부 처리한 후 플레이어와 몬스터 생존 여부를 확인한다.
- 모든 적이 사망하고 플레이어가 살아 있으면 승리한다.
- 마지막 적의 사망 효과로 플레이어 체력이 0 이하가 되면 패배한다.
- 플레이어와 마지막 적이 같은 연쇄 처리에서 모두 사망한 경우 플레이어 생존 조건을 만족하지 못하므로 패배로 처리한다.
- 보스전은 5번 보스 사망 즉시 승리하며 아직 실행하지 않은 행동, 상태 처리와 연쇄 효과를 취소한다.

종료 흐름

마지막 적 사망
→ 남은 사망·연쇄 효과 전부 처리
→ 플레이어 생존 확인
→ 승리 또는 패배 확정

3.1.12. Designer와 메인 게임의 역할
- Blockable Block Designer는 블록·조합 블록의 효과, 수치와 범위 설명을 JSON으로 출력한다.
- Blockable Monster Designer는 몬스터 능력치, 행동, 패턴, 자폭과 사망 효과를 JSON으로 출력한다.
- 각 Designer의 Codex 지침서는 JSON의 구조와 해석 시 주의점을 메인 Blockable Codex에 전달한다.
- 모든 전투 효과는 `effect_id`, `effect_name`, `description`, `target`, `value`, `type`, `parameters`의 공통 구조로 관리한다.
- `effect_id`와 `effect_name`은 효과의 고유 식별자와 표시 이름이다.
- `target`은 자신, 왼쪽, 오른쪽, 선택 대상, 전체 등 효과가 적용될 대상을 지정한다.
- `value`는 피해량, 방어도, 회복량, 상태이상 스택 또는 규칙·자원의 증감 수치다.
- `type`은 기본 공격, A 독립 공격, 방어, 회복, 지속 피해, 버프, 디버프, 군중 제어 또는 추가 효과라는 상위 처리 방식을 결정한다.
- `parameters.id`는 화상·중독·출혈, 분노·철갑, 약화·오한·상처, 기절, 추가 드로우·타격·범위·턴·배치 같은 세부 효과를 결정한다.
- 0.5.4에서 상태 스택과 추가 수치는 `value`로 읽으며 `parameters.duration`과 `parameters.intensify`는 확장 호환을 위해 보존하되 계산에는 사용하지 않는다.
- 특정 블록을 덱에 추가하는 효과처럼 숫자만으로 대상을 표현할 수 없으면 선택 필드 `reference_id`로 해당 블록을 참조한다.
- 메인 Blockable Codex는 공통 필드를 우선 해석하고, 설명은 표시와 검토 보조 정보로 사용한다.
- 이미 지원이 확정된 Type과 `parameters.id`만 기존 범용 전투 로직에 연결한다.
- 새로운 사용자 정의 Type 또는 `parameters.id`가 발견되면 임의 추론하거나 자동 연결하지 않고 즉시 사용자에게 알린 뒤 지원 규칙을 확정한다.
- 메인 게임은 실제 슬롯 판정, 대상 선택, 피해·상태 처리, UI 표시와 연쇄 대기열을 실행한다.
- 개별 블록이나 몬스터 이름을 기준으로 효과를 하드코딩하지 않는다.
- 신규 효과 유형은 공통 구조를 유지한 채 `type` 열거형과 필요한 선택 필드를 확장한다.

현재 단계의 원칙

Designer는 공통 효과 구조로 콘텐츠가 어떤 효과를 내는지 전달하고,
메인 Blockable Codex는 `type`과 `target`을 기준으로 이미 확정된 범용 로직만 실행하며,
새로운 효과는 사용자 확인 없이 임의 구현하지 않는다.

3.1.13. 효과 해석 결과 확인
- 메인 Blockable Codex가 Designer JSON을 가져올 때 사용자가 검토할 수 있는 효과 해석 보고서를 남긴다.
- 보고서에는 다음 내용을 포함한다.
  1) 새로 읽은 블록과 몬스터 목록
  2) 확정된 기존 로직과 연결한 효과
  3) 새로 발견되어 사용자 확인이 필요한 Type과 `parameters.id`
  4) 필드 누락 또는 의미 불명확으로 실행하지 않은 효과
  5) 지원하지 못한 효과
  6) 실제 전투에서 예상되는 대상과 처리 순서

해석 보고 예시

[조합 블록: 화염 파동]

해석
- 살아 있는 적 1명을 중심 대상으로 선택
- 중심과 좌우 1슬롯에 화염 피해 적용

연결 결과
- 기존 슬롯 범위 피해 로직 사용
- 중심 대상 선택 UI 사용

주의
- 빈 슬롯에는 효과가 발생하지 않음
- 범위는 빈 슬롯을 건너뛰어 늘어나지 않음

3.1.14. 해커톤 우선 구현 범위
- 적 4개 고정 슬롯
- 보스 전용 5번 슬롯과 1~5번 연결 기반 범위 판정
- 단일·좌·우·좌우·전체 공격
- 플레이어 대상 몬스터 공격
- 몬스터 진영 및 모든 전투 참가자 대상 효과

- 연쇄 사망 효과 대기열

- 모든 몬스터의 행동 예고
- Designer 효과 해석 결과 보고

후속 확장
- 적 슬롯 이동
- 위치 교환
- 밀치기와 당기기
- 앞열·뒷열 판정

- 공통 effect 레지스트리와 완전한 공통 스키마


3.2. 지도 시스템 구조

3.2.1. 전체 게임 진행 구조

해커톤 버전
- 전체 지도에는 일반 던전 2개와 중앙 최종 던전 1개를 배치한다.
- 두 일반 던전은 원하는 순서로 공략할 수 있다.
- 일반 던전 2개를 모두 완료하면 중앙 최종 던전이 개방된다.
- 먼저 완료한 던전의 보상과 고유 블록은 다음 던전 전투에 영향을 줄 수 있다.
- 중앙 최종 던전의 최종 보스를 처치하면 게임을 클리어한다.

진행 흐름

게임 시작
→ 전체 지도
→ 일반 던전 A 또는 B 선택
→ 던전 내부 탐험 및 보스 처치
→ 전체 지도 복귀
→ 남은 일반 던전 완료
→ 중앙 최종 던전 개방
→ 최종 보스 처치
→ 게임 클리어

장기 확장 구조
- 일반 던전 8개 중 3개를 완료하면 중앙 최종 던전이 개방되는 구조를 후보로 둔다.
- 일반 던전 수와 최종 던전 개방 요구 수는 코드에 고정하지 않고 설정 데이터로 관리한다.

설정 예시

해커톤
- normalDungeonCount: 2
- requiredClearCount: 2

장기 확장
- normalDungeonCount: 8
- requiredClearCount: 3

3.2.2. 지도 용어

던전(Dungeon)
- 플레이어가 공략하는 전체 지역이다.
- 하나의 던전은 여러 개의 층으로 구성될 수 있다.
- 예: 잿빛 용광로

층(Floor)
- 던전을 구성하는 세로 단계(Vertical Level)다.
- 플레이어가 한 층의 계단을 이용하거나 보스 방을 완료하면 다음 층으로 이동한다.

방(Room) 또는 노드(Node)
- 전투, 이벤트, 휴식, 보상 또는 이동이 발생하는 실제 개별 공간이다.
- 각 방은 하나의 고유 ID를 가진다.
- 방 ID는 내부 진행·저장·개발자 기능에서 사용하며 일반 상단 HUD에는 표시하지 않는다.

통로(Corridor)
- 플레이어가 이동할 수 있도록 두 방을 연결하는 경로다.
- 통로 연결 관계는 층 지도 생성 시 확정하고 저장한다.

계단 방(Stair Room)
- 현재 층을 끝내고 다음 층으로 이동하는 특수 방이다.
- 계단을 이용하면 이전 층으로 돌아갈 수 없다.

보스 방(Boss Room)
- 층 또는 던전 완료를 위한 보스 전투가 발생하는 방이다.

가지(Branch)
- 주 경로에서 갈라지는 선택 경로다.
- 일부 가지는 막다른 길이며, 끝에 강한 적과 높은 가치의 보상을 배치할 수 있다.

지도 계층
전체 지도
└─ 여러 던전
   └─ 여러 층
      └─ 통로로 연결된 여러 방

3.2.3. 기본 지도 구조
- 층 지도는 방과 통로가 연결된 공간형 구조다.
- 던전에 입장하면 템플릿 기반 제약형 무작위 방식으로 층 지도를 생성한다.
- 각 층에는 시작 방과 계단 방 또는 보스 방이 존재한다.
- 주 경로는 계단이나 보스 방까지 연결된다.
- 주 경로 중간에는 분기와 합류, 우회로와 막다른 가지가 존재할 수 있다.
- 플레이어는 현재 방과 통로로 직접 연결된 방으로 이동할 수 있다.
- 완료한 방과 발견한 통로를 이용해 이전 방으로 자유롭게 돌아갈 수 있다.
- 완료한 방의 전투, 이벤트, 보상과 휴식 효과는 다시 발생하지 않는다.
- 완료된 방만 지나는 경로라면 멀리 있는 완료 방을 클릭해 자동 이동할 수 있다.
- 미완료 방을 통과해 그 너머 방으로 자동 이동할 수 없다.
- 이동 자체에는 체력, 시간 또는 별도 자원을 소모하지 않는다.
- 계단이나 다음 층으로 이동한 뒤에는 이전 층으로 돌아갈 수 없다.
- 마지막 층의 보스를 처치하면 해당 던전을 클리어한다.
- 플레이어가 사망하면 현재 런을 종료한다.

3.2.4. 지도 진행 흐름
1) 던전 입장
2) 현재 층의 방·통로 지도 생성
3) 층 시작 방 진행
4) 현재 방과 연결된 다음 방 선택
5) 전투 또는 이벤트 진행
6) 보상 획득 및 덱 정비
7) 지도 화면으로 복귀
8) 완료한 방을 지나 이동하거나 미탐험 가지 선택
9) 막다른 위험 가지 또는 계단·보스 방향 선택
10) 필요하면 위험 가지 완료 후 갈림길로 복귀
11) 계단 또는 층 보스 진행
12) 다음 층 이동
13) 마지막 층 보스 처치
14) 던전 클리어
15) 전체 지도 복귀

3.2.5. 방 및 인카운터 종류

시작 방
- 해당 층의 출발 지점이며 각 층에 하나만 존재한다.
- 시작 방은 전투 방이 아니라 고유 블록을 선택하는 독립적인 방이다.
- 고유 블록을 선택한 뒤 연결된 다음 방들로 경로가 분기된다.
- 고유 블록의 구체적인 종류와 선택지 수는 추후 추가한다.

일반 전투 방
- 블록 배치 퍼즐을 이용해 몬스터와 싸운다.
- 몬스터를 처치하면 골드와 블록 보상을 획득한다.

엘리트·네임드 전투 방
- 일반 전투보다 강한 적이 등장한다.
- 더 높은 가치의 보상을 제공한다.
- 막다른 위험 가지 끝에 배치할 수 있다.

휴식 방
- 플레이어의 현재 체력을 20 회복한다.
- 현재 체력은 최대 체력을 초과할 수 없다.
- 한 층의 전체 방 중 절반이 지난 구간부터 등장할 수 있다.
- 한 번 완료하면 다시 돌아와도 휴식 효과가 재발동하지 않는다.

이벤트 방
- 블록 추가, 삭제, 색상·능력 변경, 형태 변형, 상점, 보물 상자 및 일반 선택 이벤트가 발생할 수 있다.
- 선택을 완료하거나 스킵하면 종료된다.
- 미믹이나 공허 괴물이 등장하면 전투 인카운터로 전환될 수 있다.

블록 변형 방
- 보유 블록을 미리 정의된 다른 블록으로 교체한다.
- 이용을 완료하거나 스킵하면 완료 상태가 된다.

보상·보물 방
- 골드, 블록 또는 특별 보상을 획득할 수 있다.
- 막다른 위험 가지의 강적 뒤에 특별 보상 방을 배치할 수 있다.
- 보상을 획득한 뒤에는 다시 받을 수 없다.

계단 방
- 다음 층으로 이동한다.
- 진입하면 현재 층으로 돌아올 수 없다.
- 미탐험 가지가 남아 있으면 이동 전 확인 창을 표시한다.

보스 방
- 해당 층 또는 던전의 마지막 전투 방이다.
- 주 경로는 최종적으로 보스 방 또는 보스 진입 지점에 연결된다.
- 일반 층에는 층 보스가, 마지막 층에는 던전 최종 보스가 등장한다.

3.2.6. 난이도와 지도 규모
- 던전 난이도에 따라 층 수, 층별 방 수, 분기 수와 가지 길이가 달라질 수 있다.
- 이 방향성은 프로토타입에서 검증하며 정확한 수치는 아직 확정하지 않는다.

생성 변수
- 층 수: 던전 전체 길이
- 층별 방 수: 한 층에 생성되는 전체 방 수
- 주 경로 길이: 시작 방에서 계단·보스 방까지의 최소 이동 수
- 가지 수와 길이: 선택 경로와 막다른 우회 경로의 규모
- 분기·합류 횟수: 경로 선택과 재결합의 빈도
- 방 종류 비율: 전투·이벤트·휴식·보상 등의 배치 비율
- 정보 공개 범위: 미발견, 발견, 완료 상태에 따라 공개하는 정보
- 전투 등급: 일반·네임드·보스 전투의 배치
- 위험 가지 보상 가치: 추가 이동과 강적 위험에 대응하는 보상 수준

해커톤 프로토타입 권장 규모
- 일반 던전 하나는 층 1개와 실제 방문 방 4~6개를 우선 목표로 한다.
- 전체 생성 방 수는 선택하지 않은 가지를 포함하므로 실제 방문 방 수보다 많을 수 있다.
- 층 수와 방 수는 데이터로 조정할 수 있게 만들며 확정 밸런스로 고정하지 않는다.

3.2.7. 한 층의 기본 구성
- 한 층은 '시작 방 → 갈림길 → 주 경로와 선택 가지 → 보스 전 준비 → 계단 또는 층 보스' 흐름을 기본 골격으로 사용한다.
- 주 경로는 비교적 안정적으로 계단이나 보스 방에 도달할 수 있어야 한다.
- 짧은 가지에는 이벤트, 회복 또는 소규모 보상을 배치할 수 있다.
- 긴 가지에는 추가 전투와 더 좋은 보상을 배치할 수 있다.
- 막다른 위험 가지에는 강력한 적 또는 엘리트와 훌륭한 보상을 배치할 수 있다.
- 조건부 가지는 열쇠, 특정 블록 또는 이벤트 결과로 개방하는 확장 후보로 둔다.
- 모든 층을 동일하게 만들지 않고 여러 구조 템플릿 중 하나를 선택해 변형한다.

공간 예시

                  [강적] ── [특별 보상]
                     │
[시작] ── [갈림길] ── [일반 방] ── [계단/보스]

플레이어는 막다른 가지의 강적과 보상을 완료한 뒤 갈림길로 돌아와 계단·보스 방향으로 진행할 수 있다.

3.2.8. 지도 생성 방식
- 완전 무작위 생성이 아니라 미리 정의한 층 구조에 제약된 무작위를 적용한다.

생성 순서
1) 던전 난이도를 기준으로 전체 층 수를 결정한다.
2) 각 층의 전체 방 수, 주 경로 길이, 가지 수와 최대 길이를 결정한다.
3) 시작 방과 계단·보스 방을 먼저 생성한다.
4) 시작 방에서 계단·보스 방까지 이어지는 주 경로를 생성한다.
5) 주 경로 사이에 분기와 합류를 추가한다.
6) 선택 가능한 막다른 가지를 추가한다.
7) 모든 방의 연결 상태와 이동 가능성을 검사한다.
8) 지도 연결 구조가 완성된 후 방 종류를 배정한다.
9) 위험 가지 끝에 강적과 그에 맞는 특별 보상이 배치되는지 검사한다.
10) 생성에 사용한 랜덤 시드를 저장한다.

지도 구조 템플릿 후보
- 초반에 넓게 분기한 뒤 합류하는 구조
- 초반에는 한 길이고 후반에 분기하는 구조
- 두 경로 사이에서 선택이 반복되는 구조
- 안전하지만 긴 경로와 위험하지만 짧은 경로
- 보상 방을 중심으로 우회하는 구조
- 주 경로에서 막다른 위험 가지가 갈라지는 구조

3.2.9. 지도 생성 및 이동 제약
- 시작 방에서 계단·보스 방까지 도달 가능한 주 경로가 반드시 존재해야 한다.
- 막다른 경로는 의도적인 선택 가지로만 생성하며, 위험 또는 보상 목적이 있어야 한다.
- 플레이어는 연결된 통로를 따라 방문한 방으로 돌아갈 수 있다.
- 완료한 방에 다시 들어갈 수 있지만 해당 방의 콘텐츠는 재발동하지 않는다.
- 방문하지 않은 방은 현재 방과 직접 연결된 경우에만 진입할 수 있다.
- 완료한 방들로만 연결된 경로는 자동 이동할 수 있다.
- 미완료 방을 통과해 그 너머로 이동할 수 없다.
- 분기 직후 합류하는 의미 없는 선택은 만들지 않는다.
- 하나의 방에서 연결되는 통로 수는 가독성을 위해 제한한다.
- 같은 종류의 방이 연속될 때마다 해당 종류의 다음 등장 확률을 직전 확률의 절반으로 낮춘다.
- 위험과 보상의 기준은 전체 경로가 아니라 개별 방에 적용한다.
- 위험도가 높은 방과 가지에는 그에 맞는 보상 가치가 배정되어야 한다.
- 서로 다른 경로가 완전히 같은 구성을 갖지 않도록 한다.
- 마지막 층의 보스는 일반 층 보스와 구분한다.
- 계단 또는 다음 층 진입 후에는 이전 층으로 돌아갈 수 없다.

3.2.10. 방 상태와 콘텐츠 재사용 방지
- 미발견: 아직 지도에 공개되지 않은 방
- 발견: 위치는 알지만 방문하지 않은 방
- 현재 위치: 플레이어가 있는 방
- 완료: 전투·이벤트·보상 처리가 끝난 방
- 이동 불가: 조건 미충족 또는 아직 연결이 공개되지 않은 방

완료 방 재방문 시 금지
- 전투 재발생
- 이벤트 재선택
- 보상 재획득
- 휴식 효과 재사용
- 블록 변형 재사용

3.2.11. 지도 표시 및 정보 공개 규칙
- 현재 위치는 다른 방과 명확하게 구분한다.
- 완료한 방은 종류와 결과를 완료 상태로 표시한다.
- 현재 방과 연결된 이동 가능 방을 활성화한다.
- 인접한 미방문 방은 종류 또는 실루엣을 표시할 수 있다.
- 더 먼 미발견 방은 상세 정보를 공개하지 않는다.
- 계단 방과 보스 방의 위치는 처음부터 공개할 수 있다.
- 통로는 발견한 범위까지만 표시한다.
- 방 종류는 아이콘과 색상으로 구분한다.
- 몬스터 등급은 전투 방의 아이콘 또는 별도 표식으로 구분한다.
- 막다른 위험 가지는 막다른 길, 위험한 기척과 특별 보상 가능성을 알아볼 수 있게 표시한다.
- 적과 보상의 정확한 내용까지 모두 공개할 필요는 없다.
- 상단 진행 정보에는 던전명과 현재 층만 표시한다. 예: '잿빛 용광로 · 1층'
- 방 ID나 전체 방 수 같은 세부 진행 수치는 상단 HUD에 표시하지 않는다.
- 색상만으로 상태를 구분하지 않고 외곽선, 아이콘과 명암을 함께 사용한다.

3.2.12. 자유 왕복과 자동 이동
- 현재 방과 직접 연결된 방은 클릭해 이동할 수 있다.
- 완료된 방과 발견한 통로만 지나는 경로는 중간 방을 한 칸씩 클릭하지 않고 자동 이동한다.
- 자동 이동 중에는 완료된 방의 콘텐츠를 다시 실행하지 않는다.
- 경로에 미완료 방, 잠긴 통로 또는 조건 미충족 방이 포함되면 자동 이동할 수 없다.
- 이동 경로는 화면에 잠시 강조해 플레이어가 도착 경로를 이해할 수 있게 한다.

3.2.13. 계단과 보스 진입
- 계단 또는 다음 층 진입은 현재 층으로 돌아올 수 없는 단방향 전환이다.
- 현재 층에 미탐험 가지가 남아 있으면 확인 창을 표시한다.
- 보스 방도 필요하면 같은 확인 규칙을 적용한다.

확인 예시

다음 층으로 이동하면 이 층으로 돌아올 수 없습니다.
아직 탐험하지 않은 가지가 1개 남아 있습니다.

[계속 진행] [취소]

3.2.14. 공통 콘텐츠와 던전 전용 콘텐츠
- 모든 던전의 방 콘텐츠를 각각 새로 만들지 않고 공통 콘텐츠를 재사용한다.
- 공통 콘텐츠: 휴식, 기본 보상, 기본 블록 변형, 공통 이벤트
- 던전 전용 콘텐츠: 배경, 대표 기믹, 일부 몬스터, 던전 보스
- 최종 던전 콘텐츠: 강화된 기존 몬스터, 최종 보스, 최종 테마

3.2.15. 지도 저장 및 이어하기
- 완료한 일반 던전 목록
- 입장 가능한 던전 목록
- 현재 던전
- 현재 층
- 현재 방 ID
- 지도 생성 랜덤 시드
- 생성된 전체 지도 구조
- 발견한 방과 통로
- 완료한 방
- 이동 가능한 방
- 현재 진행 중인 인카운터
- 플레이어 체력과 골드
- 현재 덱 구성
- 전투 진입 직전의 플레이어 체력, 골드, 덱과 인카운터 정보를 저장한다.
- 전투 도중 종료하면 지도 화면이 아니라 해당 전투의 시작 상태에서 다시 시작한다.
- 전투 중 발생한 체력 변화, 손패, 버림 더미, 드로우 순서, 배치 상태, 몬스터 체력, 현재 턴과 방어도는 재개 데이터로 저장하지 않는다.

자동 저장 시점 후보
- 방 선택 또는 이동 직후

4. 블록 및 덱 시스템

4-1. 덱의 표현
- 게임에서 덱은 블록이 들어 있는 '주머니'로 표현한다.
- 가장 처음 전투를 시작할 때 총 13개의 블록을 가진다.
- 12개는 고정된 시작 블록으로 제공하고, 나머지 1개는 시작 방에서 고유 블록을 선택해 추가한다.
- 게임 시작 시 정한 기본 덱과 이후 전투·이벤트에서 변경된 덱 구성을 현재 런 동안 유지한다.
- 각 전투에서는 덱의 드로우 순서만 무작위로 섞는다.

4-2. 블록의 구성
- 블록은 여러 개의 정사각형 칸이 서로 붙어 있는 형태다.
- 각 블록은 고유 ID, 표시 이름, 사용자 정의 type, 모양, 색상, 회전·반전 허용 여부, 자체 효과, 설명과 태그를 가진다.
- '기본', '고유', '코어', '저주' 같은 분류를 코드에 고정하지 않고 사용자 정의 type으로 관리한다.
- type은 추가·수정·삭제할 수 있어야 하며 모든 블록은 하나의 목록에서 type ID로 구분한다.
- 블록의 효과는 실행 코드를 저장하지 않고 `effect_id`, `effect_name`, `target`, `value`, `type`과 필요한 선택 필드로 표현한다.
- 효과 설명은 사람이 검토하기 위한 보조 정보이며, 실제 실행은 공통 필드와 효과 타입을 기준으로 한다.
- 일반 블록은 주로 3칸 또는 4칸으로 구성할 수 있으며, 더 복잡한 블록도 데이터로 추가할 수 있다.
- 블록의 모양은 최소 한 칸 이상이며 상하좌우로 연결되어야 한다.

4-3. 초기 블록 예시

- 다음 블록은 초기 프로토타입 후보이며 코드에 고정된 전체 목록이 아니다.

I 블록
- 형태: 정사각형 3개가 일자로 연결된 모양

O 블록
- 형태: 2x2 정사각형

L 블록
- 형태: 정사각형 3개가 ㄱ자로 연결된 모양

4-4. 모양과 색상
- 블록의 모양은 퍼즐 판에 배치되는 형태를 결정한다.
- 블록의 색상은 효과 조건과 색상 시너지 판정에 사용할 수 있다.
- 일반 등급 색상은 `steel`, `fire`, `water`, `nature`이며 모두 같은 일반 등급이다.
- `special`, `legendary`, `curse`는 각각 해당 이름의 등급 분류 역할을 한다.
- `fire`, `water`, `nature`의 색상 시너지는 메인 프로그램의 공통 전투 규칙으로 계산한다.
- `steel`, `special`, `legendary`, `curse`는 일반 속성 시너지의 속성 개수에 포함하지 않는다.
- 색상 변경 이벤트는 미리 정의된 다른 블록으로 교체하는 방식과 연결하며, 임의로 색상만 바꾸는 기능은 콘텐츠 데이터에 따라 제공한다.

4-5. 특수 블록 후보
- U자 블록
- 지그재그 블록
- 십자형 블록
- 공격과 방어를 동시에 제공하는 복합 블록
- 프로토타입에서는 I, O, L을 우선 검증하되 실제 종류와 효과는 블록 디자인 프로그램의 출력 데이터에 맞춘다.

4-6. 블록·조합 규칙 데이터
- 블록과 조합은 별도의 블록 디자인 프로그램에서 시각적으로 제작하고 JSON으로 출력한다.
- 조합식은 하나 이상의 블록을 특정 위치와 형태로 배치했을 때 완성되는 규칙이다.
- 같은 블록 여러 개, 같은 type의 서로 다른 블록, 서로 다른 type, 같은 색상 또는 서로 다른 색상의 블록을 조합할 수 있다.
- 조합식은 단순 개수 조건이 아니라 각 블록 인스턴스가 격자에서 차지하는 실제 좌표와 회전·반전 상태를 저장한다.
- 정확한 블록, 임의 블록, 특정 type, 특정 색상, 특정 태그를 요구하는 조건형 슬롯을 사용할 수 있다.
- 조합은 항상 발생하는 효과와 조건부 효과를 가질 수 있다.
- 조합식의 형상 판정은 일반 블록의 색상 차이와 무관하게 수행한다.
- 색상 시너지는 조합식별이 아니라 거푸집 전체의 `fire`, `water`, `nature` 블록 수를 기준으로 메인 프로그램이 한 번 계산한다.
- 단일 속성은 단색 단계 시너지, 정확히 두 속성은 뒤섞인 시너지만 적용하며 세 속성은 시너지를 적용하지 않는다.
- 조합 전체의 회전·반전 인정 여부는 조합별 데이터로 설정한다.
- 본 게임은 schema version, 참조 ID, 좌표, 겹침과 현재 Designer가 제공하는 효과 데이터를 검증한 규칙 JSON만 불러온다.
- 효과 ID만으로 의미를 임의 추론하거나 기존 변수에 연결하지 않는다. 새로운 Type 또는 `parameters.id`는 지원 규칙을 먼저 확정한다.


5. 전투 시스템

5-1. 전투 개요
- 전투에서는 테트리미노처럼 여러 정사각형이 붙어 있는 블록을 퍼즐 판에 배치한다.
- 퍼즐 판은 칠교놀이처럼 일정한 외곽 형태를 가진다.
- 플레이어는 매 턴 무작위로 뽑은 블록을 배치해 공격, 방어, 회복 효과를 발생시킨다.
- 적에게는 '약점'이 존재한다.
- 특정 모양을 완성하거나 판을 정확히 채우면 추가 효과가 발생한다.
- 약점을 포함한 모양을 형성하면 추가 효과가 발생한다.
- 일반 전투에는 1~2마리, 강력 전투에는 2~3마리의 몬스터가 1~4번 고정 슬롯에 등장한다.
- 보스전에는 5번 보스 전용 슬롯의 보스 1마리만 등장한다.
- 단일 및 범위 효과의 대상은 3.1의 슬롯·진영·연쇄 처리 규칙을 따른다.

5-2. 전투 화면 전체 구성

좌측 상단 플레이어 정보 HUD
- 수평 체력 바와 현재 체력/최대 체력 수치
- 체력 바 아래에 이로운 상태 이상 아이콘을 수평 배치
- 그 아래에 해로운 상태 이상 아이콘을 수평 배치
- 그 아래에 현재 골드와 남은 덱 블록 수 표시

화면 중앙
- 플레이어 퍼즐 판과 몬스터 또는 전투 기믹용 퍼즐 판을 배치한다.
- 플레이어와 몬스터의 실제 이미지 또는 연출 영역은 별도로 구성할 수 있다.
- 일반 몬스터는 1~4번 고정 슬롯에 배치하며 각 슬롯의 점유와 빈 상태가 구분되어야 한다.
- 보스전에서는 1~4번과 모두 연결된 5번 보스 전용 슬롯을 추가로 표시한다.
- 이번 턴에 뽑은 블록을 표시한다.
- 남은 블록 확인 버튼, 버려진 블록 확인 버튼, 턴 종료 버튼을 배치한다.
- 블록을 집었을 때만 회전 조작 안내를 표시한다.
- 모든 살아 있는 몬스터의 다음 행동, 예상 효과와 대상 진영을 표시한다.

플레이어 퍼즐 판 아래 상태 표시
- 수평 체력 바와 체력 바 중앙의 현재 체력/최대 체력 수치
- 체력 바 아래에 이로운 상태 이상 아이콘을 수평 배치
- 그 아래에 해로운 상태 이상 아이콘을 수평 배치
- 그 아래에 이번 턴 배치한 블록 수/최대 배치 가능 수를 표시한다. 예: 2/3

몬스터 상태 표시
- 각 몬스터 슬롯에 현재 체력/최대 체력과 수평 체력 바를 표시한다.
- 각 몬스터의 이로운 상태와 해로운 상태 아이콘을 구분해 표시한다.
- 다음 행동 예고는 어느 몬스터의 행동인지 슬롯과 연결해 표시한다.
- 범위 대상 선택 중에는 중심 대상, 범위 포함 대상과 범위 밖 대상을 서로 다르게 강조한다.
- 몬스터에게는 플레이어의 배치 블록 수를 표시하지 않는다.

우측 상단 정보 및 설정 HUD
- 현재 던전명과 층 표시. 예: 잿빛 용광로 · 1층
- 지도 확인 버튼
- 설정 버튼: 톱니바퀴 아이콘 사용
- 메인 화면 이동 버튼: 문 아이콘 사용
- 자동 저장 상태 표시
- 메인 화면 이동 버튼은 오작동 방지를 위해 다른 버튼과 시각적으로 분리한다.
- 아이콘에 마우스를 올리면 기능 이름을 알려주는 툴팁을 표시한다.

기타 전투 정보
- 현재 턴
- 필요한 경우 플레이 시간
- 도감 버튼은 기능 확정 후 추가한다.

5-3. 퍼즐 판 규칙
- 퍼즐 판은 블록을 놓을 수 있는 정사각형 칸들의 집합이다.
- 블록은 퍼즐 판 내부에만 배치할 수 있다.
- 블록끼리 겹칠 수 없다.
- 판 밖으로 나가는 배치는 허용하지 않는다.
- 칸마다 표시되던 대각선 또는 불필요한 내부 장식선은 제거한다.
- 격자와 외곽선만 사용해 가시성을 확보한다.

5-4. 퍼즐 판과 체력의 관계
- 퍼즐 판인 거푸집은 플레이어 체력에 따라 본 게임에서 크기가 달라진다.
- 체력이 감소하면 3x3 중심 영역 바깥의 칸이 하나씩 제거된다.
- 최소 크기는 3x3이며 중심 영역은 항상 보장한다.
- 체력 구간별 정확한 크기, 최대 크기와 칸 제거 순서는 아직 확정하지 않는다.
- 체력이 늘어날 때는 가장 최근에 빠진 칸을 먼저 복구한다.
- 빠진 칸을 모두 복구한 뒤 추가 칸이 필요하면 테두리를 따라 순차적으로 생성한다.
- 몬스터의 외형 또는 특징에 맞는 판이 존재할 수 있다.
- 몬스터 판은 추가 효과를 주거나 특정 기믹을 수행하는 데 사용될 수 있다.

5-5. 드로우와 덱 순환
1) 전투 시작 시 13개의 블록으로 구성된 주머니를 섞는다.
2) 턴 시작 시 주머니에서 블록 5개를 뽑는다.
3) 플레이어는 뽑은 블록 중 기본적으로 최대 3개를 퍼즐 판에 배치한다.
4) 추가 효과가 있으면 최대 배치 가능 수가 늘어날 수 있다.
5) 턴 종료 전까지 사용하지 않은 블록은 임시 주머니인 버림 더미로 이동한다.
6) 이번 턴에 사용한 블록도 효과 처리 후 버림 더미로 이동한다.
7) 다음 드로우에 필요한 수량보다 주머니의 블록이 부족하면 남은 블록을 먼저 뽑고, 버림 더미를 섞어 주머니를 다시 만든 뒤 부족한 수량을 뽑는다.
8) 추가 턴은 완전히 새로운 플레이어 턴이므로 일반 턴과 같이 손패를 드로우하고 기본 배치 횟수를 다시 제공한다.

5-6. 남은 블록 확인
- 남은 블록 버튼은 덱에 있지만 아직 사용되지 않은 블록의 목록을 보여준다.
- 블록의 종류와 수량을 확인할 수 있다.
- 다음에 뽑힐 블록을 예측할 수 없도록 화면 표시 순서를 무작위로 섞는다.
- 실제 드로우 순서는 노출하지 않는다.

5-7. 버려진 블록 확인
- 버려진 블록 버튼은 현재 버림 더미에 있는 블록 목록을 보여준다.
- 지금까지 사용했거나 사용하지 못해 버린 블록을 확인할 수 있다.
- 버튼은 턴 종료 버튼의 왼쪽에 배치한다.

5-8. 블록 조작

블록 배치
- 블록을 마우스로 드래그해 퍼즐 판에 배치한다.
- 배치 가능한 위치에 들어가면 가능한 상태임을 시각적으로 표시한다.
- 판 밖으로 나가거나 다른 블록과 겹치면 배치할 수 없다.

블록 회전
- 블록을 드래그하는 도중 R 키를 누르면 오른쪽으로 90도 회전한다.
- R 키를 반복해서 누르면 90도 단위로 계속 회전한다.
- 정사각형처럼 회전해도 형태가 같은 블록은 동일하게 표시한다.

블록 회수
- 턴 종료 전에는 이미 배치한 블록을 다시 퍼즐 판에서 꺼낼 수 있다.
- 꺼낸 블록은 이번 턴의 손패로 돌아간다.
- 회수한 블록은 다른 위치에 다시 배치할 수 있다.
- 사용하지 않은 상태로 턴을 종료하면 버림 더미로 이동한다.
- 턴 종료 후에는 배치를 되돌릴 수 없다.

추후 개발 후보
- 도감에 등록된 형태가 현재 손패에 존재하면 해당 형태를 즉시 배치하는 기능

5-10. 퍼즐 판 초기화
- 턴 종료 시 그 턴에 배치한 블록을 모두 제거한다.
- 이전 턴의 블록 배치는 다음 턴에 남지 않는다.
- 다음 턴에는 빈 퍼즐 판에서 다시 배치한다.

5-11. 블록 기본 효과
- 각 블록은 자체 효과를 0개 이상 가질 수 있다.
- 자체 효과에는 공격, 방어, 회복, 상태 이상, 추가 드로우 등 본 게임에 구현된 effect ID를 사용할 수 있다.
- 블록 자체 효과의 기본 수치는 해당 효과의 `value`에서 읽고, 추가 참조가 필요하면 선택 필드를 사용한다.
- 블록별 피해·방어·회복 수치는 블록 디자인 프로그램의 결과물에서 가져온다.
- `fire`, `water`, `nature`의 공통 색상 시너지는 `BLOCKABLE_COMBAT_SYSTEM.md` V0.5.4의 누적 단계 규칙으로 메인 프로그램이 계산한다.

5-12. 방어도
- 방어도는 방어도 무시 피해가 아닌 일반 피해를 대신 받는 소모형 수치다.
- 각 기본 공격과 `A` 독립 공격의 피해량은 대상의 현재 방어도에서 먼저 차감하고, 방어도를 초과한 피해만 체력에 적용한다.
- 현재 턴에 획득한 방어도는 해당 턴의 몬스터 공격을 막을 수 있다.
- 방어도 증가량, 유지와 배율은 서로 다른 전투 요소로 사용할 수 있다.
- 기본적으로 방어도는 턴 종료 시 0이 되지만 유지 효과가 있으면 지정된 다음 턴까지 보존한다.

적용 공식

armorDamage = min(currentArmor, damage)
hpDamage = max(0, damage - currentArmor)
nextArmor = max(0, currentArmor - damage)
nextHp = max(0, currentHp - hpDamage)

- 방어도 무시 피해는 방어도를 변경하지 않고 체력에 직접 적용한다.
- `현재 체력 + 현재 방어도 - damage`는 총 생존 수치를 이해하기 위한 표현이며, 실제 구현은 방어도와 체력을 위 공식처럼 분리해 갱신한다.

예시
- 플레이어 방어도: 10
- 몬스터 공격력: 15
- 방어도가 피해 10을 막는다.
- 남은 피해 5가 플레이어 체력에 적용된다.

5-13. 특정 모양 완성 효과
- 여러 블록을 조합해 규칙 데이터에 등록된 실제 배치 도면을 만들면 조합 효과가 발생한다.
- 조합은 정확한 블록 배치뿐 아니라 type, 색상, 태그 등의 슬롯 조건을 사용할 수 있다.
- 일반 블록은 색상이 달라도 형태와 슬롯 조건이 같으면 같은 조합식을 완성할 수 있다.
- 조합식의 기하 판정 후 참여 블록과 미참여 블록을 구분한다.
- 참여 블록의 B 계열 피해는 조합 B에 합산한다.
- 조합식에 참여하지 않은 각 블록의 B 계열 피해는 해당 블록의 독립 A 패킷 1회로 변환하며 조합 H를 상속하지 않는다.
- 기존 `INDEPENDENT_DAMAGE` 패킷은 출처별로 유지하고 임의로 합치지 않는다.
- 조합의 기본 효과와 조건부 효과를 판정한 뒤 거푸집 전체 색상 시너지를 한 번 계산한다.
- 조합 공격력과 타격 횟수는 서로 다른 값으로 관리한다.

5-14. 중복 세트 보너스
- 같은 턴에 같은 종류의 모양을 여러 개 완성하면 효과가 증가한다.
- 여러 조합이 동시에 성립할 때의 우선순위와 하나의 블록이 여러 조합에 중복 참여할 수 있는지는 아직 확정하지 않는다.
- 중복 조합의 조건과 배율은 블록·조합 규칙 데이터 및 밸런스 테스트를 통해 결정한다.

5-15. 퍼즐 판 완성 보너스
- 퍼즐 판을 빈칸 없이 정확하게 채우면 추가 능력이 발동한다.
- 후보 효과는 추가 공격, 모든 공격 블록 효과 증가, 추가 방어도, 추가 골드, 다음 턴 추가 드로우 등이다.
- 판 완성 보너스는 일반 블록 효과 및 모양 세트 효과를 모두 계산한 후 계산한다.

5-16. 효과 계산 순서
1) B, P, M, D, W, H, A를 현재 상태에서 확정한다.
   - B는 기본 공격 1타의 피해 기준값이며 기본값은 0이다.
   - P는 기본 공격에 직접 더하는 피해 보너스이며 기본값은 0이다. 활성 분노 1스택당 P +1이다.
   - M은 공격력 증가 배율이며 기본값은 1이다.
   - D는 약화 등 공격력 감소 배율이며 기본값은 1이다.
   - W는 상처 등 받는 피해 증가 배율이며 기본값은 1이다.
   - H는 기본 공격 총 타격 횟수이며 기본값은 1이다.
   - A는 기본 공격 뒤 별도로 실행하는 독립 피해이며 기본값은 0이다.

2) 기본 공격 B를 H회 실행한다.

   `기본 공격 1타 = (B + P) × M × D × W`

   - 각 타격은 피해, 방어도, 반응, 사망과 연쇄 효과를 개별 처리한다.
   - 중심 대상이 사망하거나 무효화되면 남은 연타를 다른 적에게 재지정하지 않는다.
   - 추가 타격은 `EXTRA / HIT_COUNT`의 value만큼 H에 더한다.

3) 독립 공격 A 패킷을 정의된 순서대로 실행한다.

   `독립 공격 = A × M × D × W`

   - 조합식에 참여하지 않은 블록의 B는 블록별 A 패킷으로 변환하며 H를 상속하지 않는다.
   - 기본 공격 대상이 사망했더라도 A는 자체 대상과 범위를 다시 판정한다.
   - A 자체의 지정 대상이 무효라면 다른 적에게 자동 재지정하지 않는다.

4) 버프·디버프·지속 피해·군중 제어를 갱신한다.
   - 효과 스택은 JSON의 value에서 읽는다.
   - `parameters.id`로 분노·철갑, 약화·오한·상처, 화상·중독·출혈, 기절을 구분한다.
   - 버프는 획득 다음 턴에 활성화되고 그 턴 종료 시 제거한다.
   - 새 약화·오한·상처는 적용 턴에 감소하지 않는다.

5) 방어·회복·자원 효과를 적용한다.
   - 방어와 회복은 각각 `BLOCK`, `RECOVERY`의 value를 사용한다.
   - 드로우·추가 타격·범위·추가 턴·추가 배치는 `EXTRA`와 `parameters.id`로 구분한다.
   - 피해 적용 후 체력이 0이면 사망 처리한다.

6) 사망·연쇄 효과와 승리 예외를 처리한다.
   - 일반전은 현재 효과와 대기열이 모두 끝나기 전에는 승리를 확정하지 않는다.
   - 보스전은 5번 보스 사망이 확정되면 남은 처리를 취소하고 즉시 승리한다.

7) 추가 턴 또는 몬스터 행동으로 진행한다.
   - 추가 턴이 있으면 몬스터 행동과 몬스터 상태 피해를 생략하고 완전히 새로운 플레이어 턴을 시작한다.
   - 추가 턴도 일반 드로우, 기본 배치 횟수, 빈 거푸집과 방어도 초기화를 사용한다.
   - 추가 턴 중 다시 추가 턴을 얻을 수 있다.
   - 추가 턴이 없으면 살아 있는 몬스터가 슬롯 순서대로 행동한다.

8) 턴 종료 상태와 최종 종료 판정을 처리한다.
   - 화상·출혈·중독은 5-18의 대상별 공식으로 피해와 스택 감소를 처리한다.
   - 기존 약화·오한·상처는 1스택 감소한다.
   - 일반전은 상태 피해와 연쇄 대기열이 끝난 뒤 모든 적이 죽고 플레이어가 살아 있을 때 승리한다.

5-17. 몬스터 행동
- 몬스터는 턴마다 공격 또는 특수 행동을 한다.
- 살아 있는 모든 몬스터의 다음 행동은 플레이어 행동 전에 결정해 화면에 표시한다.
- 행동 예고에는 피해 또는 효과뿐 아니라 대상 진영을 함께 표시한다.
- 플레이어의 블록 효과를 처리한 뒤 몬스터가 생존했을 경우 1~4번 슬롯 순서로 행동하고, 보스전에서는 5번 보스가 마지막에 행동한다.
- 플레이어의 공격이나 앞선 연쇄 효과로 몬스터가 사망했다면 해당 턴의 행동을 실행하지 않는다.
- 몬스터 행동 패턴 FSM은 다음 ability_id를 결정하고, 행동 실행 상태는 IDLE, INTENT_READY, QUEUED, ACTING, RESOLVED, STUN_SKIPPED, CANCELLED, DEAD를 사용한다.
- 기절 상태인 몬스터는 QUEUED 상태의 실행 직전에 현재 행동을 건너뛰고 STUN_SKIPPED로 전환한다.
- 기절로 행동을 건너뛴 뒤 기절 스택을 제거하고 행동 패턴 위치는 다음 단계로 진행한다.
- 기절로 취소된 능력 효과와 신규 쿨다운은 적용하지 않는다.
- 행동 차례 전에 사망한 몬스터는 행동과 기절 소비를 모두 수행하지 않는다.
- 특수 몬스터는 특정 칸 봉인, 특정 색상 약화, 배치 방향 제한, 방해 블록 추가 등의 행동을 사용할 수 있다.
- 자폭 행동, 사망 시 효과와 피격 반응은 서로 다른 발동 조건으로 처리한다.

5-18. 상태와 상태 이상

기본 상태
- 체력: 플레이어 또는 몬스터가 생존할 수 있는 수치다. 플레이어 체력이 0 이하가 되면 현재 런이 종료된다. 개별 몬스터 체력이 0 이하가 되면 사망 처리하며, 모든 적과 연쇄 효과 처리가 끝난 뒤 전투 결과를 판정한다.
- 방어도: 피해를 대신 받는 임시 체력이다. 방어도 무시 피해를 제외한 피해를 먼저 흡수하며, 기본적으로 턴 종료 시 사라지지만 유지 효과가 있으면 보존한다.
- 분노: 획득 다음 턴에 활성화되며 스택당 P +1을 제공하고 활성 턴 종료 시 모두 제거한다.
- 철갑: 획득 다음 턴에 활성화되며 방어도 획득 시 스택당 방어 +1을 제공하고 활성 턴 종료 시 모두 제거한다.
- `BUFF / DAMAGE_BONUS`는 삭제된 구형 효과이며 P 또는 분노에 임의로 연결하지 않는다.
- 힘: 향후 별도 공격 능력치가 필요할 경우 추가할 후보이며 현재는 사용하지 않는다.
- 민첩: 플레이어 버프·디버프 및 방어·행동 관련 효과에 사용할 능력치다. 구체적인 적용 공식은 추후 확정한다.

상태 이상 피해
- 플레이어가 받는 출혈 피해 = 이번 턴에 최종 확정해 사용한 블록 개수 × 감소 전 출혈 스택 수
- 몬스터가 받는 출혈 피해 = 감소 전 출혈 스택 수 × 3
- 출혈은 방어도를 무시하고 체력에 직접 피해를 준다.
- 출혈 피해 처리 후 스택이 1 감소한다.
- 화상 피해 = 감소 전 화상 스택 수
- 화상은 일반 피해처럼 방어도로 막을 수 있다.
- 화상 피해 처리 후 스택이 절반으로 감소하며 홀수는 내림한다.
- 중독은 부여된 다음 턴부터 적용한다.
- 플레이어 중독 피해 = 블록을 배치할 때마다 `max(1, floor(중독 스택 × 0.5))`
- 몬스터 중독 피해 = 턴 종료 시 감소 전 중독 스택 수 × 3
- 중독은 방어도를 무시하며 턴 종료 후 스택을 절반으로 감소시키고 소수점 이하는 버린다.
- 이번 턴에 새로 부여된 출혈과 화상도 같은 턴 종료에 피해를 발생시킨다.
- 출혈·화상·중독은 분노, 약화, 상처, 공격력 배율의 영향을 받지 않는다.
- 출혈을 화상보다 먼저 처리한다.
- 출혈로 객체가 사망하면 해당 객체의 화상과 남은 상태이상 처리를 중단한다.
- 상태이상 피해로 발생한 사망 효과는 일반 사망·연쇄 효과 대기열에 등록한다.

상태 이상 디버프
- 약화: 1스택당 공격자의 일반 공격 피해를 10% 감소시키며 최종 피해량 공식의 D에 적용한다.
- 약화 계수 D = max(0, 1 - 약화 스택 × 0.10)
- 상처: 1스택당 대상이 받는 일반 피해를 10% 증가시키며 공격 공식의 W에 적용한다.
- 상처 계수 W = 1 + 상처 스택 × 0.10
- 오한: 새로 획득하는 방어도를 스택당 1 감소시키며 철갑과 서로 상쇄한다. 최종 획득 방어도는 0 미만이 될 수 없다.
- 새로 적용된 상처·약화·오한은 적용된 턴에 항상 보호한다.
- 다음 턴부터 턴 종료마다 1스택씩 사라지며, 해당 턴 피해 계산에 실제 참여했는지는 감소 조건으로 사용하지 않는다.

군중 제어
- 기절: 현재 예약된 몬스터 행동을 건너뛴다.
- 기절은 중첩할 수 없으며 최대 1스택이다.
- 실제 행동 순서가 도착해 행동을 건너뛴 직후 스택을 제거한다.
- 기절로 행동을 건너뛰어도 몬스터의 행동 패턴 위치는 다음 단계로 진행한다.
- 행동 차례 전에 몬스터가 사망하면 기절은 소비하지 않는다.

턴 종료 상태이상 순서
1) 플레이어 출혈 피해, 출혈 감소, 사망 판정
2) 플레이어가 생존하면 화상 피해, 화상 감소, 사망 판정
3) 플레이어 중독 감소와 적용 턴 보호가 끝난 약화·상처·오한 1스택 감소
4) 플레이어의 활성 분노·철갑 제거와 새로 얻은 분노·철갑 활성화
5) 추가 턴이 아니라면 살아 있는 몬스터를 1번부터 5번 슬롯 순서로 선택
6) 몬스터 출혈 피해, 출혈 감소, 사망·연쇄 효과 처리
7) 생존한 몬스터의 화상 피해, 화상 감소, 사망·연쇄 효과 처리
8) 생존한 몬스터의 중독 피해, 중독 감소와 적용 턴 보호가 끝난 약화·상처·오한 1스택 감소
9) 몬스터의 활성 분노·철갑 제거와 새로 얻은 분노·철갑 활성화

11) 일반전 최종 승리·패배 판정

- 상태이상 처리 중 5번 보스가 사망하면 남은 상태이상과 연쇄 처리를 취소하고 즉시 승리한다.

5-20. 전투 종료 조건

승리
- 일반 전투와 강력 전투는 모든 몬스터가 사망하고 현재 효과 및 사망·연쇄 효과 대기열이 비어 있으며 플레이어가 살아 있으면 종료된다.
- 보스전은 5번 보스가 사망하는 즉시 승리하며 남은 처리와 미실행 효과를 취소한다.

패배
- 현재 효과 및 필수 후속 처리를 마친 뒤 플레이어의 체력이 0 이하이면 전투가 종료된다.
- 마지막 적과 플레이어가 같은 연쇄 처리에서 모두 사망하면 패배로 처리한다.

후퇴
- 보스방을 제외한 일반 몬스터 전투의 후퇴 가능 여부와 처리 방식은 아직 결정되지 않았다.


6. 전투 결과 및 보상

6-1. 골드 보상
- 전투에서 승리하면 인카운터에 등장한 몬스터 구성과 등급에 따라 정해진 범위 내에서 기본 골드를 받는다.
- 구체적인 획득량과 계산 공식은 아직 확정되지 않았다.

6-2. 블록 보상
- 일반 전투 종료 후 무작위 블록 3개를 제시한다.
- 블록 선택지에는 무색 및 유색 블록이 포함될 수 있다.
- 플레이어는 블록 1개를 선택해 덱에 추가할 수 있다.
- 필요하지 않다면 아무것도 선택하지 않고 스킵할 수 있다.
- 보상 처리가 끝나면 지도 화면으로 복귀한다.

6-3. 인카운터별 결과

일반 전투
- 성공 조건: 모든 몬스터 처치 및 사망·연쇄 효과 처리 후 플레이어 생존
- 보상: 골드, 블록 3개 중 1개 선택
- 종료 후: 지도 복귀

보스 전투
- 성공 조건: 보스 처치
- 보상: 층 또는 던전 클리어 보상. 다회차 플레이가 생기면 추후 확장
- 일반 층 보스 종료 후: 다음 층 진입
- 일반 던전 최종 보스 종료 후: 전체 지도 복귀 및 해당 던전 완료 처리
- 중앙 최종 던전의 최종 보스 종료 후: 게임 클리어

일반 이벤트
- 성공 조건: 선택 완료 또는 스킵
- 보상: 이벤트에 따라 다름
- 종료 후: 지도 복귀

이벤트 전투
- 성공 조건: 미믹 또는 공허 괴물 처치
- 보상: 특수 보상 또는 일반 전투 보상
- 종료 후: 지도 복귀
- 프로토타입 이후 개발한다.

상점 이벤트
- 완료 조건: 구매 후 나가기, 또는 판매와 변형 중 하나를 수행한 뒤 나가기
- 변형은 플레이어가 보유한 블록을 블록 디자인 프로그램으로 미리 제작한 다른 블록으로 교체하는 방식이다.
- 플레이어가 블록의 칸을 직접 이동하거나 임의의 모양을 만드는 방식은 사용하지 않는다.
- 구매하거나 정비한 덱은 현재 런 동안 유지한다.
- 종료 후 지도 화면으로 복귀한다.


7. 이벤트 시스템

7-1. 이벤트 분류
- 이벤트 인카운터는 일반 이벤트와 레어 이벤트로 나뉜다.
- 현재 초안의 등장 비율은 일반 이벤트 70%, 레어 이벤트 30%다.
- 이 비율은 지도·경제 공식과 함께 추후 검증한다.

7-2. 일반 이벤트

상점
- 골드로 블록을 구매할 수 있다.
- 보유한 블록을 판매할 수 있다.
- 보유한 블록을 변형시킬 수 있다.
- 판매와 변형은 둘 중 하나만 수행할 수 있다.
- 구매 목록과 판매 목록은 리롤할 수 없다.
- 이용하지 않고 나갈 수 있다.

무료 블록 추가
- 무작위 블록 5개를 제시한다.
- 그중 1개를 선택해 덱에 추가할 수 있다.
- 스킵할 수 있다.
- 리롤할 수 없다.
- 최대 1회 선택할 수 있다.

무료 블록 삭제
- 현재 덱에 있는 블록 중 1개를 제거할 수 있다.
- 스킵할 수 있다.
- 최대 1회 가능하다.

무료 모양 변경 또는 색 변경
- 현재 덱에 있는 블록 1개를 미리 정해진 교체 대상 블록으로 변경할 수 있다.
- 교체 관계와 결과 블록은 블록 디자인 프로그램의 출력 데이터로 정의한다.
- 스킵할 수 있다.
- 최대 1회 가능하다.

유료 블록 추가
- 무작위 블록 3개를 제시한다.
- 무색, 유색 및 특수 블록이 등장할 수 있다.
- 골드를 지불하고 그중 1개를 덱에 추가할 수 있다.
- 스킵할 수 있다.
- 목록을 리롤할 수 있다.
- 기존 초안의 임시 리롤 비용은 최초 25골드이며, 리롤할 때마다 최초 비용만큼 증가한다.

유료 블록 삭제
- 골드를 지불해 덱의 블록 1개를 제거할 수 있다.
- 스킵할 수 있다.
- 기존 초안의 임시 비용은 최초 50골드이며, 제거할 때마다 최초 비용만큼 증가한다.

유료 모양 변경 또는 색 변경
- 골드를 지불해 현재 덱에 있는 블록 1개를 미리 정해진 교체 대상 블록으로 변경할 수 있다.
- 스킵할 수 있다.
- 교체 결과는 블록 디자인 프로그램에서 제작한 블록 데이터만 사용할 수 있다.
- 기존 초안의 임시 비용은 최초 50골드이며, 변경할 때마다 최초 비용만큼 증가한다.
- 최대 2회 가능하다.

변형 이벤트
- 플레이어가 보유한 블록 1개를 선택한다.
- 선택한 블록에 연결된 미리 정의된 변형 결과 중 하나로 교체한다.
- 블록의 칸을 게임 안에서 직접 이동하는 기능은 제공하지 않는다.
- 변형 전·후 블록의 type, 모양, 색상, 효과와 교체 가능 관계는 블록 디자인 프로그램의 결과물에 맞춘다.

보물 상자
- 플레이어는 상자를 열거나 지나갈 수 있다.
- 상자를 열면 골드, 미믹, 공허의 상자 또는 광대 상자 등의 결과가 발생할 수 있다.
- 골드 보상, 결과별 확률 및 비용은 현재 확정 공식이 없으므로 추후 결정한다.
- 미믹은 즉시 전투로 전환되는 후보 콘텐츠다.
- 공허의 상자는 골드 또는 체력을 대가로 요구하는 후보 콘텐츠다.
- 광대 상자는 지울 수 없는 저주 블록을 추가하는 후보 콘텐츠다.

7-4. 이벤트 종료

11. 확정 사항과 추가 결정 사항

11-1. 현재 확정한 기준
- 기본 덱은 13개다. 12개 고정 제공 후 시작 방에서 고유 블록 1개를 선택해 추가한다.
- 지도는 전체 지도 → 던전 → 층 → 방·통로의 계층으로 구성한다.
- 해커톤 버전에는 일반 던전 2개와 중앙 최종 던전 1개를 둔다.
- 일반 던전 2개를 모두 완료하면 중앙 최종 던전을 개방한다.
- 장기 확장에서는 일반 던전 수와 요구 클리어 수를 설정 데이터로 변경할 수 있다.
- 층 지도는 주 경로, 분기·합류 및 막다른 선택 가지를 가진 공간형 구조다.
- 각 층에는 시작 방과 계단 방 또는 보스 방이 존재한다.
- 프로토타입에서는 템플릿 기반 제약형 무작위 생성을 적용한다.
- 완료한 방과 발견한 통로를 따라 자유롭게 왕복할 수 있다.
- 완료 방의 전투, 이벤트, 보상, 휴식과 변형은 다시 발생하지 않는다.
- 완료 방만 지나는 경로는 자동 이동할 수 있다.
- 계단이나 다음 층에 진입한 뒤에는 이전 층으로 돌아갈 수 없다.
- 막다른 위험 가지에는 강한 적과 높은 가치의 보상을 배치할 수 있다.
- 시작 방은 전투가 아닌 고유 블록 선택 방이며, 선택 후 다음 경로로 분기한다.
- 같은 종류의 방이 연속될 때마다 해당 종류의 다음 등장 확률은 절반으로 감소한다.
- 휴식 방은 층의 절반 이후부터 등장할 수 있으며 현재 체력을 20 회복한다.
- 미발견 방의 상세 정보는 공개하지 않고 인접 방, 계단과 보스 위치는 규칙에 따라 일부 공개할 수 있다.
- 상단 HUD에는 던전명과 층만 표시한다.
- 일반 전투에는 1~2마리, 강력 전투에는 2~3마리의 몬스터가 1~4번 고정 슬롯에 등장한다.
- 보스전에는 5번 슬롯의 보스 1마리만 등장하며 부하 몬스터를 함께 생성하지 않는다.
- 몬스터 사망 후 다른 몬스터가 빈 슬롯으로 당겨지지 않는다.
- 단일·좌·우·좌우·전체 공격을 지원한다. 일반전의 범위는 1~4번 선형 슬롯의 거리로 판정하고, 보스전에서는 5번과 1~4번의 직접 연결 관계를 추가한다.
- 보스전의 연결 범위 피해는 직접 대상과 동일한 수치로 적용하며 피해 감소를 두지 않는다.
- 보스 밸런스는 우선 최대 체력과 기본 능력치로 조정한다.
- 몬스터 효과는 플레이어, 몬스터 진영 또는 모든 전투 참가자를 대상으로 할 수 있다.
- 자폭 행동, 사망 폭발과 피격 반응 폭발을 서로 다른 발동 조건으로 구분한다.
- 사망·연쇄 효과는 순차 대기열로 처리하고 동시 사망 효과는 1~4번 슬롯 순서로 등록한 뒤 5번 보스를 마지막에 등록한다.
- 일반 전투와 강력 전투는 마지막 적이 죽어도 대기열을 모두 처리한 후 플레이어가 살아 있을 때만 승리한다.
- 보스전은 5번 보스 사망 즉시 승리한다.
- 프로토타입의 몬스터 행동은 1~4번 슬롯 순서를 우선 적용하고 보스전에서는 5번 보스가 마지막에 행동하며, 모든 행동 예고를 공개한다.
- Block Designer와 Monster Designer의 효과는 `effect_id`, `effect_name`, `description`, `target`, `value`, `type`, `parameters` 공통 규격을 사용하며 메인 Codex는 `type + parameters.id + value + target`을 범용 로직에 연결한다.
- Designer 데이터를 반영할 때 확정 로직 연결, 신규 Type·ID 발견, 필드 오류와 미지원 효과를 효과 해석 보고서로 남긴다.
- 블록 3개 중 하나를 선택하는 보상은 일반적으로 전투 승리 보상이다.
- 이벤트 인카운터는 각 이벤트에 정해진 별도 결과를 적용한다.
- 턴 종료 시 이번 턴에 놓은 블록을 전부 제거한다.
- 다음 턴은 빈 퍼즐 판에서 시작한다.
- 턴 종료 전에는 배치한 블록을 회수하고 재배치할 수 있다.
- 한 턴에는 기본적으로 블록을 최대 3개 배치한다.
- 블록과 조합은 type, 모양, 색상, 효과를 데이터로 정의하고 블록 디자인 프로그램의 JSON 결과와 연동한다.
- 플레이어 기본 공격 B, 독립 공격 A, 상태 갱신, 방어·회복·자원 효과, 추가 턴 확인, 생존한 몬스터 행동, 턴 종료 상태 처리, 최종 종료 판정 순서로 처리한다.
- 기본 공격 1타 피해량은 `(B + P) × M × D × W`로 계산하고 H회 개별 실행한다.
- A는 기본 공격의 모든 처리가 끝난 뒤 `A × M × D × W`로 계산하는 독립 공격이다.
- P는 기본값 0이며 활성 분노 1스택당 1을 더한다. 삭제된 `BUFF / DAMAGE_BONUS`는 P 또는 분노에 연결하지 않는다.
- 약화는 공격자의 D에, 상처는 각 공격 대상의 W에 적용한다.
- 기본 공격 대상이 사망·무효화되면 남은 연타와 해당 공격 기회는 재지정 없이 종료하지만, A 독립 공격은 자체 타겟팅 규칙으로 별도 판정한다.
- 출혈과 화상은 턴 종료 단계에서 처리하며 새로 부여된 턴에도 발동한다. 중독은 부여된 다음 턴부터 작동한다.
- 기절은 몬스터의 현재 행동을 건너뛰고 제거되며 행동 패턴 위치는 진행한다.
- 몬스터 등급은 일반, 네임드, 보스로 구분한다.
- 방어도는 기본적으로 턴 종료 시 0이 되며 유지 효과가 있으면 지정된 다음 턴까지 보존한다.
- 방어도 증가량과 방어도 배율은 서로 다른 전투 요소로 사용할 수 있다.
- 단일 속성은 누적 단색 시너지, 정확히 두 속성은 뒤섞인 시너지만 적용하고 세 속성은 시너지를 적용하지 않는다.
- 색상 시너지 피해는 B가 아니라 독립 피해 A로 처리한다.
- 조합 미참여 블록의 B 계열 피해는 블록별 A 1회로 변환하고 조합 H를 상속하지 않는다.
- 추가 타격은 `EXTRA / HIT_COUNT`의 value만큼 H를 증가시킨다.
- 플레이어 출혈은 사용 블록 개수×스택, 몬스터 출혈은 스택×3으로 계산한다.
- 새 약화·상처·오한은 적용 턴에 보호하고 다음 턴부터 1스택씩 감소한다.
- 분노·철갑은 획득 다음 턴에 활성화되고 그 턴 종료 시 제거한다.
- 추가 턴은 일반 드로우·배치 초기화·방어도 초기화를 포함한 완전히 새로운 플레이어 턴이며 몬스터 행동과 몬스터 상태 피해를 처리하지 않는다.
- 전투 중 종료하면 해당 전투의 시작 상태에서 다시 시작한다.
- 변형 이벤트는 보유 블록을 미리 정의된 다른 블록으로 교체한다.
- 마지막 층에는 일반 층 보스와 구분되는 던전 최종 보스가 존재한다.
- 좌측 상단, 중앙의 양측 판 아래, 우측 상단의 전투 UI 구조를 사용한다.
- 플레이어 판 아래에는 이번 턴 배치 블록 수를 표시한다.

11-2. 지도와 진행. 추후 결정

- 상점 전용 방 추가 여부

- 보스 직전 방의 고정 규칙
- 고유 블록의 구체적인 종류와 선택지 수
- 등급별 몬스터의 정확한 수량과 배치
- 막다른 위험 가지의 등장 빈도와 보상 등급

- 던전 최종 보스와 최종 클리어 연출

- 변형 이벤트의 블록별 교체 관계

11-4. 퍼즐과 조작. 추후 결정
- 퍼즐 판의 기본 크기와 체력 연동 방식의 최종 확정
- 몬스터 형태 기반과 층 난이도 기반 중 어느 방식으로 판을 정할지
- 블록을 드래그하지 않는 상태에서도 회전할 수 있는지
- 모바일 또는 터치 환경에서 회전을 어떻게 조작할지
- 배치 가능한 위치를 어떤 방식으로 표시할지
- 조합식 전체의 회전·반전 인정 여부 기본값

11-5. 전투 규칙. 추후 결정
- 특정 모양의 종류와 기본 보너스
- 중복 세트 개수별 효과 배율
- 여러 세트가 같은 블록을 공유할 수 있는지
- 여러 조합이 동시에 성립할 때의 우선순위
- 조합 발동 후 참여 블록의 소비 또는 유지 방식
- 퍼즐 판 완성 보너스의 정확한 효과
- 공격, 방어, 회복 수치에 세트 배율을 동일하게 적용할지
- 체력, 공격력, 방어도 등 기본 밸런스 수치
- 힘을 분노와 별개의 능력치로 추가할지 여부 및 민첩의 구체적인 공식
- 공격력 배율 M과 받는 피해 증가 계수 W의 상한
- 개별 효과에서 공통 내림·0 하한과 다른 반올림 규칙이 필요한지 여부
- 오버킬 골드 계산식과 상한
- 일반 전투 후퇴 가능 여부와 처리 방식
- 몬스터별 체력, 어빌리티, 피해, 방어와 행동 선택 공식
- 여러 몬스터의 행동 순서를 장기적으로 속도 능력치로 확장할지 여부
- 각 효과가 여러 대상에게 같은 피해를 적용할지 대상별로 재계산할지에 대한 표준 규칙
- 공통 `type` 열거형에 새 효과를 추가할 때 필요한 선택 필드와 하위 호환 정책

11-6. 이벤트와 경제. 추후 결정

12. 한 문장 요약

전체 지도에서 공략할 던전을 선택하고 방·통로형 층 지도의 주 경로와 위험·보상 가지를 자유롭게 탐험하며, 매 턴 주머니에서 블록 5개를 뽑아 최대 3개를 배치하고 블록 자체 효과·조합식·색상 시너지와 연결 기반 범위 공격으로 일반전의 1~2마리, 강력 전투의 2~3마리 또는 보스전의 보스 1마리를 상대해 중앙 최종 던전의 보스를 처치하는 로그라이크 블록 배치 게임이다.


부록 A. 미확정 제안값

주의
- 이 부록은 확정 규칙이 아니다.
- 기존 본문과 충돌할 경우 본문을 우선한다.

A-1. 경제 밸런스 제안값
- 일반 전투 평균 보상: 100골드
- 강한 전투 평균 보상: 150골드
- 블록 구매: 150~300골드
- 블록 삭제: 최초 200골드
- 유료 변경: 최초 150골드
- 리롤: 최초 50골드
- 위 수치는 확정값이 아니며 기존 본문의 임시 비용을 대체하지 않는다.

A-2. 튜토리얼 제안
- 첫 전투에서 필요한 순간에 한 단계씩 표시
- 블록 드래그
- R 키 회전
- 유효한 칸에만 배치 가능
- 이미 놓은 블록 회수
- 한 턴 최대 3개 사용
- 블록 색상별 효과
- 몬스터 행동 예고
- 턴 종료
- 덱과 버림 더미 확인
- 구체적인 진행 순서, 표시 방식 및 재열람 규칙은 아직 없음


부록 B. 개발자 모드

목적 및 접근 조건
- 게임 테스트와 디버깅을 위한 개발 환경 전용 모드다.
- Vite 개발 환경에서만 활성화하며 실제 release에서는 일반 사용자가 접근할 수 없다.
- URL 파라미터나 저장 데이터만으로 release에서 개발자 기능을 활성화할 수 없다.
- 개발자 기능은 일반 모드의 게임 규칙을 다시 구현하지 않고 기존 진행·보상·저장 흐름을 재사용한다.

메인 화면
- 개발 환경에서는 메인 화면 좌측 하단에 개발자 전용 메뉴를 표시한다.
- '개발자 게임 시작'과 '개발자 이어하기' 버튼을 제공한다.
- 개발자 게임 시작 시 프롤로그를 생략하고 지도 화면으로 진입한다.
- 개발자 이어하기 데이터가 없으면 해당 버튼을 비활성화한다.
- 일반 런과 개발자 런은 서로 다른 저장 슬롯을 사용한다.
- 개발자 플레이 결과가 일반 이어하기 데이터에 영향을 주지 않는다.

지도 화면
- 개발자 모드에서는 일반적인 발견·이동 가능 상태와 관계없이 현재 층의 원하는 방에 바로 진입할 수 있다.
- 일반 모드에서는 현재 방과 연결된 미방문 방 또는 완료 경로로 도달 가능한 방만 이동할 수 있다.
- 개발자 모드의 직접 이동은 방 콘텐츠의 완료 여부를 임의로 초기화하지 않는다.
- 필요하면 현재 층의 모든 방·통로 공개, 선택 방 완료 처리와 선택 방 콘텐츠 재실행 기능을 별도 개발자 도구로 제공한다.
- 개발자 모드 전용 '골드 +1000' 버튼을 표시하며, 클릭할 때마다 현재 골드를 1000씩 추가한다.

전투 화면
- 개발자 모드에서는 턴 종료 버튼 왼쪽에 '자동 승리' 버튼을 표시한다.
- 자동 승리는 플레이어 입력 단계에서만 사용할 수 있고 중복 실행할 수 없다.
- 자동 승리도 기존 승리 흐름을 사용하여 골드·블록 보상, 방 완료, 지도 복귀, 층 이동 및 던전 클리어 처리를 유지한다.
- 턴 종료 버튼 위에는 접거나 펼칠 수 있는 개발자 로그 패널을 표시한다.
- 로그에는 전투 시작과 몬스터별 슬롯 정보, 블록 배치 수와 점유 칸, 대상 선택과 범위, 플레이어 공격 피해, 몬스터별 잔여 체력, 사망·연쇄 효과 대기열, 몬스터 행동, 플레이어 체력 변화, 다음 턴 준비, 자동 승리 및 처치 정보를 기록한다.
- 로그는 최근 100개까지만 유지한다.
- 전투 로그는 전투 화면의 임시 UI 상태이며 저장 데이터에 포함하지 않는다.

적용 범위
- 메인 화면의 개발자 진입 메뉴, 지도 개발자 도구, 자동 승리 및 전투 로그는 모두 개발자 모드에서만 표시하고 실행한다.
- 일반 게임의 지도 이동, 전투 계산, 보상 및 저장 규칙은 변경하지 않는다.
