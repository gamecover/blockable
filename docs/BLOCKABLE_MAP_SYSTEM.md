> 파일명: `BLOCKABLE_MAP_SYSTEM.md`  
> 문서 상태: 초안 — 변경된 지도 시스템의 기획 및 구현 기준

## 1. 문서 목적

이 문서는 Blockable의 던전 지도 시스템을 실제 게임에 구현하기 위한 상세 명세이다.

전체 게임의 방향과 던전의 역할은 `BLOCKABLE_GAME_DESIGN.md`에서 관리하고, 이 문서에서는 다음 내용을 구체적으로 정의한다.

- 던전·층·노드의 관계
- 주 경로와 일반·위험 브랜치의 생성
- 난이도 1~10의 초기 생성 수치
- 노드 유형과 층당 생성 한도
- 플레이어 이동, 노드 진입, 재방문 규칙
- 보상 배율과 위험 브랜치의 비용
- 지도 UI와 노드 상태 표시
- 절차적 생성 순서와 유효성 검증
- 저장·불러오기 및 전투 시스템 연동
- 구현 단계와 테스트 기준

개별 이벤트, 상점 상품, 몬스터 편성, 보상 테이블의 실제 콘텐츠는 이 문서에 중복 기재하지 않는다. 이 문서는 해당 콘텐츠가 지도에 배치되고 실행되는 공통 규칙만 정의한다.

## 3. 핵심 용어

### 3.1 던전

던전은 한 번의 연속된 탐험 단위이며 여러 층으로 구성된다.

예:

```text
잿빛 용광로
├─ 1층
├─ 2층
└─ 3층: 보스층
```

### 3.2 층

층은 하나의 독립된 노드 그래프이다.

- 각 층에는 시작 노드가 정확히 1개 존재한다.
- 일반 층에는 계단 노드가 정확히 1개 존재한다.
- 최종 층에는 계단 대신 보스 노드가 정확히 1개 존재한다.
- 플레이어가 계단 또는 보스에 도달하면 해당 층의 필수 진행을 완료한다.

### 3.3 노드

노드는 하나의 방 또는 하나의 게임 경험을 나타낸다.

예:

- 시작
- 일반 전투
- 이벤트
- 상점
- 회복
- 강적
- 보상
- 계단
- 보스

### 3.4 경로와 거리

이 문서에서는 수치 혼동을 막기 위해 다음 기준을 사용한다.

| 용어 | 계산 기준 |
|---|---|
| 경로 길이 | 노드 사이를 이동하는 통로, 즉 간선의 수 |
| 방문 노드 수 | 시작과 목적지를 포함하여 실제 들어간 노드의 수 |
| 브랜치 길이 | 갈림길 다음부터 브랜치 끝까지 포함된 노드 수 |
| 브랜치 깊이 | 갈림길에서 브랜치 끝까지의 이동 횟수 |

단순한 일자형 브랜치에서는 `브랜치 길이 = 브랜치 깊이`이다.

예:

```text
시작 ─ A ─ B ─ 계단
```

- 주 경로 길이: 3
- 필수 방문 노드 수: 4

### 3.5 주 경로

주 경로는 시작 노드에서 계단 또는 보스 노드까지 이어지는 필수 경로이다.

- 주 경로는 층마다 정확히 1개 생성한다.
- 브랜치는 주 경로보다 짧은 우회 경로를 만들 수 없다.
- 초기 버전에서는 주 경로를 단순 경로로 생성한다.
- 주 경로의 중간 노드를 거치지 않고 목적지로 갈 수 있는 지름길은 생성하지 않는다.

### 3.6 브랜치

브랜치는 주 경로의 중간 노드에서 갈라지는 선택 경로이다.

- 브랜치 개수: 주 경로에서 갈라지는 가지의 수
- 브랜치 길이: 가지 하나에 포함된 노드 수
- 브랜치 최대 깊이: 갈림길에서 가장 먼 가지 끝까지의 최대 거리
- 초기 버전에서는 브랜치 내부에서 다시 갈라지는 중첩 브랜치를 만들지 않는다.
- 기본 브랜치는 주 경로에서 생성하지만, 좌표상 가까운 노드끼리는 확률적으로 보조 통로가 추가될 수 있다.
- 보조 통로로 인해 브랜치 끝이 다른 브랜치나 주 경로와 연결되어 선택 가능한 순환 경로가 생길 수 있다.
- 하나의 노드에 연결할 수 있는 브랜치 수를 별도 상한으로 제한하지 않으며, 실제 연결 수는 인접한 빈 격자와 확률 결과로 자연스럽게 제한한다.

## 4. 지도 시스템의 설계 목표

지도는 단순히 다음 전투를 선택하는 메뉴가 아니라 다음 선택을 제공해야 한다.

- 짧고 안전한 주 경로로 보스까지 진행할 것인가
- 추가 전투와 자원 소모를 감수하고 브랜치를 탐험할 것인가
- 보스 전에 회복·상점·보상을 확보할 것인가
- 위험 브랜치의 강적과 특별 보상에 도전할 것인가

난이도가 높아질 때 플레이 시간이 지나치게 증가하지 않도록 세 축을 분리한다.

| 난이도 축 | 조절 대상 |
|---|---|
| 지도 규모 | 층 수, 생성 노드 수, 주 경로 길이 |
| 탐험 복잡도 | 브랜치 수, 길이, 깊이 |
| 전투 위험도 | 일반 몬스터 능력치, 강적 수, 위험 노드 구성 |

후반 난이도는 지도 규모보다 전투 위험도와 위험 브랜치의 비중을 더 크게 높인다.

## 5. 층의 기본 구조

### 5.1 일반 층

```text
시작 → 주 경로 노드들 → 계단
          ├─ 일반 브랜치
          └─ 위험 브랜치
```

### 5.2 최종 층

```text
시작 → 주 경로 노드들 → 보스
          ├─ 일반 브랜치
          └─ 위험 브랜치
```

### 5.3 첫 번째 층의 시작 노드

고유 블록 선택은 새 게임 시작 후 최초 전체 지도 진입 전에 한 번만 진행한다. 던전의 첫 번째 층 시작 노드는 이후 층과 동일한 안전한 `floor_start` 노드로 사용한다.

- 시작 노드는 정확히 1개이다.
- 던전에 입장하면 시작 노드로 자동 이동한다.
- 시작 노드는 진입 즉시 `cleared` 상태가 된다.
- 던전 시작 노드에서는 고유 블록을 추가로 선택하지 않는다.

### 5.4 두 번째 층 이후의 시작 노드

- 이전 층의 계단에서 이동하면 자동으로 진입한다.
- 별도 전투나 비용이 없는 안전한 도착 지점이다.
- 진입 즉시 `cleared` 상태로 처리한다.

### 5.5 보스 노드

- 최종 층에 정확히 1개만 생성한다.
- 반드시 시작 노드에서 도달 가능해야 한다.
- 보스 노드 뒤에 일반 노드나 브랜치를 배치하지 않는다.
- 보스 처치 시 던전을 완료한다.

## 6. 브랜치 종류

### 6.1 일반 브랜치

일반 브랜치는 비교적 낮은 위험으로 보조 기회를 제공한다.

배치 가능한 콘텐츠:

- 일반 전투
- 이벤트
- 상점
- 회복
- 일반 보상

일반 브랜치의 마지막 노드는 보상·상점·회복·이벤트 중 하나를 우선 배치한다. 공간이 부족하거나 방 유형 한도를 초과하면 일반 전투 후 보상 방식으로 대체할 수 있다.

### 6.2 위험 브랜치

위험 브랜치는 추가 위험을 감수하고 더 좋은 보상을 얻는 선택 경로이다.

필수 규칙:

- 주 경로가 아닌 브랜치에만 생성한다.
- 끝 노드에는 강적과 특별 보상이 함께 존재해야 한다.
- 강적을 처치하기 전에는 최종 보상을 획득할 수 없다.
- 보스 필수 경로에는 위험 브랜치의 강적을 배치하지 않는다.
- 위험 브랜치는 지도에서 사전에 식별 가능해야 한다.

위험 브랜치의 비용은 이동 횟수가 아니라 다음과 같은 내부 콘텐츠에서 발생한다.

- 추가 전투
- 강적 전투
- HP 손실 가능 이벤트
- 회복 없이 이어지는 연속 전투
- 보스 전에 소비되는 체력과 자원

### 6.3 조건부 브랜치

열쇠, 특정 블록, 업적 등으로 개방되는 조건부 브랜치는 향후 확장 항목이다.

해커톤 초기 버전에는 구현하지 않는다.

## 7. 난이도별 초기 생성 수치

다음 수치는 구현 및 플레이 테스트를 시작하기 위한 **초기 밸런스 기준값**이다. 시스템 규칙은 확정 기준으로 사용하되, 수치는 테스트 결과에 따라 데이터 파일에서 조정할 수 있어야 한다.

모든 노드 관련 범위는 `층당` 기준이며, 전체 층 수만 던전 전체 기준이다.

| 2 | 2 | 6~8 | 8 | 4~5 | 5~7 | 3~4 | 1~2 | 1~2 | 2 | 0~1 | 1 | ×1.1~1.5 |
| 3 | 3 | 7~9 | 9 | 5~6 | 6~8 | 4~5 | 2 | 1~2 | 2 | 1 | 1 | ×1.1~1.6 |

### 7.1 수치 해석

- `필수 방문 노드 = 주 경로 길이 + 1`을 기본 관계로 사용한다.
- 모든 브랜치를 탐험하면 `전체 방문 노드 수 = 해당 층의 생성 노드 수`가 된다.
- 권장 방문 노드 수는 필수 경로에 일반적인 브랜치 탐험을 더한 플레이 테스트 목표값이다.
- 난이도 1 생성기는 목표 노드 수를 정한 뒤 브랜치 2개의 최소 노드 예산을 먼저 예약한다.
- 난이도 1의 세 번째 브랜치는 목표 노드가 9개이고 예산이 충분할 때 조건부로 생성한다.
- 브랜치 최소 예산을 확보한 뒤 남은 범위에서 주 경로 길이를 결정한다.
- 증가한 노드 예산은 계단·보스까지의 필수 경로보다 선택 브랜치에 우선 배정한다.
- 난이도 1의 주 경로 길이는 기존보다 최대 1만 증가시키고, 완전 수평 경로는 생성하지 않는다.
- 시작→계단·보스 최단 경로의 목적지 쪽 중앙에는 회복 노드를 정확히 1개 보장한다.
- 보장 회복 외의 추가 회복은 일반 노드 2%, 브랜치 끝 5% 확률로 생성하며 층당 최대 1개만 허용한다.
- 개발자 모드의 전역 난이도 1~10은 이 표의 층 수, 노드 수, 주 경로, 브랜치 및 위험 브랜치 수치를 실제 생성기에 연결한다.
- 범위의 최댓값을 무조건 채우지 않는다.
- 최종 층도 같은 규모 규칙을 사용하되 목적지 노드를 계단 대신 보스로 지정한다.
- 모든 층의 시작 노드는 전체 노드 수에 포함한다.
- 실제 생성되는 강적 방 수는 실제 생성된 위험 브랜치 수보다 클 수 없다.
- 표의 `브랜치 수`는 주 경로에서 최초 생성하는 기본 브랜치 수이며, 근접 노드 사이에 추가되는 보조 통로 수는 포함하지 않는다.
- 근접 보조 통로의 초기 생성 확률은 후보 통로당 35%로 사용한다.

### 7.2 층별 전투 위험 보정

같은 난이도에서도 뒤쪽 층의 전투는 더 강해져야 한다. 지도 규모를 다시 늘리는 대신 몬스터 편성과 보상에 층 보정을 적용한다.

초기 기준:

```text
floorProgress = (현재 층 - 1) / max(전체 층 - 1, 1)
```

`floorProgress`는 몬스터 데이터 선택과 보상 등급 확률에 전달한다. 구체적인 몬스터 능력치 배율은 전투 밸런스 데이터에서 관리하며 지도 생성기가 직접 계산하지 않는다.

|---|---|---|---|
| 층 시작 | `floor_start` | 현재 위치 설정 | 가능 |
| 일반 전투 | `battle` | 일반 몬스터 전투 | 승리 후 빈 방 |
| 이벤트 | `event` | 이벤트 선택지 실행 | 완료 후 재실행 불가 |
| 상점 | `shop` | 구매 UI 실행 | 층을 떠나기 전 재이용 가능 |
| 회복 | `rest` | 회복 또는 관련 선택 실행 | 사용 후 재실행 불가 |
| 강적 | `elite` | 강적 전투 실행 | 승리 후 보상 완료 상태 |
| 보상 | `reward` | 지정 보상 선택 | 수령 후 재실행 불가 |
| 계단 | `stairs` | 다음 층 진입 확인 | 다음 층 이동 전까지 가능 |
| 보스 | `boss` | 보스 전투 실행 | 승리 시 던전 종료 |

### 8.1 전투 노드 완료

- 전투 승리 후 해당 노드를 `cleared`로 변경한다.
- 전투 보상이 남아 있다면 `reward_pending` 상태를 거친다.
- 보상 선택까지 끝나야 인접 노드로 이동할 수 있다.
- 전투 도중 지도를 열더라도 다른 노드로 이동할 수 없다.

### 8.2 상점 재방문

- 이미 방문한 상점도 현재 층에 머무는 동안 다시 열 수 있다.
- 구매한 상품과 보유 재고 상태는 유지한다.
- 상점 재방문으로 상품을 새로 추첨하지 않는다.

### 8.3 회복·이벤트·보상 재방문

- 완료된 결과 화면만 확인할 수 있다.
- 효과와 보상은 다시 지급하지 않는다.

## 9. 방 유형별 생성 한도

### 9.1 공통 배치 규칙

- 시작 노드: 층당 정확히 1개
- 계단 또는 보스: 층당 정확히 1개
- 상점: 층당 최대 1개
- 회복: 중앙 보장 1개, 추가 회복 최대 1개
- 보상: 층당 최대 1개
- 강적: 난이도 테이블의 최대 개수 이하
- 위험 브랜치: 난이도 테이블의 범위 이하
- 동일한 전투 계열 노드: 최대 2개 연속
- 보스 바로 전 노드: 일반 전투·상점·회복 중 하나

### 9.2 일반 노드 구성 목표

시작·계단·보스·강적을 제외한 남은 노드에 다음 목표 비율을 적용한다.

| 유형 | 목표 비율 |
|---|---:|
| 일반 전투 | 40~55% |
| 이벤트 | 15~25% |
| 상점 | 0~15%, 최대 1개 |
| 회복 | 중앙 1개 보장, 일반 노드 2%·브랜치 끝 5%로 추가 1개까지 |
| 일반 보상 | 0~10%, 최대 1개 |

비율은 정확한 할당량이 아니라 가중치로 사용한다. 생성 결과는 노드 수가 적을 때 비율보다 필수 배치 및 최대 개수 규칙을 우선한다.

### 9.3 보스 직전 안전 규칙

- 보스 직전 1개 노드는 `battle`, `shop`, `rest` 중 하나이다.
- 보스 직전 노드는 `elite`가 될 수 없다.
- 보스 직전 2개 노드가 모두 전투일 경우 둘 중 하나는 일반 전투여야 한다.
- 시작→보스 최단 경로의 목적지 쪽 중앙에는 회복 방을 반드시 배치한다.

### 9.4 위험 브랜치 끝

위험 브랜치의 마지막 노드는 단순 `elite` 노드가 아니라 다음 결과를 함께 가진다.

```text
강적 전투 승리
→ 위험 브랜치 보상 생성
→ 보상 선택 완료
→ 노드 cleared
```

별도의 보상 노드를 추가할 노드 예산이 있는 경우:

```text
강적 노드 → 특별 보상 노드
```

노드 예산이 부족한 경우:

```text
강적 노드 내부에서 특별 보상 지급
```

두 표현은 플레이 결과가 같아야 한다.

## 10. 브랜치 보상

### 10.1 보상 배율

```text
최종 보상 배율
= 기본 브랜치 배율
× 깊이 보정
× 위험도 보정
```

초기 기준:

| 브랜치 특성 | 목표 배율 |
|---|---:|
| 깊이 1 일반 브랜치 | ×1.1 |
| 깊이 2 일반 브랜치 | ×1.2 |
| 깊이 2 위험 브랜치 | ×1.5 |
| 깊이 3 위험 브랜치 | ×1.8 |
| 강적이 있는 위험 브랜치 최종 방 | 최대 ×2.0 |

난이도 테이블의 보상 배율 범위를 최종 하한·상한으로 적용한다.

```text
finalRewardMultiplier =
    clamp(
        baseBranchMultiplier
        * depthModifier
        * riskModifier,
        difficulty.rewardMultiplierMin,
        difficulty.rewardMultiplierMax
    )
```

### 10.2 배율 적용 대상

모든 보상 수치에 동일한 곱셈을 적용하지 않는다.

- 골드 수량 증가
- 높은 등급 보상 확률 증가
- 보상 선택지 수 증가
- 고유 블록·장비 출현 확률 증가
- 회복량 증가가 필요한 경우 별도 상한 적용

### 10.3 중복 보상 방지

- 하나의 위험 브랜치는 특별 보상을 한 번만 지급한다.
- 강적 전투 보상과 브랜치 끝 보상을 별도로 지급할 경우 데이터에서 명시적으로 구분한다.
- 저장·불러오기 후 보상이 다시 생성되거나 지급되지 않아야 한다.

## 11. 지도 생성 절차

지도 생성은 다음 순서를 고정한다.

### 11.1 1단계: 입력 확정

```text
던전 ID
난이도 1~10
난수 시드
지도 설정 버전
던전별 허용 노드 유형
```

같은 입력과 같은 설정 버전은 같은 지도를 생성해야 한다.

### 11.2 2단계: 층 수 결정

난이도 테이블에서 전체 층 수를 읽는다.

### 11.3 3단계: 층별 목표 노드 수 결정

1. `층당 생성 노드 범위`에서 목표 노드 수를 추첨한다.
2. `층당 최대 노드`를 넘지 않도록 제한한다.
3. 난이도별 최소 브랜치 수에 필요한 노드 예산을 먼저 예약한다.
4. 주 경로와 최소 브랜치를 만들 수 없는 값이면 재추첨한다.

### 11.4 4단계: 주 경로 생성

1. 예약된 브랜치 예산을 제외한 범위에서 주 경로 길이를 추첨한다.
2. 시작 노드를 생성한다.
3. 길이만큼 간선을 가진 단순 경로를 생성한다.
4. 마지막 노드를 일반 층에서는 계단, 최종 층에서는 보스로 지정한다.
5. 중간 노드는 아직 유형이 없는 `unassigned` 상태로 둔다.
6. 시작 노드의 화면 좌표는 지도 중앙에 둔다.
7. 계단 또는 보스의 화면 방향은 동·서·남·북 및 대각선 방향 중에서 시드 기반으로 결정하며, 특정 방향에 고정하지 않는다.
8. 주 경로 좌표에는 가로·세로 이동을 모두 포함하여 최소 한 번 이상 꺾이게 한다.
9. 완전한 직선 배치나 목적지가 시작점에 지나치게 가까운 배치는 좌표를 다시 생성한다.
10. `ㄱ자`, `ㄴ자`, 계단형, 완만한 `S자`처럼 진행 방향을 읽을 수 있는 배치를 우선한다.
11. 모든 노드는 서로 다른 격자 좌표를 사용하며, 노드 UI가 겹치지 않는 최소 간격을 확보한다.

### 11.5 5단계: 브랜치 생성

1. 브랜치 개수를 난이도 범위에서 결정한다.
2. 주 경로의 시작과 목적지를 제외한 노드 중 갈림 지점을 선택한다.
3. 기본 브랜치 갈림 지점은 분산하되, 이후 추가되는 보조 통로에는 노드별 연결 수 상한을 두지 않는다.
4. 브랜치 길이를 범위 안에서 추첨한다.
5. 남은 노드 예산을 초과하면 길이를 줄이거나 브랜치 생성을 취소한다.
6. 기본 브랜치를 생성한 뒤, 서로 인접한 격자 좌표에 있는 미연결 노드 쌍을 보조 통로 후보로 수집한다.
7. 지정된 수만큼 위험 브랜치를 선택한다.
8. 브랜치는 비어 있는 격자 좌표로 배치하며, 길이가 2 이상이면 한 방향으로 포개지지 않고 최소 한 번 꺾이게 한다.
9. 남은 노드 예산은 브랜치 길이를 늘리는 데 우선 사용하고, 조건이 충족되면 추가 브랜치를 생성한다.
10. 보조 통로 후보마다 설정 확률을 적용하며, 선택된 통로는 `link` 경로로 구분한다.
11. 보조 통로는 시작 노드와 계단·보스 노드에 직접 추가하지 않는다.
12. 보조 통로를 추가해도 기존 시작→계단·보스 최단 필수 경로가 바뀌지 않아야 한다.

### 11.6 6단계: 필수 노드 유형 배치

1. 모든 층의 시작을 `floor_start`로 지정한다.
2. 첫 층도 던전 진입 시 자동으로 시작 노드에 배치하고 완료 처리한다.
3. 목적지를 `stairs` 또는 `boss`로 지정한다.
4. 시작→목적지 최단 경로의 목적지 쪽 중앙을 `rest`로 지정한다.
5. 위험 브랜치 끝을 `elite` 및 특별 보상 대상으로 지정한다.
6. 보스 직전 안전 규칙을 적용한다.

### 11.7 7단계: 나머지 노드 유형 배치

1. 층별 방 유형 한도를 계산한다.
2. 일반 브랜치 끝에 보조 보상 유형을 우선 배치한다.
3. 주 경로와 브랜치의 미지정 노드를 가중치로 배치한다.
4. 같은 전투 유형 3연속 여부를 확인한다.
5. 상점·회복·보상 최대 개수를 확인한다.
6. 위반이 있으면 해당 노드 유형을 다시 추첨한다.

### 11.8 8단계: 콘텐츠 참조 연결

각 노드 유형에 실제 콘텐츠 후보를 연결한다.

예:

```text
battle → monsterEncounterPoolId
event  → eventPoolId
shop   → shopPoolId
elite  → eliteEncounterPoolId
boss   → bossEncounterId
```

지도 생성 시 후보 풀만 확정하고, 실제 콘텐츠 추첨 시점은 저장 정책에 따라 다음 중 하나를 선택한다.

- 지도 생성 시 모두 확정
- 노드 최초 공개 시 확정
- 노드 최초 진입 시 확정

초기 구현 권장안은 **지도 생성 시 모두 확정**이다. 저장·불러오기와 재시작 악용을 막기 쉽기 때문이다.

### 11.9 9단계: 유효성 검증

모든 검증을 통과해야만 지도를 플레이 상태로 저장한다.

### 11.10 10단계: 실패 처리

- 최대 재생성 횟수: 층당 50회
- 50회 실패 시 해당 난이도의 안전 템플릿 지도를 사용한다.
- 개발 모드에서는 실패한 시드, 검증 항목, 생성 설정을 로그로 남긴다.
- 사용자 화면에는 내부 생성 실패 로그를 노출하지 않는다.

## 12. 생성 의사 코드

```text
function generateDungeon(dungeonId, difficulty, seed):
    rng = createSeededRandom(seed)
    config = difficultyConfigs[difficulty]
    dungeon = new DungeonMap()

    for floorIndex in 1..config.floorCount:
        success = false

        for attempt in 1..50:
            targetNodeCount = rng.range(
                config.nodesPerFloorMin,
                config.nodesPerFloorMax
            )

            branchPlan = reserveMinimumBranchBudget(
                targetNodeCount,
                config,
                rng
            )

            mainPathLength = pickMainPathLengthFromRemainingBudget(
                targetNodeCount,
                branchPlan,
                config,
                rng
            )

            floor = createMainPath(
                floorIndex,
                mainPathLength,
                requireVerticalBend = true,
                rng
            )

            attachBranches(floor, branchPlan, config, rng)
            assignRequiredNodeTypes(floor, dungeon, config)
            assignOptionalNodeTypes(floor, config, rng)
            assignContentReferences(floor, dungeonId, difficulty, rng)

            validation = validateFloor(floor, config)

            if validation.valid:
                dungeon.floors.push(floor)
                success = true
                break

        if not success:
            dungeon.floors.push(
                createSafeTemplateFloor(floorIndex, config)
            )

    return validateDungeon(dungeon, config)
```

## 13. 유효성 검증

### 13.1 필수 그래프 검증

- 시작 노드가 정확히 1개 존재한다.
- 계단 또는 보스 노드가 정확히 1개 존재한다.
- 모든 노드는 시작 노드에서 도달 가능하다.
- 고립된 노드가 없다.
- 끊어진 통로가 없다.
- 같은 두 노드 사이에 중복 통로가 없다.
- 자기 자신으로 연결되는 통로가 없다.
- 기본 주 경로와 브랜치는 모두 연결되어야 하며, 근접 보조 통로에 의한 순환 경로는 허용한다.
- 보조 통로는 격자상 서로 인접한 노드끼리만 연결해야 한다.

### 13.2 경로 검증

- 시작에서 목적지까지 최단 경로가 존재한다.
- 최단 경로 길이가 주 경로 길이 범위를 만족한다.
- 필수 방문 노드 수가 난이도 범위를 만족한다.
- 브랜치가 더 짧은 보스·계단 경로를 만들지 않는다.
- 보스·계단을 통과해야 접근할 수 있는 일반 노드가 없다.
- 난이도 1의 주 경로에는 최소 1회의 상하 이동이 존재한다.
- 난이도 1에서는 완전 수평인 시작→계단·보스 경로를 허용하지 않는다.
- 최단 경로의 목적지 쪽 중앙 노드가 `rest`인지 확인한다.

### 13.3 규모 검증

- 생성 노드 수가 층당 범위를 만족한다.
- 생성 노드 수가 절대 상한을 초과하지 않는다.
- 브랜치 개수와 길이가 난이도 범위를 만족한다.
- 브랜치 깊이가 최대 깊이를 넘지 않는다.

### 13.4 콘텐츠 검증

- 위험 브랜치 수가 설정 범위를 만족한다.
- 강적 방 수가 최대 개수를 넘지 않는다.
- 위험 브랜치 끝에 강적과 특별 보상이 존재한다.
- 상점·회복·보상 방이 각각 최대 개수를 넘지 않는다.
- 보장 회복을 제외한 추가 회복 방이 층당 1개를 넘지 않는다.
- 동일 전투 계열이 3개 이상 연속되지 않는다.
- 보스 직전 안전 규칙을 만족한다.
- 모든 콘텐츠 참조 ID가 실제 데이터에 존재한다.

### 13.5 던전 전체 검증

- 층 수가 난이도 설정과 일치한다.
- 마지막 층에만 보스가 존재한다.
- 마지막 층 이전에는 계단이 존재한다.
- 모든 계단이 정확히 다음 층 시작점으로 연결된다.
- 던전 진입 시 첫 층의 `floor_start`로 자동 이동하며 해당 노드는 완료 처리된다.

## 14. 플레이어 이동 규칙

### 14.1 이동 가능 조건

플레이어는 인접 노드로 직접 이동하거나, 이미 완료된 방만 통과하는 경로를 통해 여러 칸 자동 이동할 수 있다.

이동하려는 노드는 다음 중 하나여야 한다.

- 아직 방문하지 않은 인접 노드
- 이미 완료한 노드와 그 노드만 통과하는 도달 가능한 목적지
- 재이용 가능한 상점 노드

### 14.2 이동 불가 조건

다음 상황에서는 이동할 수 없다.

- 현재 전투가 진행 중
- 이벤트 선택이 끝나지 않음
- 보상이 남아 있음
- 노드 진입 연출 또는 층 전환이 진행 중
- 목적지까지 완료된 방만 통과하는 경로가 없음

### 14.3 왕복과 이동 비용

- 완료한 노드를 통한 왕복 이동은 허용한다.
- 초기 버전에는 별도의 이동 횟수나 이동 자원을 소비하지 않는다.
- 브랜치의 비용은 이동이 아니라 그 안의 전투·이벤트·자원 소모로 구성한다.

### 14.4 여러 칸 자동 이동

일반 게임 모드에서는 완료된 방만 지나는 경로에 한해 여러 칸 자동 이동을 허용한다.

- 미완료 노드를 중간 경유지로 사용할 수 없다.
- 목적지는 이동 가능 또는 완료 상태여야 한다.
- 개발자 모드에서는 디버깅을 위해 완료 여부와 관계없이 모든 방으로 이동할 수 있다.

## 15. 노드 런타임 상태

### 15.1 노드 진행 상태

```text
locked
→ available
→ current
→ resolving
→ reward_pending
→ cleared
```

| 상태 | 의미 |
|---|---|
| `locked` | 아직 이동할 수 없는 노드 |
| `available` | 현재 위치에서 다음 이동 대상으로 선택 가능 |
| `current` | 플레이어가 현재 위치한 노드 |
| `resolving` | 전투·이벤트·상점 등의 콘텐츠 처리 중 |
| `reward_pending` | 본 콘텐츠는 끝났지만 보상 선택이 남음 |
| `cleared` | 콘텐츠와 보상이 모두 완료됨 |

상점은 `cleared` 이후에도 `revisitable: true`로 다시 열 수 있다.

### 15.2 공개 상태

진행 상태와 정보 공개 상태를 분리한다.

```text
hidden
→ revealed
→ visited
```

초기 구현 기준:

- 현재 노드와 그래프 거리 1인 인접 노드는 유형과 통로를 공개한다.
- 그래프 거리 2인 노드는 `미확인` 표시와 해당 노드까지 이어지는 통로만 공개한다.
- 그래프 거리 3 이상인 노드와 통로는 지도에 표시하지 않는다.
- 플레이어가 이동하면 새 현재 노드를 기준으로 공개 범위를 다시 계산한다.
- 정확한 몬스터 편성, 이벤트 내용, 보상 결과는 진입 전까지 숨긴다.
- 한 번 방문한 노드의 결과는 지도에서 확인 가능하게 유지한다.
- 개발자 모드도 기본 공개 범위는 일반 모드와 같으며, 전용 `던전 맵 전체 보기` 토글을 켠 동안에만 모든 노드와 통로를 공개한다.

이는 위험과 보상을 선택하게 하면서도 재시작을 통한 콘텐츠 재추첨을 방지한다.

## 16. 계단·보스 진입 경고

계단 또는 보스 노드를 선택했을 때 현재 층에 미완료 브랜치가 남아 있으면 경고를 표시한다.

```text
아직 탐험하지 않은 길이 있습니다.
이 층을 떠나면 다시 돌아올 수 없습니다.

[계속 탐험] [다음 층으로]
```

규칙:

- `계속 탐험`: 현재 노드에 머문다.
- `다음 층으로`: 확인 후 층을 종료한다.
- 다음 층에 진입하면 이전 층으로 돌아갈 수 없다.
- 보스 노드는 경고 확인 후 전투를 시작한다.
- 경고는 미완료 일반·위험 브랜치가 있을 때만 표시한다.
- 완료한 상점의 미구매 상품은 미완료 브랜치로 계산하지 않는다.

## 17. 지도 UI

### 17.1 기본 표시

지도 화면은 최소한 다음 정보를 표시한다.

- 던전 이름
- 현재 층 / 전체 층
- 현재 노드
- 노드와 통로
- 노드 유형
- 일반·위험 브랜치 구분
- 방문·완료·이동 가능 상태
- 플레이어 HP, 골드 및 핵심 자원
- 지도 닫기 또는 현재 콘텐츠 복귀 버튼

### 17.2 권장 배치

- 현재 층의 지도만 중앙에 크게 표시한다.
- 시작 노드는 지도 중앙에 배치한다.
- 주 경로는 시드에 따라 중앙에서 임의 방향으로 진행하며 최소 한 번 꺾인다.
- 일반 브랜치는 주 경로 주변의 빈 격자 좌표로 뻗으며 다른 노드와 겹치지 않는다.
- 위험 브랜치는 색상, 테두리, 경고 아이콘으로 구분한다.
- 계단 또는 보스는 시작점 기준 임의 방향의 주 경로 끝에 배치한다.
- 지도 캔버스는 화면 크기에 맞춰 노드 간격을 압축하지 않고, 지도 이미지 안쪽의 유효 영역을 충분히 사용하는 논리 크기를 유지한다.
- 지도 캔버스가 화면 뷰포트보다 크면 배경 드래그 또는 방향키로 상하좌우 이동할 수 있게 한다.
- 지도 오른쪽에는 접근 가능한 확대·축소 버튼과 현재 확대율을 표시한다.
- 지도 진입 시 현재 노드가 뷰포트 중앙 부근에 오도록 초기 위치를 맞춘다.
- 층 목록은 상단 또는 측면의 작은 진행 표시로 제공한다.

그래프 데이터의 연결 관계와 화면 좌표는 분리한다. 노드의 실제 이동 가능 여부는 좌표가 아니라 `edge` 데이터로 판정한다.

### 17.3 상태 표현

| 상태 | 권장 표현 |
|---|---|
| 현재 위치 | 밝은 외곽선과 플레이어 마커 |
| 이동 가능 | 점등 또는 호버 강조 |
| 방문하지 않음 | 기본 아이콘, 세부 내용 숨김 |
| 완료 | 체크 또는 어두운 완료 표시 |
| 위험 브랜치 | 붉은색·주황색 경고 테두리 |
| 강적 | 강적 전용 아이콘 |
| 계단 | 다음 층 아이콘 |
| 보스 | 대형 보스 아이콘과 전용 프레임 |
| 선택 불가 | 낮은 채도와 클릭 차단 |

색상만으로 상태를 구분하지 않고 아이콘·테두리·명암을 함께 사용한다.

### 17.4 통로 표현

- 주 경로 통로는 일반 굵기로 표시한다.
- 브랜치 통로는 조금 얇게 표시한다.
- 위험 브랜치 통로는 경고색 또는 불꽃 효과를 사용할 수 있다.
- 현재 이동 가능한 통로는 호버 시 점등한다.
- 완료한 통로는 낮은 채도로 유지하되 사라지지 않는다.
- 노드, 통로, 지도 배경은 같은 이동·확대 레이어에 포함하여 확대율과 드래그 위치가 서로 어긋나지 않게 한다.

## 20. 저장 및 불러오기

### 20.1 저장 대상

- `schema_version`
- `generator_version`
- 난수 시드
- 생성된 전체 노드와 통로
- 모든 노드의 콘텐츠 참조
- 현재 층과 현재 노드
- 노드 진행 및 공개 상태
- 보상 수령 여부
- 상점 재고와 구매 상태
- 전투 진입 전·후 상태

### 20.2 재생성 금지

불러오기 시 시드로 지도를 다시 생성하는 것을 기본 방식으로 사용하지 않는다.

- 이미 생성된 노드와 통로를 저장한다.
- 지도 생성 알고리즘이 업데이트되어도 진행 중인 세이브의 지도가 바뀌지 않아야 한다.
- 시드는 디버깅과 재현을 위해 함께 저장한다.

### 20.3 중복 보상 방지

노드 완료와 보상 수령은 분리해서 저장한다.

```text
전투 승리 저장
→ reward_pending
→ 보상 선택
→ reward_claimed
→ cleared
```

게임이 중간에 종료되어도 이미 받은 보상을 다시 받을 수 없어야 하며, 아직 선택하지 않은 보상은 사라지지 않아야 한다.

## 21. 다른 시스템과의 연동

### 21.1 전투 시스템

```text
전투 노드 진입
→ encounter_id로 전투 생성
→ BLOCKABLE_COMBAT_SYSTEM 규칙 실행
→ 승리 결과 수신
→ 보상 처리
→ 지도 노드 완료
```

지도는 전투의 내부 턴과 피해 계산을 직접 처리하지 않는다.

### 21.2 이벤트 시스템

```text
이벤트 노드 진입
→ event_id로 이벤트 로드
→ 선택지와 결과 처리
→ 완료 상태 수신
→ 지도 노드 완료
```

### 21.3 상점 시스템

상점은 노드 최초 생성 시 재고를 확정하며, 재방문 시 같은 재고와 구매 상태를 사용한다.

### 21.4 보상 시스템

지도는 다음 값을 보상 시스템에 전달한다.

- 난이도
- 현재 층
- 노드 유형
- 일반·위험 브랜치 구분
- 브랜치 깊이
- 최종 보상 배율

## 23. 예외 처리

### 23.1 콘텐츠 참조 누락

- 개발 모드: 오류를 표시하고 누락 ID를 로그에 기록한다.
- 배포 모드: 해당 노드를 안전한 일반 전투 또는 이벤트 폴백으로 교체한다.
- 보스 콘텐츠가 누락된 경우 던전을 시작하지 않고 명확한 오류 화면을 표시한다.

### 23.2 이동 중 중복 입력

- 첫 이동 요청 후 입력을 잠근다.
- 이동 완료 이벤트 전까지 추가 노드 클릭을 무시한다.
- 애니메이션 완료와 실제 위치 변경은 하나의 상태 전이로 처리한다.

### 23.3 전투 결과 중복 수신

- 노드별 `resolution_id`를 사용한다.
- 같은 전투 결과가 두 번 도착해도 보상과 완료 처리는 한 번만 실행한다.

### 23.4 잘못된 세이브

- 현재 노드가 존재하지 않으면 해당 층의 시작 노드로 복구한다.
- 통로와 노드 연결이 손상되었으면 세이브를 자동 덮어쓰지 않는다.
- 복구 불가능한 경우 사용자에게 새 던전 시작 여부를 확인한다.

## 25. 구현 단계

### 1단계: 데이터 모델

- 난이도 설정 타입
- 던전·층·노드·통로·브랜치 타입
- 생성 데이터와 런타임 데이터 분리

완료 기준:

- 고정된 샘플 지도를 데이터만으로 표현할 수 있다.

### 2단계: 주 경로 생성

- 시드 기반 난수
- 시작과 계단·보스 생성
- 난이도별 주 경로 길이 적용

완료 기준:

- 같은 시드에서 같은 주 경로가 생성된다.

### 3단계: 브랜치 생성

- 일반·위험 브랜치
- 길이·깊이·노드 예산 제한
- 근접 노드 확률 연결과 희소 순환 경로

완료 기준:

- 설정 범위를 넘는 브랜치가 생성되지 않는다.

### 4단계: 노드 유형 배치

- 필수 노드 배치
- 방 유형 가중치와 최대 개수
- 위험 브랜치 강적·보상
- 보스 직전 안전 규칙

완료 기준:

- 모든 노드가 유효한 콘텐츠 유형을 가진다.

### 5단계: 검증과 폴백

- 그래프·경로·규모·콘텐츠 검증
- 최대 50회 재생성
- 안전 템플릿

완료 기준:

- 무작위 시드 대량 테스트에서 플레이 불가능한 지도가 반환되지 않는다.

### 6단계: 지도 UI

- 노드와 통로 렌더링
- 상태별 표시
- 호버·선택·이동
- 위험 브랜치와 보스 표시

완료 기준:

- 플레이어가 현재 위치와 이동 가능한 노드를 즉시 구분할 수 있다.

### 7단계: 노드 콘텐츠 연동

- 전투
- 이벤트
- 상점
- 회복
- 보상
- 계단과 보스

완료 기준:

- 각 노드 진입부터 완료 후 지도 복귀까지 진행된다.

### 8단계: 저장·불러오기

- 생성 지도 저장
- 런타임 상태 저장
- 중복 보상 방지

완료 기준:

- 어떤 노드 상태에서도 저장 후 동일한 상태로 복귀한다.

## 26. 필수 테스트 시나리오

### 26.1 생성

- 난이도 1~10 각각 1,000개 이상의 시드 생성
- 모든 층이 최대 노드 수 이하인지 확인
- 시작과 계단·보스가 정확히 1개인지 확인
- 모든 노드가 도달 가능한지 확인
- 최단 경로가 설정 범위인지 확인
- 난이도 1의 주 경로가 완전 수평으로 생성되지 않는지 확인
- 모든 층의 시작 노드가 지도 중앙 좌표인지 확인
- 여러 시드에서 계단·보스가 시작점 기준 다양한 방향에 생성되는지 확인
- 모든 노드가 서로 다른 격자 좌표를 사용하고 UI 최소 간격을 확보하는지 확인
- 길이 2 이상의 브랜치가 한 방향으로 포개지지 않고 꺾이는지 확인
- 근접 보조 통로가 후보별 확률에 따라 생성되며 연결이 없는 층도 나오는지 확인
- 보조 통로가 인접 격자만 연결하고 노드별 고정 연결 상한을 적용하지 않는지 확인
- 보조 통로 추가 후에도 기존 시작→계단·보스 최단 필수 경로가 유지되는지 확인
- 난이도 1에서 브랜치 최소 노드 예산을 먼저 확보하는지 확인
- 생성 결과가 추첨된 목표 노드 수를 모두 사용하는지 확인
- 최단 경로 중앙의 보장 회복과 추가 회복 최대 1개 제한 확인
- 위험 브랜치 끝에 강적과 보상이 있는지 확인
- 동일 전투 노드가 3개 이상 연속되지 않는지 확인

### 26.2 이동

- 인접 노드로 이동 가능
- 연결되지 않은 노드로 이동 불가
- 완료 노드를 통한 왕복 가능
- 전투·이벤트·보상 처리 중 이동 불가
- 빠른 연속 클릭에도 한 번만 이동

### 26.3 브랜치

- 일반 브랜치 완료 후 주 경로 복귀
- 위험 브랜치 포기 후 주 경로 진행
- 위험 브랜치 강적 처치 후 보상 1회 지급
- 깊이와 위험도에 따른 보상 배율 적용

### 26.4 층 전환

- 미탐험 브랜치가 있으면 경고 표시
- 경고 취소 시 현재 층 유지
- 확인 시 다음 층 시작 노드로 이동
- 다음 층 진입 후 이전 층 복귀 불가
- 최종 층 보스 승리 후 던전 완료

### 26.5 저장·불러오기

- 최초 시작 노드
- 일반 노드 이동 중
- 전투 승리 후 보상 대기
- 위험 브랜치 완료 후
- 상점 일부 구매 후
- 계단 진입 직전
- 보스 전투 직전

각 상태에서 지도 구조, 현재 위치, 보상 수령 여부가 유지되어야 한다.

## 29. 최종 구현 원칙

1. 지도는 `던전 → 층 → 노드`의 계층으로 관리한다.
2. 각 층에는 시작과 계단·보스가 정확히 하나씩 존재한다.
3. 주 경로는 보스까지의 필수 진행이며 브랜치는 선택적 위험·보상 경로이다.
4. 일반 브랜치와 위험 브랜치를 데이터와 UI에서 명확히 구분한다.
5. 위험 브랜치의 비용은 이동 횟수가 아니라 전투와 자원 소모에서 발생한다.
6. 보상은 브랜치 깊이와 위험도를 함께 반영한다.
7. 지도 규모, 탐험 복잡도, 전투 위험도를 분리해서 난이도를 조정한다.
8. 무작위 생성 결과는 반드시 유효성 검증을 통과해야 한다.
9. 생성된 지도는 저장하며 불러오기 때 임의로 다시 생성하지 않는다.
10. 그래프 연결, 콘텐츠 데이터, UI 좌표와 런타임 상태를 서로 분리한다.
11. 개별 전투·이벤트의 내부 규칙은 각 전용 시스템이 소유한다.
12. 초기 구현은 검증 가능한 기본 경로를 먼저 보장하고, 근접 보조 통로로 제한적인 순환 경로를 허용한다.
