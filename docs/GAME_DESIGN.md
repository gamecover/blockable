Blockable 기획안 v0.5

프로젝트 목적
- NHN 2026 해커톤 참여를 목적으로 제작하는 웹 기반 게임 프로토타입이다.
- 공식 페이지: https://nan2026.nhn.com/

작성 기준
- 현재까지 논의된 세계관, 지도, 전투, 블록, 보상, 이벤트 및 UI 구성을 통합한 기획 초안이다.
- v0.4 본문, 2026-07-25 회의 내용, 블록·조합 규칙 편집기 기획안 v0.3 및 이후 대화에서 확정한 기준을 우선 적용한다.
- 편의상 사용한 '레고'라는 표현은 실제 게임 제작 시 '블록'으로 통일한다.
- 최근 대화에서 직접 확정한 UI 구성은 본문에 반영한다.
- 확정하지 않은 수치와 규칙은 본문에서 명시적으로 '임시값', '후보' 또는 '추후 결정'으로 구분한다.
- 지도는 프로토타입 검증을 위해 템플릿 기반 제약형 무작위 생성 방식을 우선 적용한다. 난이도별 층·노드 수와 세부 확률은 아직 확정되지 않았다.
- 비용, 확률, 피해량 등 본문에 남아 있는 숫자는 별도 표기가 없는 한 프로토타입 검증용 임시값이다.

3. 주요 게임 구조

3-1. 지도 용어

던전(Dungeon)
- 플레이어가 공략하는 전체 지역이다.
- 하나의 던전은 여러 개의 층으로 구성될 수 있다.
- 예: 잿빛 용광로

층(Floor)
- 던전을 구성하는 세로 단계(Vertical Level)다.
- 플레이어가 한 층의 보스 노드를 완료하면 다음 층으로 이동한다.

노드 위치(Node Step)
- 한 층 안에서의 가로 진행 순서(Horizontal Level)다.
- 예: '잿빛 용광로 1-3'에서 1은 1층, 3은 해당 층의 세 번째 노드 위치를 의미한다.

노드(Node)
- 전투나 이벤트가 발생하는 실제 개별 공간이다.
- 같은 노드 위치에 여러 개의 선택 가능한 노드가 존재할 수 있다.
- 같은 위치의 노드는 내부적으로 1-3-A, 1-3-B, 1-3-C처럼 고유 ID를 부여해 구분한다.
- 노드 위치와 고유 ID는 내부 진행·저장·개발자 기능에서 사용하며 일반 상단 HUD에는 표시하지 않는다.

지도 계층
던전
└─ 여러 층
   └─ 여러 노드 위치
      └─ 하나 이상의 전투·이벤트 노드

3-2. 기본 지도 구조
- 지도는 Slay the Spire처럼 노드와 노드가 연결된 분기형 구조다.
- 던전에 입장하면 지도를 무작위로 생성한다.
- 진행 방향은 지도 왼쪽 끝인 9시 방향에서 오른쪽 방향이다.
- 각 층에는 시작 노드와 보스 노드가 하나씩 존재한다.
- 시작 노드를 완료하면 연결된 다음 노드를 선택할 수 있다.
- 노드를 완료하면 지도 화면으로 돌아온다.
- 현재 노드와 직접 연결된 다음 노드만 선택할 수 있다.
- 경로는 중간에 분기되거나 다시 합류할 수 있다.
- 완료한 노드는 완료 상태로 표시한다.
- 층 보스를 처치하면 다음 층으로 이동한다.
- 마지막 층의 보스를 처치하면 던전을 클리어한다.
- 플레이어가 사망하면 현재 런을 종료한다.

3-3. 지도 진행 흐름
1) 던전 입장
2) 지도 생성
3) 층 시작 노드 진행
4) 연결된 다음 노드 선택
5) 전투 또는 이벤트 진행
6) 보상 획득 및 덱 정비
7) 지도 화면으로 복귀
8) 다음 노드 선택
9) 층 보스 진행
10) 다음 층 이동
11) 마지막 층 보스 처치
12) 던전 클리어

3-4. 노드 및 인카운터 종류

시작 노드
- 해당 층의 출발 지점이며 각 층에 하나만 존재한다.
- 시작 노드는 전투 노드가 아니라 고유 블록을 선택하는 독립적인 노드다.
- 고유 블록을 선택한 뒤 연결된 다음 노드들로 경로가 분기된다.
- 고유 블록의 구체적인 종류와 선택지 수는 추후 추가한다.

전투 노드
- 블록 배치 퍼즐을 이용해 몬스터와 싸운다.
- 몬스터를 처치하면 골드와 블록 보상을 획득한다.
- 몬스터 등급에 따라 일반, 네임드, 보스 인카운터로 구분한다.
- 등급은 몬스터의 종류가 아니라 인카운터의 난이도와 지도 표시를 구분하는 기준이다.

휴식 노드
- 플레이어의 현재 체력을 20 회복한다.
- 현재 체력은 최대 체력을 초과할 수 없다.
- 한 층의 전체 노드 위치 중 절반이 지난 시점부터 등장할 수 있다.
- 예를 들어 노드 위치가 5개라면 세 번째 위치부터 등장할 수 있다.

이벤트 노드
- 블록 추가, 삭제, 색상·능력 변경, 형태 변형, 상점, 보물 상자 및 일반 선택 이벤트가 발생할 수 있다.
- 선택을 완료하거나 스킵하면 종료된다.
- 미믹이나 공허 괴물이 등장하면 전투 인카운터로 전환될 수 있다.

보스 노드
- 해당 층의 마지막 노드다.
- 일반 경로는 최종적으로 보스 노드에 연결된다.
- 일반 층에는 층 보스가, 마지막 층에는 던전 최종 보스가 등장한다.

3-5. 난이도와 지도 규모
- 던전 난이도에 따라 층 수, 층별 노드 위치 수 및 위치별 노드 수가 달라질 수 있다.
- 이 방향성은 프로토타입에서 검증하며 정확한 수치는 아직 확정하지 않는다.

생성 변수
- 층 수: 던전 전체 길이
- 층별 노드 위치 수: 한 층에서 진행하는 가로 단계 수
- 위치별 노드 수: 같은 진행 위치에서 선택 가능한 공간 수
- 분기 횟수: 경로 선택이 발생하는 빈도
- 합류 횟수: 나뉜 경로가 다시 합쳐지는 빈도
- 노드 종류 비율: 전투·이벤트 등의 배치 비율
- 정보 공개 범위: 현재까지 이동한 노드만 공개하고, 다음 노드의 종류와 상세 정보는 공개하지 않는다.
- 전투 등급: 일반·네임드·보스 전투의 배치

프로토타입용 임시 기준
- 쉬움: 1층, 층별 7개 노드 위치, 위치별 1~2개 노드. 짧고 단순한 경로.
- 보통: 2층, 층별 8~10개 노드 위치, 위치별 1~3개 노드. 분기와 합류가 반복되는 경로.
- 어려움: 3층, 층별 10~12개 노드 위치, 위치별 2~3개 노드. 긴 경로와 위험한 선택 증가.
- 최고 난이도: 3층 이상, 층별 12개 이상 노드 위치, 위치별 2~4개 노드. 경로별 위험과 보상 차이 확대.
- 위 수치는 프로토타입 검증용이며 확정 밸런스가 아니다.

3-6. 한 층의 기본 구성
- 한 층은 '고유 블록 선택 → 첫 번째 분기 → 일부 경로 합류 → 두 번째 분기 → 보스 전 준비 → 층 보스' 흐름을 기본 골격으로 사용한다.
- 노드 위치가 10개인 층은 다음 구성을 예시로 사용할 수 있다.
  - 1: 고유 블록 선택 노드
  - 2~3: 첫 번째 분기
  - 4: 일부 경로 합류
  - 5~7: 주요 경로 선택 구간
  - 8: 보스 전 합류
  - 9: 준비 또는 위험·보상 선택
  - 10: 층 보스
- 모든 층을 동일하게 만들지 않고 여러 구조 템플릿 중 하나를 선택해 변형한다.

3-7. 지도 생성 방식
- 완전 무작위 생성이 아니라 미리 정의한 층 구조에 제약된 무작위를 적용한다.

생성 순서
1) 던전 난이도를 기준으로 전체 층 수를 결정한다.
2) 각 층의 노드 위치 수와 위치별 최대 노드 수를 결정한다.
3) 시작 노드와 보스 노드를 먼저 생성한다.
4) 시작 노드에서 보스까지 이어지는 기본 경로를 2~3개 생성한다.
5) 기본 경로 사이에 분기와 합류를 추가한다.
6) 연결되지 않은 노드와 막다른 경로가 있는지 검사한다.
7) 지도 연결 구조가 완성된 후 노드 종류를 배정한다.
8) 모든 선택 가능한 경로가 보스까지 도달하는지 검사한다.
9) 생성에 사용한 랜덤 시드를 저장한다.

지도 구조 템플릿 후보
- 초반에 넓게 분기한 뒤 합류하는 구조
- 초반에는 한 길이고 후반에 분기하는 구조
- 두 경로 사이에서 선택이 반복되는 구조
- 안전하지만 긴 경로와 위험하지만 짧은 경로
- 보상 노드를 중심으로 우회하는 구조

3-8. 지도 생성 제약
- 모든 시작 경로는 보스까지 연결되어야 한다.
- 막다른 경로를 생성하지 않는다.
- 이전 노드로 돌아갈 수 없다.
- 완료한 노드에 다시 진입할 수 없다.
- 현재 위치와 연결된 다음 노드만 활성화한다.
- 분기 직후 합류하는 의미 없는 선택은 만들지 않는다.
- 하나의 노드에서 연결되는 다음 노드는 최대 2~3개로 제한한다.
- 모든 최종 경로는 보스 노드에 연결한다.
- 같은 종류의 노드가 연속될 때마다 해당 종류의 다음 등장 확률을 직전 확률의 절반으로 낮춘다.
- 위험과 보상의 기준은 전체 경로가 아니라 개별 노드에 적용한다.
- 위험도가 높은 노드에는 그에 맞는 보상 가치가 배정되어야 한다.
- 서로 다른 경로가 완전히 같은 구성을 갖지 않도록 한다.
- 마지막 층의 보스는 일반 층 보스와 구분한다.

3-9. 지도 표시 규칙
- 현재 위치는 다른 노드와 명확하게 구분한다.
- 완료한 노드는 완료 상태로 표시한다.
- 선택 가능한 다음 노드만 활성화한다.
- 연결되지 않은 노드는 선택할 수 없도록 한다.
- 노드 사이의 연결 경로를 화면에 표시한다.
- 노드 종류는 아이콘이나 색상으로 구분한다.
- 몬스터 등급은 전투 노드의 아이콘 또는 별도 표식으로 구분한다.
- 같은 노드 위치에 여러 선택지가 있으면 위·중간·아래에 나누어 배치한다.
- 플레이어가 이동한 노드만 진행 이력으로 표시한다.
- 아직 이동하지 않은 다음 노드는 선택 가능 여부만 표시하며 노드 종류와 상세 정보는 공개하지 않는다.
- 상단 진행 정보에는 던전명과 현재 층만 표시한다. 예: '잿빛 용광로 · 1층'
- 노드 위치, '3/10', '4/10F' 같은 세부 진행 수치는 상단 HUD에 표시하지 않는다.

3-10. 지도 저장 및 이어하기
- 현재 던전
- 현재 층
- 현재 노드 ID
- 지도 생성 랜덤 시드
- 생성된 전체 지도 구조
- 완료한 노드
- 선택 가능한 다음 노드
- 현재 진행 중인 인카운터
- 플레이어 체력과 골드
- 현재 덱 구성
- 전투 진입 직전의 플레이어 체력, 골드, 덱과 인카운터 정보를 저장한다.

4. 블록 및 덱 시스템

4-1. 덱의 표현
- 게임에서 덱은 블록이 들어 있는 '주머니'로 표현한다.
- 가장 처음 전투를 시작할 때 총 13개의 블록을 가진다.
- 12개는 고정된 시작 블록으로 제공하고, 나머지 1개는 시작 노드에서 고유 블록을 선택해 추가한다.
- 게임 시작 시 정한 기본 덱과 이후 전투·이벤트에서 변경된 덱 구성을 현재 런 동안 유지한다.
- 각 전투에서는 덱의 드로우 순서만 무작위로 섞는다.

4-2. 블록의 구성
- 블록은 여러 개의 정사각형 칸이 서로 붙어 있는 형태다.
- 각 블록은 고유 ID, 표시 이름, 사용자 정의 type, 모양, 색상, 회전·반전 허용 여부, 자체 효과, 설명과 태그를 가진다.
- '기본', '고유', '코어', '저주' 같은 분류를 코드에 고정하지 않고 사용자 정의 type으로 관리한다.
- type은 추가·수정·삭제할 수 있어야 하며 모든 블록은 하나의 목록에서 type ID로 구분한다.
- 블록의 효과는 실행 코드를 저장하지 않고 본 게임이 해석하는 effect ID와 parameters로 정의한다.
- 일반 블록은 주로 3칸 또는 4칸으로 구성할 수 있으며, 더 복잡한 블록도 데이터로 추가할 수 있다.
- 블록의 모양은 최소 한 칸 이상이며 상하좌우로 연결되어야 한다.

4-3. 초기 블록 예시

- 다음 블록은 초기 프로토타입 후보이며 코드에 고정된 전체 목록이 아니다.

I 블록
- 형태: 정사각형 3개가 일자로 연결된 모양

O 블록
- 형태: 2x2 정사각형

L 블록
- 형태: 정사각형 3개가 ㄱ자로 연결된 모양

4-4. 모양과 색상
- 블록의 모양은 퍼즐 판에 배치되는 형태를 결정한다.
- 블록의 색상은 효과 조건과 색상 시너지 판정에 사용할 수 있다.
- 빨강은 공격, 파랑은 방어처럼 색상 역할을 코드에 고정하지 않는다.
- 초기 기본 색상은 빨강, 주황, 노랑, 초록, 파랑, 남색, 보라 7색이며 필요하면 색상을 추가할 수 있다.
- 색상별 실제 전투 효과와 수치는 블록·조합 규칙 데이터에서 정의한다.
- 색상 변경 이벤트는 미리 정의된 다른 블록으로 교체하는 방식과 연결하며, 임의로 색상만 바꾸는 기능은 콘텐츠 데이터에 따라 제공한다.

4-5. 특수 블록 후보
- U자 블록
- 지그재그 블록
- 십자형 블록
- 공격과 방어를 동시에 제공하는 복합 블록
- 프로토타입에서는 I, O, L을 우선 검증하되 실제 종류와 효과는 블록 디자인 프로그램의 출력 데이터에 맞춘다.

4-6. 블록·조합 규칙 데이터
- 블록과 조합은 별도의 블록 디자인 프로그램에서 시각적으로 제작하고 JSON으로 출력한다.
- 조합식은 하나 이상의 블록을 특정 위치와 형태로 배치했을 때 완성되는 규칙이다.
- 같은 블록 여러 개, 같은 type의 서로 다른 블록, 서로 다른 type, 같은 색상 또는 서로 다른 색상의 블록을 조합할 수 있다.
- 조합식은 단순 개수 조건이 아니라 각 블록 인스턴스가 격자에서 차지하는 실제 좌표와 회전·반전 상태를 저장한다.
- 정확한 블록, 임의 블록, 특정 type, 특정 색상, 특정 태그를 요구하는 조건형 슬롯을 사용할 수 있다.
- 조합은 항상 발생하는 효과와 조건부 효과를 가질 수 있다.
- 모든 조합에 공통으로 적용할 색상 보너스는 color synergies로 별도 관리한다.
- 조합 전체의 회전·반전 인정 여부는 조합별 데이터로 설정한다.
- 본 게임은 schema version, 참조 ID, 좌표, 겹침, 효과 ID와 parameters를 검증한 규칙 JSON만 불러온다.


5. 전투 시스템

5-1. 전투 개요
- 전투에서는 테트리미노처럼 여러 정사각형이 붙어 있는 블록을 퍼즐 판에 배치한다.
- 퍼즐 판은 칠교놀이처럼 일정한 외곽 형태를 가진다.
- 플레이어는 매 턴 무작위로 뽑은 블록을 배치해 공격, 방어, 회복 효과를 발생시킨다.
- 적에게는 '약점'이 존재한다.
- 특정 모양을 완성하거나 판을 정확히 채우면 추가 효과가 발생한다.
- 약점을 포함한 모양을 형성하면 추가 효과가 발생한다.

5-2. 전투 화면 전체 구성

좌측 상단 플레이어 정보 HUD
- 수평 체력 바와 현재 체력/최대 체력 수치
- 체력 바 아래에 이로운 상태 이상 아이콘을 수평 배치
- 그 아래에 해로운 상태 이상 아이콘을 수평 배치
- 그 아래에 현재 골드와 남은 덱 블록 수 표시

화면 중앙
- 플레이어 퍼즐 판과 몬스터 퍼즐 판을 배치한다.
- 플레이어와 몬스터의 실제 이미지 또는 연출 영역은 별도로 구성할 수 있다.
- 이번 턴에 뽑은 블록을 표시한다.
- 남은 블록 확인 버튼, 버려진 블록 확인 버튼, 턴 종료 버튼을 배치한다.
- 블록을 집었을 때만 회전 조작 안내를 표시한다.
- 몬스터의 다음 행동과 예상 효과를 표시한다.

플레이어 퍼즐 판 아래 상태 표시
- 수평 체력 바와 체력 바 중앙의 현재 체력/최대 체력 수치
- 체력 바 아래에 이로운 상태 이상 아이콘을 수평 배치
- 그 아래에 해로운 상태 이상 아이콘을 수평 배치
- 그 아래에 이번 턴 배치한 블록 수/최대 배치 가능 수를 표시한다. 예: 2/3

몬스터 퍼즐 판 아래 상태 표시
- 수평 체력 바와 체력 바 중앙의 현재 체력/최대 체력 수치
- 체력 바 아래에 이로운 상태 이상 아이콘을 수평 배치
- 그 아래에 해로운 상태 이상 아이콘을 수평 배치
- 몬스터에게는 배치 블록 수를 표시하지 않는다.

우측 상단 정보 및 설정 HUD
- 현재 던전명과 층 표시. 예: 잿빛 용광로 · 1층
- 지도 확인 버튼
- 설정 버튼: 톱니바퀴 아이콘 사용
- 메인 화면 이동 버튼: 문 아이콘 사용
- 자동 저장 상태 표시
- 메인 화면 이동 버튼은 오작동 방지를 위해 다른 버튼과 시각적으로 분리한다.
- 아이콘에 마우스를 올리면 기능 이름을 알려주는 툴팁을 표시한다.

기타 전투 정보
- 현재 턴
- 필요한 경우 플레이 시간
- 도감 버튼은 기능 확정 후 추가한다.

5-3. 퍼즐 판 규칙
- 퍼즐 판은 블록을 놓을 수 있는 정사각형 칸들의 집합이다.
- 블록은 퍼즐 판 내부에만 배치할 수 있다.
- 블록끼리 겹칠 수 없다.
- 판 밖으로 나가는 배치는 허용하지 않는다.
- 칸마다 표시되던 대각선 또는 불필요한 내부 장식선은 제거한다.
- 격자와 외곽선만 사용해 가시성을 확보한다.

5-4. 퍼즐 판과 체력의 관계
- 퍼즐 판인 거푸집은 플레이어 체력에 따라 본 게임에서 크기가 달라진다.
- 체력이 감소하면 3x3 중심 영역 바깥의 칸이 하나씩 제거된다.
- 최소 크기는 3x3이며 중심 영역은 항상 보장한다.
- 체력 구간별 정확한 크기, 최대 크기와 칸 제거 순서는 아직 확정하지 않는다.
- 체력이 늘어날 때는 가장 최근에 빠진 칸을 먼저 복구한다.
- 빠진 칸을 모두 복구한 뒤 추가 칸이 필요하면 테두리를 따라 순차적으로 생성한다.
- 몬스터의 외형 또는 특징에 맞는 판이 존재할 수 있다.
- 몬스터 판은 추가 효과를 주거나 특정 기믹을 수행하는 데 사용될 수 있다.

5-5. 드로우와 덱 순환
1) 전투 시작 시 13개의 블록으로 구성된 주머니를 섞는다.
2) 턴 시작 시 주머니에서 블록 5개를 뽑는다.
3) 플레이어는 뽑은 블록 중 기본적으로 최대 3개를 퍼즐 판에 배치한다.
4) 추가 효과가 있으면 최대 배치 가능 수가 늘어날 수 있다.
5) 턴 종료 전까지 사용하지 않은 블록은 임시 주머니인 버림 더미로 이동한다.
6) 이번 턴에 사용한 블록도 효과 처리 후 버림 더미로 이동한다.
7) 다음 드로우에 필요한 수량보다 주머니의 블록이 부족하면 남은 블록을 먼저 뽑고, 버림 더미를 섞어 주머니를 다시 만든 뒤 부족한 수량을 뽑는다.
8) 추가 턴 효과가 발생하면 해당 효과 데이터에 따라 블록을 리필하는 추가 턴과 리필하지 않는 추가 턴으로 구분한다.

5-6. 남은 블록 확인
- 남은 블록 버튼은 덱에 있지만 아직 사용되지 않은 블록의 목록을 보여준다.
- 블록의 종류와 수량을 확인할 수 있다.
- 다음에 뽑힐 블록을 예측할 수 없도록 화면 표시 순서를 무작위로 섞는다.
- 실제 드로우 순서는 노출하지 않는다.

5-7. 버려진 블록 확인
- 버려진 블록 버튼은 현재 버림 더미에 있는 블록 목록을 보여준다.
- 지금까지 사용했거나 사용하지 못해 버린 블록을 확인할 수 있다.
- 버튼은 턴 종료 버튼의 왼쪽에 배치한다.

5-8. 블록 조작

블록 배치
- 블록을 마우스로 드래그해 퍼즐 판에 배치한다.
- 배치 가능한 위치에 들어가면 가능한 상태임을 시각적으로 표시한다.
- 판 밖으로 나가거나 다른 블록과 겹치면 배치할 수 없다.

블록 회전
- 블록을 드래그하는 도중 R 키를 누르면 오른쪽으로 90도 회전한다.
- R 키를 반복해서 누르면 90도 단위로 계속 회전한다.
- 정사각형처럼 회전해도 형태가 같은 블록은 동일하게 표시한다.

블록 회수
- 턴 종료 전에는 이미 배치한 블록을 다시 퍼즐 판에서 꺼낼 수 있다.
- 꺼낸 블록은 이번 턴의 손패로 돌아간다.
- 회수한 블록은 다른 위치에 다시 배치할 수 있다.
- 사용하지 않은 상태로 턴을 종료하면 버림 더미로 이동한다.
- 턴 종료 후에는 배치를 되돌릴 수 없다.

5-9. 기본 턴 흐름
0) 턴 시작
1) 몬스터 행동 결정 후 표시
2) 주머니에서 블록 5개 드로우
3) 매 턴 블록 회전 및 퍼즐 판 배치 가능 횟수 제공. 기본 최대 3회
4) 필요하면 배치한 블록 회수 및 재배치
5) 플레이어가 턴 종료 선택
6) 블록 효과, 조합식, 조건부 효과 및 색상 시너지 판정
7) 추가 턴 진행 여부와 블록 리필 여부 확인
8) 플레이어 상태 이상 피해 적용
9) 플레이어 공격 피해 계산 및 몬스터에게 적용
10) 몬스터 상태 이상 피해 적용
11) 몬스터가 생존했다면 예고한 효과 및 피해 적용
12) 플레이어와 몬스터의 사망 여부 확인
13) 사용한 블록과 사용하지 않은 블록을 버림 더미로 이동
14) 배치한 블록을 퍼즐 판에서 모두 제거
15) 플레이어 방어도를 0으로 초기화
16) 상태 이상 스택 감소 처리
17) 추가 턴이면 지정된 리필 규칙으로 추가 턴 시작, 아니면 다음 일반 턴 시작

추후 개발 후보
- 도감에 등록된 형태가 현재 손패에 존재하면 해당 형태를 즉시 배치하는 기능

5-10. 퍼즐 판 초기화
- 턴 종료 시 그 턴에 배치한 블록을 모두 제거한다.
- 이전 턴의 블록 배치는 다음 턴에 남지 않는다.
- 다음 턴에는 빈 퍼즐 판에서 다시 배치한다.

5-11. 블록 기본 효과
- 각 블록은 자체 효과를 0개 이상 가질 수 있다.
- 자체 효과에는 공격, 방어, 회복, 상태 이상, 추가 드로우 등 본 게임에 구현된 effect ID를 사용할 수 있다.
- 블록 자체 효과의 수치는 해당 블록의 parameters에서 읽는다.
- 색상 자체의 효과를 코드에 고정하지 않으며 색상 조건과 공통 시너지는 규칙 데이터로 판정한다.
- 색상별 실제 효과와 블록별 피해·방어·회복 수치는 블록 디자인 프로그램의 결과물과 밸런스 테스트로 확정한다.

5-12. 방어도
- 방어도는 몬스터의 공격 피해를 대신 받는다.
- 받은 피해가 방어도보다 크면 남은 피해가 플레이어 체력에 적용된다.
- 현재 턴에 획득한 방어도는 해당 턴의 몬스터 공격을 막을 수 있다.
- 방어도는 턴이 끝날 때마다 0으로 초기화한다.

예시
- 플레이어 방어도: 10
- 몬스터 공격력: 15
- 방어도가 피해 10을 막는다.
- 남은 피해 5가 플레이어 체력에 적용된다.

5-13. 특정 모양 완성 효과
- 여러 블록을 조합해 규칙 데이터에 등록된 실제 배치 도면을 만들면 조합 효과가 발생한다.
- 조합은 정확한 블록 배치뿐 아니라 type, 색상, 태그 등의 슬롯 조건을 사용할 수 있다.
- 조합의 기본 효과, 조건부 효과와 색상 시너지를 각각 판정한다.
- 조합 공격력과 타격 횟수는 서로 다른 값으로 관리한다.

5-14. 중복 세트 보너스
- 같은 턴에 같은 종류의 모양을 여러 개 완성하면 효과가 증가한다.
- 여러 조합이 동시에 성립할 때의 우선순위와 하나의 블록이 여러 조합에 중복 참여할 수 있는지는 아직 확정하지 않는다.
- 중복 조합의 조건과 배율은 블록·조합 규칙 데이터 및 밸런스 테스트를 통해 결정한다.

5-15. 퍼즐 판 완성 보너스
- 퍼즐 판을 빈칸 없이 정확하게 채우면 추가 능력이 발동한다.
- 후보 효과는 추가 공격, 모든 공격 블록 효과 증가, 추가 방어도, 추가 골드, 다음 턴 추가 드로우 등이다.
- 판 완성 보너스는 일반 블록 효과 및 모양 세트 효과를 모두 계산한 후 계산한다.

5-16. 효과 계산 순서
1) 추가 턴 진행 여부 확인
   - 조합 또는 효과로 추가 턴이 발생했는지 확인한다.
   - 추가 턴은 블록 리필 있음과 블록 리필 없음으로 구분한다.
2) 플레이어 상태 이상 피해 적용
   - 플레이어 체력에서 출혈·화상 등 상태 이상 피해를 차감한다.
   - 상태 이상별 방어도 무시 여부를 적용한다.
3) 플레이어 공격 적용

   최종 공격 피해 =
   {
     (블록 공격력 + 플레이어 버프·디버프)
     + (조합 공격력 × 타격 횟수)
   }
   × 디버프 약화 계수
   × 공격력 배율

   - 타격 횟수는 전체 공격력이 아니라 조합 공격력에만 곱한다.
   - 블록 공격력은 이번 턴에 발동한 블록 자체 공격 효과의 합이다.
   - 조합 공격력과 타격 횟수는 성립한 조합 효과에서 가져온다.
   - 플레이어 버프·디버프, 약화 계수와 공격력 배율의 실제 수치는 상태 및 효과 데이터에서 가져온다.
4) 몬스터 상태 이상 피해 적용
   - 몬스터에게 부여된 출혈·화상 등 상태 이상 피해를 몬스터 체력에 적용한다.
5) 몬스터 효과 및 피해 적용
   - 앞 단계까지 몬스터가 생존했다면 예고된 몬스터 행동을 실행한다.
   - 방어도는 방어도 무시 효과가 아닌 피해를 먼저 흡수하고, 남은 피해만 체력에 적용한다.

5-17. 몬스터 행동
- 몬스터는 턴마다 공격 또는 특수 행동을 한다.
- 몬스터의 다음 행동은 플레이어 행동 전에 결정해 화면에 표시한다.
- 플레이어의 블록 효과를 처리한 뒤 몬스터가 생존했을 경우에 행동한다.
- 플레이어의 공격으로 몬스터가 사망했다면 해당 턴의 몬스터 행동은 실행하지 않는다.
- 특수 몬스터는 특정 칸 봉인, 특정 색상 약화, 배치 방향 제한, 방해 블록 추가 등의 행동을 사용할 수 있다.

5-18. 상태와 상태 이상

기본 상태
- 체력: 플레이어 또는 몬스터가 생존할 수 있는 수치다. 플레이어 체력이 0 이하가 되면 현재 런이 종료되고, 몬스터 체력이 0 이하가 되면 전투에서 승리한다.
- 방어도: 피해를 대신 받는 임시 체력이다. 방어도 무시 피해를 제외한 피해를 먼저 흡수하며, 턴 종료 시 0으로 초기화한다.
- 힘: 플레이어 버프·디버프 및 공격력 계산에 사용할 능력치다. 구체적인 획득 방식과 수치는 추후 확정한다.
- 민첩: 플레이어 버프·디버프 및 방어·행동 관련 효과에 사용할 능력치다. 구체적인 적용 공식은 추후 확정한다.

상태 이상 피해
- 출혈: 턴 종료 처리 시 '판에 놓은 블록 개수 × 출혈 스택 수'만큼 피해를 받는다. 방어도를 무시하며 처리 후 스택이 1 감소한다.
- 화상: 턴 종료 처리 시 화상 스택 수만큼 피해를 받는다. 방어도로 막을 수 있으며 처리 후 스택이 절반으로 감소한다. 홀수 스택은 내림한다.

상태 이상 디버프
- 약화: 스택당 공격력이 10% 감소한다. 턴 종료 시 스택이 1 감소한다.
- 상처: 스택당 받는 피해가 10% 증가한다. 턴 종료 시 스택이 1 감소한다.

군중 제어
- 기절: 현재 행동 턴을 건너뛴다. 중첩할 수 없으며 최대 1스택이다. 해당 턴을 건너뛴 뒤 스택이 제거된다.

5-19. 몬스터 데이터와 등급
- 몬스터의 정확한 총수는 아직 정하지 않는다.
- 회의록의 수량은 프로토타입 제작 규모를 가늠하기 위한 대략적인 값이며 확정 수량이 아니다.
- 몬스터 등급은 일반, 네임드, 보스로 구분한다.
- 몬스터 티어는 난이도, 레벨 또는 등장 조건을 나타내며 등급과 별도로 관리한다.
- 지도에서는 전투 노드에 몬스터 등급을 구분할 수 있는 표식을 표시하되, 아직 방문하지 않은 미래 노드의 정보는 공개하지 않는다.

몬스터 데이터
- 고유 ID
- 몬스터명
- 티어 및 등장 조건
- 등급
- 최대 체력
- 행동 및 전용 어빌리티 목록
- 행동별 피해·방어·상태 이상 수치
- 행동 선택 조건과 연속 행동 제한
- 다음 행동 예고 정보
- 상태 이상과 면역
- 처치 보상
- 등장 가능한 던전과 층
- 퍼즐 판 형태 또는 전용 기믹

프로토타입 몬스터 후보

일반
- 잉걸불 슬라임
- 잔불 박쥐
- 녹슨 노역꾼
- 폭발하는 영혼
- 매달리는 잿더미

네임드
- 용암 심장
- 절제된 분노

보스
- 철을 삼키는 자
- 녹아내린 드레이크
- 끓어오르는 용광로 기사

- 위 목록의 몬스터별 체력, 기술, 피해, 방어도 및 등장 조건은 이후 밸런스 설계에서 추가한다.

5-20. 전투 종료 조건

승리
- 몬스터의 체력이 0 이하가 되는 순간 전투가 종료된다.

패배
- 플레이어의 체력이 0 이하가 되는 순간 전투가 종료된다.

후퇴
- 보스방을 제외한 일반 몬스터 전투의 후퇴 가능 여부와 처리 방식은 아직 결정되지 않았다.


6. 전투 결과 및 보상

6-1. 골드 보상
- 전투에서 승리하면 몬스터에 따라 정해진 범위 내에서 기본 골드를 받는다.
- 구체적인 획득량과 계산 공식은 아직 확정되지 않았다.

6-2. 블록 보상
- 일반 전투 종료 후 무작위 블록 3개를 제시한다.
- 블록 선택지에는 무색 및 유색 블록이 포함될 수 있다.
- 플레이어는 블록 1개를 선택해 덱에 추가할 수 있다.
- 필요하지 않다면 아무것도 선택하지 않고 스킵할 수 있다.
- 보상 처리가 끝나면 지도 화면으로 복귀한다.

6-3. 인카운터별 결과

일반 전투
- 성공 조건: 몬스터 처치
- 보상: 골드, 블록 3개 중 1개 선택
- 종료 후: 지도 복귀

보스 전투
- 성공 조건: 보스 처치
- 보상: 던전 클리어 보상. 다회차 플레이가 생기면 추후 확장
- 종료 후: 게임 클리어

일반 이벤트
- 성공 조건: 선택 완료 또는 스킵
- 보상: 이벤트에 따라 다름
- 종료 후: 지도 복귀

이벤트 전투
- 성공 조건: 미믹 또는 공허 괴물 처치
- 보상: 특수 보상 또는 일반 전투 보상
- 종료 후: 지도 복귀
- 프로토타입 이후 개발한다.

상점 이벤트
- 완료 조건: 구매 후 나가기, 또는 판매와 변형 중 하나를 수행한 뒤 나가기
- 변형은 플레이어가 보유한 블록을 블록 디자인 프로그램으로 미리 제작한 다른 블록으로 교체하는 방식이다.
- 플레이어가 블록의 칸을 직접 이동하거나 임의의 모양을 만드는 방식은 사용하지 않는다.
- 구매하거나 정비한 덱은 현재 런 동안 유지한다.
- 종료 후 지도 화면으로 복귀한다.


7. 이벤트 시스템

7-1. 이벤트 분류
- 이벤트 인카운터는 일반 이벤트와 레어 이벤트로 나뉜다.
- 현재 초안의 등장 비율은 일반 이벤트 70%, 레어 이벤트 30%다.
- 이 비율은 지도·경제 공식과 함께 추후 검증한다.

7-2. 일반 이벤트

상점
- 골드로 블록을 구매할 수 있다.
- 보유한 블록을 판매할 수 있다.
- 보유한 블록을 변형시킬 수 있다.
- 판매와 변형은 둘 중 하나만 수행할 수 있다.
- 구매 목록과 판매 목록은 리롤할 수 없다.
- 이용하지 않고 나갈 수 있다.

무료 블록 추가
- 무작위 블록 5개를 제시한다.
- 그중 1개를 선택해 덱에 추가할 수 있다.
- 스킵할 수 있다.
- 리롤할 수 없다.
- 최대 1회 선택할 수 있다.

무료 블록 삭제
- 현재 덱에 있는 블록 중 1개를 제거할 수 있다.
- 스킵할 수 있다.
- 최대 1회 가능하다.

무료 모양 변경 또는 색 변경
- 현재 덱에 있는 블록 1개를 미리 정해진 교체 대상 블록으로 변경할 수 있다.
- 교체 관계와 결과 블록은 블록 디자인 프로그램의 출력 데이터로 정의한다.
- 스킵할 수 있다.
- 최대 1회 가능하다.

유료 블록 추가
- 무작위 블록 3개를 제시한다.
- 무색, 유색 및 특수 블록이 등장할 수 있다.
- 골드를 지불하고 그중 1개를 덱에 추가할 수 있다.
- 스킵할 수 있다.
- 목록을 리롤할 수 있다.
- 기존 초안의 임시 리롤 비용은 최초 25골드이며, 리롤할 때마다 최초 비용만큼 증가한다.

유료 블록 삭제
- 골드를 지불해 덱의 블록 1개를 제거할 수 있다.
- 스킵할 수 있다.
- 기존 초안의 임시 비용은 최초 50골드이며, 제거할 때마다 최초 비용만큼 증가한다.

유료 모양 변경 또는 색 변경
- 골드를 지불해 현재 덱에 있는 블록 1개를 미리 정해진 교체 대상 블록으로 변경할 수 있다.
- 스킵할 수 있다.
- 교체 결과는 블록 디자인 프로그램에서 제작한 블록 데이터만 사용할 수 있다.
- 기존 초안의 임시 비용은 최초 50골드이며, 변경할 때마다 최초 비용만큼 증가한다.
- 최대 2회 가능하다.

변형 이벤트
- 플레이어가 보유한 블록 1개를 선택한다.
- 선택한 블록에 연결된 미리 정의된 변형 결과 중 하나로 교체한다.
- 블록의 칸을 게임 안에서 직접 이동하는 기능은 제공하지 않는다.
- 변형 전·후 블록의 type, 모양, 색상, 효과와 교체 가능 관계는 블록 디자인 프로그램의 결과물에 맞춘다.

보물 상자
- 플레이어는 상자를 열거나 지나갈 수 있다.
- 상자를 열면 골드, 미믹, 공허의 상자 또는 광대 상자 등의 결과가 발생할 수 있다.
- 골드 보상, 결과별 확률 및 비용은 현재 확정 공식이 없으므로 추후 결정한다.
- 미믹은 즉시 전투로 전환되는 후보 콘텐츠다.
- 공허의 상자는 골드 또는 체력을 대가로 요구하는 후보 콘텐츠다.
- 광대 상자는 지울 수 없는 저주 블록을 추가하는 후보 콘텐츠다.

7-3. 레어 이벤트

생명의 샘
- 플레이어의 최대 체력을 늘릴 수 있다.
- 현재 초안의 임시 증가량은 최대 체력 25다.
- 최대 체력이 늘어난 만큼 현재 체력도 회복한다.

7-4. 이벤트 종료
- 이벤트 선택을 완료하거나 스킵하면 인카운터가 종료된다.
- 미믹이나 공허 괴물 전투로 전환되면 해당 몬스터를 처치해야 완료된다.
- 이벤트가 끝나면 지도 화면으로 복귀하고 다음 분기 노드를 선택한다.

9. 추가 개발 후보

9-1. 유물 시스템. 우선순위 1

- 퍼즐 판을 완성하면 추가 골드 획득
- 매 전투 첫 턴에 블록 1개 추가 드로우

9-2. 특수 아이템

예시
- 현재 퍼즐 판을 특정 모양으로 변경
- 블록 1개 재드로우
- 배치한 블록 1개 회수
- 특정 칸의 잠금 해제

9-3. 점수 및 랭킹
- 게임을 클리어하거나 종료했을 때 최종 점수를 계산한다.
- 점수를 이용해 랭킹을 보여줄 수 있다.

점수 요소 후보
- 도달한 층
- 처치한 몬스터 수
- 남은 체력
- 보유 골드
- 오버킬 피해량
- 퍼즐 판 완성 횟수
- 특정 모양 완성 횟수
- 클리어에 사용한 턴 수

9-4. 상태 이상 확장 후보
- 출혈, 화상, 약화, 상처와 기절의 기본 규칙은 5-18에 적용한다.
- 다음 항목은 이후 추가할 후보이다.

예시

- 방어도 획득량 감소

- 퍼즐 판의 특정 칸 봉인

- 튜토리얼의 필요성은 있으나 구체적인 구성, 진행 순서 및 표시 공식은 아직 확정되지 않았다.
- 첫 전투에서 필요한 순간에 단계별로 안내하는 방식은 제안 상태로 유지한다.
- 드래그, R 키 회전, 유효 위치, 블록 회수, 최대 3개 배치, 색상별 효과, 몬스터 행동 예고, 턴 종료, 덱·버림 더미 확인 등이 안내 후보이다.


10. 공통 화면 및 UI 동작

10-1. 메인 화면
- NEW GAME
- CONTINUE
- 설정
- 종료 또는 메인 화면에서 필요한 기타 메뉴
- CONTINUE는 3-10의 저장 데이터를 불러온다.
- 전투 도중 종료한 저장 데이터라면 해당 전투의 시작 상태로 복원한다.

10-2. 설정 및 지도 버튼
- 메인 화면을 제외한 화면의 우측 상단에는 현재 던전명·층, 지도, 설정, 메인 화면 이동 버튼을 배치한다.
- 설정에는 효과음·배경음 음량과 전체 화면 전환 기능을 포함하는 안을 우선 검토한다.
- 메인 화면 이동 시 확인 창을 표시한다.
- 브라우저 기본 alert보다 게임 내부 모달을 사용한다.
- 설정 창이 열린 동안 배경 화면의 입력을 차단한다.
- 전투 중에는 블록 드래그, 회전 및 턴 종료 입력도 차단한다.

10-3. 자동 저장 표시
- 우측 상단에 작은 자동 저장 상태 표시를 둔다.
- 저장 중, 저장 완료, 저장 실패 상태를 색상 또는 짧은 애니메이션으로 구분한다.
- 전투 진입 직전 상태와 3-10의 런 데이터를 저장하며 세부 자동 저장 시점은 계속 검증한다.

10-4. UI 표현 방향
- 저채도 금속 프레임과 제한적인 불빛을 사용해 대장간·던전 분위기를 표현한다.
- 플레이어 상태 표시는 차가운 청색 계열, 몬스터 상태 표시는 달궈진 적색 계열을 사용할 수 있다.
- 상태 아이콘은 금속 표찰이나 공구처럼 체력 바 아래에 매달린 형태를 사용할 수 있다.
- 상태 아이콘이 많아질 경우 최대 표시 개수와 +N 형태의 초과 표시 규칙이 필요하다.
- 상태 추가·제거 시에만 짧게 움직이고 지속적인 흔들림은 사용하지 않는다.


11. 확정 사항과 추가 결정 사항

11-1. 현재 확정한 기준
- 기본 덱은 13개다. 12개 고정 제공 후 시작 노드에서 고유 블록 1개를 선택해 추가한다.
- 지도는 던전 → 층 → 노드 위치 → 실제 노드의 계층으로 구성한다.
- 지도는 왼쪽에서 오른쪽으로 진행하는 분기형 구조로 생성한다.
- 각 층에는 시작 노드와 보스 노드가 하나씩 존재한다.
- 프로토타입에서는 템플릿 기반 제약형 무작위 생성을 적용한다.
- 이전 노드로 돌아가거나 완료한 노드에 다시 진입할 수 없다.
- 모든 경로는 해당 층의 보스 노드까지 연결되어야 한다.
- 시작 노드는 전투가 아닌 고유 블록 선택 노드이며, 선택 후 다음 경로로 분기한다.
- 같은 종류의 노드가 연속될 때마다 해당 종류의 다음 등장 확률은 절반으로 감소한다.
- 휴식 노드는 층의 절반 이후부터 등장할 수 있으며 현재 체력을 20 회복한다.
- 미래 노드의 종류와 상세 정보는 공개하지 않는다.
- 상단 HUD에는 던전명과 층만 표시한다.
- 블록 3개 중 하나를 선택하는 보상은 일반적으로 전투 승리 보상이다.
- 이벤트 인카운터는 각 이벤트에 정해진 별도 결과를 적용한다.
- 턴 종료 시 이번 턴에 놓은 블록을 전부 제거한다.
- 다음 턴은 빈 퍼즐 판에서 시작한다.
- 턴 종료 전에는 배치한 블록을 회수하고 재배치할 수 있다.
- 한 턴에는 기본적으로 블록을 최대 3개 배치한다.
- 블록과 조합은 type, 모양, 색상, 효과를 데이터로 정의하고 블록 디자인 프로그램의 JSON 결과와 연동한다.
- 추가 턴 확인, 플레이어 상태 이상 피해, 플레이어 공격, 몬스터 상태 이상 피해, 생존한 몬스터 행동 순서로 처리한다.
- 조합 공격력에만 타격 횟수를 곱한 뒤 약화 계수와 공격력 배율을 적용한다.
- 출혈, 화상, 약화, 상처와 기절의 기본 규칙을 적용한다.
- 몬스터 등급은 일반, 네임드, 보스로 구분한다.
- 방어도는 턴 종료 시 0으로 초기화한다.
- 전투 중 종료하면 해당 전투의 시작 상태에서 다시 시작한다.
- 변형 이벤트는 보유 블록을 미리 정의된 다른 블록으로 교체한다.
- 마지막 층에는 일반 층 보스와 구분되는 던전 최종 보스가 존재한다.
- 좌측 상단, 중앙의 양측 판 아래, 우측 상단의 전투 UI 구조를 사용한다.
- 플레이어 판 아래에는 이번 턴 배치 블록 수를 표시한다.

11-2. 지도와 진행. 추후 결정
- 각 난이도의 정확한 층 수
- 층별 정확한 노드 위치 수와 위치별 최대 노드 수
- 노드 종류별 최초 등장 확률
- 상점 노드 추가 여부

- 보스 직전 노드의 고정 규칙
- 고유 블록의 구체적인 종류와 선택지 수
- 등급별 몬스터의 정확한 수량과 배치
- 던전 최종 보스와 최종 클리어 연출

11-3. 덱과 블록. 추후 결정

- 덱이 지나치게 작아지는 것을 막기 위한 최소 블록 수
- 블록 희귀도와 획득 확률
- 실제 블록 type 목록
- 색상별 실제 전투 효과
- 블록별 피해, 방어, 회복과 상태 이상 수치
- 블록 자체 효과와 조합 효과의 세부 중첩 방식
- 변형 이벤트의 블록별 교체 관계

11-4. 퍼즐과 조작. 추후 결정
- 퍼즐 판의 기본 크기와 체력 연동 방식의 최종 확정
- 몬스터 형태 기반과 층 난이도 기반 중 어느 방식으로 판을 정할지
- 블록을 드래그하지 않는 상태에서도 회전할 수 있는지
- 모바일 또는 터치 환경에서 회전을 어떻게 조작할지
- 배치 가능한 위치를 어떤 방식으로 표시할지
- 조합식 전체의 회전·반전 인정 여부 기본값

11-5. 전투 규칙. 추후 결정
- 특정 모양의 종류와 기본 보너스
- 중복 세트 개수별 효과 배율
- 여러 세트가 같은 블록을 공유할 수 있는지
- 여러 조합이 동시에 성립할 때의 우선순위
- 조합 발동 후 참여 블록의 소비 또는 유지 방식
- 퍼즐 판 완성 보너스의 정확한 효과
- 공격, 방어, 회복 수치에 세트 배율을 동일하게 적용할지
- 체력, 공격력, 방어도 등 기본 밸런스 수치
- 힘과 민첩의 구체적인 공식
- 약화 계수와 공격력 배율의 하한·상한
- 몬스터 방어도·고정 방어력의 세부 적용 방식
- 오버킬 골드 계산식과 상한
- 일반 전투 후퇴 가능 여부와 처리 방식
- 몬스터별 체력, 어빌리티, 피해, 방어와 행동 선택 공식

11-6. 이벤트와 경제. 추후 결정
- 일반 이벤트와 레어 이벤트 내부의 개별 등장 확률
- 상점 판매 가격과 구매 가격

- 미믹과 공허 괴물의 난이도 및 보상
- 공허 괴물 전투 승리 시 특수 보상 여부

- 골드 획득량과 소비 비용의 전체 경제 공식

11-7. 저장 및 이어하기. 추후 결정

- 저장할 런 데이터의 정확한 범위

- 설정값과 프롤로그 열람 여부의 별도 저장 여부


12. 한 문장 요약

난이도에 따라 여러 층과 노드로 생성되는 분기형 던전에서 고유 블록을 선택해 출발하고, 매 턴 주머니에서 블록 5개를 뽑아 최대 3개를 배치하며 블록 자체 효과·조합식·색상 시너지로 몬스터와 싸워 최종 보스를 처치하는 로그라이크 블록 배치 게임이다.


부록 A. 미확정 제안값

주의
- 이 부록은 확정 규칙이 아니다.
- 기존 본문과 충돌할 경우 본문을 우선한다.

A-1. 경제 밸런스 제안값
- 일반 전투 평균 보상: 100골드
- 강한 전투 평균 보상: 150골드
- 블록 구매: 150~300골드
- 블록 삭제: 최초 200골드
- 유료 변경: 최초 150골드
- 리롤: 최초 50골드
- 위 수치는 확정값이 아니며 기존 본문의 임시 비용을 대체하지 않는다.

A-2. 튜토리얼 제안
- 첫 전투에서 필요한 순간에 한 단계씩 표시
- 블록 드래그
- R 키 회전
- 유효한 칸에만 배치 가능
- 이미 놓은 블록 회수
- 한 턴 최대 3개 사용
- 블록 색상별 효과
- 몬스터 행동 예고
- 턴 종료
- 덱과 버림 더미 확인
- 구체적인 진행 순서, 표시 방식 및 재열람 규칙은 아직 없음


부록 B. 개발자 모드

목적 및 접근 조건
- 게임 테스트와 디버깅을 위한 개발 환경 전용 모드다.
- Vite 개발 환경에서만 활성화하며 실제 release에서는 일반 사용자가 접근할 수 없다.
- URL 파라미터나 저장 데이터만으로 release에서 개발자 기능을 활성화할 수 없다.
- 개발자 기능은 일반 모드의 게임 규칙을 다시 구현하지 않고 기존 진행·보상·저장 흐름을 재사용한다.

메인 화면
- 개발 환경에서는 메인 화면 좌측 하단에 개발자 전용 메뉴를 표시한다.
- '개발자 게임 시작'과 '개발자 이어하기' 버튼을 제공한다.
- 개발자 게임 시작 시 프롤로그를 생략하고 지도 화면으로 진입한다.
- 개발자 이어하기 데이터가 없으면 해당 버튼을 비활성화한다.
- 일반 런과 개발자 런은 서로 다른 저장 슬롯을 사용한다.
- 개발자 플레이 결과가 일반 이어하기 데이터에 영향을 주지 않는다.

지도 화면
- 개발자 모드에서는 일반적인 노드 활성화 상태와 관계없이 현재 노드 위치 또는 이후 노드 위치에 바로 진입할 수 있다.
- 현재 위치보다 이전 노드 위치로는 이동할 수 없다.
- 예를 들어 현재 위치가 1-3-A라면 1-1과 1-2에는 진입할 수 없으며, 1-3-B, 1-4 및 1-5에는 진입할 수 있다.
- 진행 위치 비교는 A·B 같은 개별 노드 구분이 아니라 층과 노드 위치를 기준으로 한다.
- 일반 모드에서는 기존과 같이 현재 노드에 연결된 선택 가능 노드만 활성화한다.
- 개발자 모드 전용 '골드 +1000' 버튼을 표시하며, 클릭할 때마다 현재 골드를 1000씩 추가한다.

전투 화면
- 개발자 모드에서는 턴 종료 버튼 왼쪽에 '자동 승리' 버튼을 표시한다.
- 자동 승리는 플레이어 입력 단계에서만 사용할 수 있고 중복 실행할 수 없다.
- 자동 승리도 기존 승리 흐름을 사용하여 골드·블록 보상, 노드 완료, 지도 복귀, 층 이동 및 던전 클리어 처리를 유지한다.
- 턴 종료 버튼 위에는 접거나 펼칠 수 있는 개발자 로그 패널을 표시한다.
- 로그에는 전투 시작과 몬스터 정보, 블록 배치 수와 점유 칸, 플레이어 공격 피해, 몬스터 잔여 체력, 몬스터 공격, 플레이어 체력 변화, 다음 턴 준비, 자동 승리 및 처치 정보를 기록한다.
- 로그는 최근 100개까지만 유지한다.
- 전투 로그는 전투 화면의 임시 UI 상태이며 저장 데이터에 포함하지 않는다.

적용 범위
- 메인 화면의 개발자 진입 메뉴, 지도 개발자 도구, 자동 승리 및 전투 로그는 모두 개발자 모드에서만 표시하고 실행한다.
- 일반 게임의 지도 이동, 전투 계산, 보상 및 저장 규칙은 변경하지 않는다.
